# MCP по умолчанию: результат реализации

Дата: 2026-10-31. Установленные клиенты: Codex CLI 0.166.0, Qwen Code 0.26.4.

Общая политика `ai-hooks/mcp-policy.json` включает лимит обычного текста и
обработку ошибок без lifecycle. TokenSave и RAG используют общий proxy; Codex
сохраняет ленивый catalog Playwright, Qwen — proxy с прямым handshake backend.
Настройки MCP обоих установленных клиентов синхронизированы. Старые активные
подключения нужно переподключить. Пользовательские файлы `vscode/` не изменялись.

Проверки Node покрывают UTF-8, JSON/structuredContent/ошибки/медиа, метаданные,
параллельные ответы, full/range-чтение артефакта, ошибку записи и приватное хранение,
истечение защиты, восстановление, изменение индекса, запрет повторов writes,
неизвестные ошибки, явные digests/force, изменение файла, потерю generation,
новый диалог/модель, compaction и сброс бюджета runner. Установщики проверяют
сохранение настроек и идемпотентность; Codex проверяется также реальным TOML
round-trip с сохранением approval mode, enabled, timeouts и пользовательского env.

Выполнены полный набор `node --test --test-concurrency=1 ai-hooks/test/test-*.mjs`
(57 тестов, все прошли),
`./install.sh --check` и `./install.sh --qwen --check`. Проверки установки не
доказывают фактическое исполнение hooks.

Фиксированная синтетическая нагрузка состоит из двух малых чтений, двух больших
ответов и трёх одинаковых ошибок аргументов. Сравниваются отключённые оптимизации
и обычный proxy без generation/budget-файлов:

| Показатель | Отключено | По умолчанию |
| --- | ---: | ---: |
| Байты сериализованных ответов клиенту | 80723 | 27213 |
| Успешные результаты | 4 | 4 |
| Ошибки клиенту | 3 | 3 |
| Вызовы backend | 7 | 6 |
| Ошибки backend | 3 | 2 |

Это примерно 66% сокращения байтов в данном сценарии, включая JSON-обёртку,
пути артефактов и указатели. Длина путей влияет на точное число. Полные большие
результаты восстановлены и проверены отдельно; их чтение не включено в эту
нагрузку. Backend генерирует прежний объём текста, proxy сокращает передачу
клиенту. Байты текста модели, число модельных вызовов, latency сопоставимых
модельных задач и native usage/cached input/output/reasoning не измерялись.

Через реальный Codex app-server, без запроса к модели, выполнены discovery,
малый вызов TokenSave, большой `tokensave_read`, чтение полного артефакта,
диапазона и повторное чтение. В проверенной версии файла исходный текст составил
15094 bytes, ответ proxy — 13000 bytes, запрошенный диапазон — 512 bytes;
повторное чтение снова вернуло текст. Размер исходника меняется при правках.
`qwen mcp list` подтвердил Connected для TokenSave, RAG и Playwright через proxy.
Полные пользовательские сценарии с моделью в обоих клиентах не запускались;
проверка Qwen подтверждает discovery/handshake, а не модельный выбор инструмента.

Для lifecycle сверена схема установленного `codex app-server`:
`item/completed` с `contextCompaction`, `thread/compacted`, `model/rerouted`.
В установленном Qwen найдены SessionStart и PreCompact/PostCompact, но безопасный
контракт привязки всех изменений истории и модели к конкретному процессу MCP
не подтверждён. Поэтому обычные сессии обоих клиентов не используют
автоматический `if_digest` и общий бюджет хода. Их сохраняет только runner,
владеющий своим потоком и явно передающий generation/budget. TTL для digests
не применяется; TTL 30 секунд используется только для защиты от ошибок backend.

Общий бюджет runner ограничивает обычный текст; видимые указатели полного
результата могут превысить его после исчерпания. При невозможности безопасно
сохранить артефакт полный успешный ответ важнее лимита. Свежие артефакты защищены
60 секунд, затем могут удаляться при следующем сохранении. Если лимит хранения
занят свежими файлами, новый ответ возвращается целиком.

Меньше байтов не означает такое же сокращение токенов, пятичасового лимита или
стоимости подписки. Меньше обращений к backend не доказывает меньше обращений
к модели. Серверный prompt cache и скорость генерации этой проверкой не оценены.

После дополнительной проверки устранены три проблемы: закреплённые путь Chrome
и профиль заменены поиском браузера с сохранением явных настроек; `atomicJson`
убирает временный файл при ошибках; proxy ограничивает время ожидания backend
и очищает ожидающие вызовы и таймеры при закрытии. Зависший backend завершается
через EOF, SIGTERM и SIGKILL без повтора операций с неизвестным итогом.
Полный повторный прогон после ревью: 63 теста, все прошли, включая backend
с потомком, игнорирующим SIGTERM, восстановление RAG по явному `project`,
неизменность прав `.env.local` при `--check` и очистку старых логов sync.
Proxy завершает собственную группу процессов backend; свежие логи сохраняются.
Каталог Playwright проверен через `node bin/mcp-catalog.mjs playwright --check`.
Конфигурации Codex и Qwen синхронизированы; обе проверки установки прошли.
