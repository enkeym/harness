# Автоматическое управление контекстом

## Планы и Handoff

Если плану нужен файл, общий навык `task-brief` направляет его в `.opencode/plans/<task-id>.md` внутри проекта. Имена уникальны для задач; явно заданный пользователем путь имеет приоритет. Агент сохраняет план незавершённой или заблокированной задачи и передаёт точный путь при Handoff, а после завершения работы и проверок удаляет только её временный план. Это инструкция модели, а не файловый сборщик по событию завершения шага. Пользовательские планы и файлы других задач не удаляются.

Большой план служит файловым кешем: он сохраняется один раз, а в начале обновляется короткий checkpoint с фазой, текущим шагом, разрешениями, проверенными контрактами, неизвестными фактами и следующей правкой или проверкой. Handoff передаёт путь и этот checkpoint вместо полного плана. Продолжение готового разрешённого плана сразу выполняет текущий шаг, восстанавливая только недостающие инструкции и необходимые исходники. Повторное обследование требует конкретного недостающего факта, изменения требований или противоречия. Если после очередного сжатия тот же шаг не продвинулся, агент уменьшает шаг либо называет конкретный блокер. Это правило работы модели, а не программный запрет инструментов; файловый кеш не делает чтение бесплатным и не гарантирует кеширование у провайдера.

Установка включает глобальный `handoff`: в OpenCode вызывайте `/handoff`.
Командой управляет плагин: он ждёт завершения исходной работы, генерирует сводку без
инструментов, сохраняет `.opencode/HANDOFF.md` (или путь из аргумента), создаёт новую
сессию с прежними агентом и разрешениями и передаёт ей план для немедленного
продолжения. TUI показывает ход переноса и автоматически открывает продолжение, если
пользователь остался в исходной сессии. Повторный вызов из неё открывает то же
продолжение без повторного запуска плана. Ошибки показываются уведомлением.
Shell-задачи и субагенты для переноса не запускаются. Плагин создаёт каталог
`.opencode` и дополняет его `.gitignore` правилами для `HANDOFF.md` и `handoffs/`,
сохраняя существующие правила. Явно заданный путь остаётся под управлением
пользователя. Уже отслеживаемые Git файлы эти правила не исключают.

Модель и effort выбирает пользователь. Ручной `/handoff` генерирует сводку на
текущей модели, а продолжение получает ту же модель и variant; автоматическая
компактация также сохраняет модель сессии. Прежние маркеры
`HARNESS-ROUTE: progress=… next=…` удаляются из сводки и продолжения и не влияют
на выбор модели; автоматического перехода на Pro после тупика нет. Для DeepSeek
остаётся явный ручной аргумент `--route=pro|flash`, без него модель не меняется.
У других провайдеров аргумент игнорируется. Завершённая или заблокированная
работа не переносится.

## Бриф с переходом между моделями

`task-brief` применяется перед архитектурой, содержательным планированием,
разработкой модуля, сложным аудитом и диагностикой с неясной причиной или неудачной
попыткой. Обычные локальные правки, фактические ответы и выполнение подходящего
готового плана его не требуют. Решение принимает агент по инструкциям навыка;
это не фильтр по ключевым словам и не гарантия каждого модельного решения.

Политика `ai-hooks/brief-routing.json` отделена от общего навыка. В OpenCode
она включает инструмент `brief_transition`: `stage=plan` ставит переход в очередь,
после успешного завершения хода плагин создаёт свежую сессию с моделью исходной
сессии. Отдельной модели планировщика нет, автоматической смены нет: Pro
выбирается только вручную, в том числе `--route=pro` в Handoff. Исходная модель
с variant сохраняется. Начальный
бриф передаёт цель и ограничения; посреди работы — компактный Handoff с фактами,
последними указаниями, разрешениями и путём плана. Повторного запроса к модели
для генерации сводки нет. Исходная история не копируется.

Существенные открытые вопросы планировщик задаёт через интерактивный инструмент
клиента (`question` в OpenCode), с вариантами и рекомендацией. Список вопросов
в Markdown и ответ «продолжи» не заменяют выбор пользователя. Ответы либо явно
делегированные решения сохраняются в плане и Handoff. Планировщик возвращает
готовый план через `stage=implement`, если реализация разрешена и эти вопросы
решены. Её выполняет новая сессия на сохранённой исходной модели с прежними
разрешениями. Запрос только на анализ завершается у планировщика. После ошибки
хода очередь отменяется; новое сообщение пользователя до переноса отменяет
устаревшую очередь. Сбой доставки использует проверки и повторное продолжение
существующего Handoff. Ручной `/handoff` сохраняет фазу брифа и исходную модель.
Если ручной перенос уже ожидает завершения хода, он принимает ожидающую фазу брифа;
очередь снимается только после подтверждённой доставки. Оба запроса используют одно
продолжение. Заметки по умолчанию записываются атомарно с правами `0600`; симлинки
в каталогах автоматических заметок отклоняются.
Отключение: `opencode.enabled=false` в политике; замена планировщика — её
`opencode.planner`. После изменения перезапустите сервис OpenCode без активной работы.

Свежая сессия уменьшает передаваемую историю, но не удаляет кеш провайдера.
Общие инструкции, описание инструментов и Handoff всё равно входят в запрос.
Два перехода и повторное чтение файлов имеют стоимость; для короткой задачи
они могут оказаться дороже. Экономию нужно проверять по полным связанным сессиям,
учитывая cache read/write, цену моделей, число попыток и качество результата.

## Автоматическое сжатие

Автоматический Handoff работает через штатное сжатие клиента: старые сообщения
заменяются сводкой в активном контексте, диалог и сохранённая история остаются.
Сводка использует `skills/handoff/SKILL.md`, сохраняет цель, последние указания,
ограничения, изменения, проверки, оставшийся план и следующее действие. Переносится
только незавершённый чекпойнт: выполненные фазы не повторяются в оставшемся плане,
а чекпойнт Handoff главнее устаревших отметок в файле плана. Одна передача создаёт
одну сессию, и одно событие выполнения обрабатывается один раз, даже если плагин
загружен несколькими экземплярами. Продолжение
разрешённой задачи после сжатия не требует подтверждения; готовые и заблокированные
задачи не перезапускаются. Это не отключает разрешения на остальные операции.

Общая политика — `ai-hooks/bin/context-policy.mjs`. OpenCode
получает собственные значения (`contextPolicy.opencode`): сжатие начинается на
135000 токенах, `buffer = 15000`, последние 20000 токенов сохраняются. Плагин
ограничивает рабочий `limit.input` максимумом 150000, сохраняя меньшие лимиты
моделей. Его hook `compaction` передаёт те же инструкции Handoff. Модель и провайдер
не меняются. Маленькие окна могут сжиматься раньше. Порог проверяется клиентом на
границе шага; один большой ответ инструмента может перескочить его, поэтому это не
гарантия жёсткого размера каждого запроса. В OpenCode native provider compaction
может вернуть непрозрачный checkpoint вместо текстовой сводки; текстовый Handoff
hook применяется к summary.

Применение: `./install.sh --opencode`; проверка — та же команда с `--check`.
После изменения кода плагина или Handoff выполните `opencode service restart` при
отсутствии активной работы: `reload` может сохранить прежний модуль плагина в памяти.

Бюджет чтений OpenCode (`softReads` 20, `hardReads` 40, `stopReads` 60 в
`contextPolicy.opencode`) считает `read`, `grep`, `glob`, `skill`, `execute` и
`shell`; запись файла сбрасывает счётчик. Напоминания добавляются в результат
инструмента (`execute.after` → `result.content`), а не в системный промпт: начало
запроса остаётся стабильным для кеша провайдера. На `hardReads` запросы к
инструментам ограничиваются, на `stopReads` агент завершает ход и возвращает
вывод; лимит не блокирует инструменты на стоп-уровне, где ход всё равно завершается.
Выводы встроенных инструментов (`read`, `grep`, `glob`, `shell`, `webfetch`,
`execute`) длиннее `contextPolicy.opencode.toolOutputBytes` (20 КБ) усекаются в
том же `execute.after` до бюджета с маркером `full_result=`. Полный ответ
сохраняется в приватном каталоге `$XDG_STATE_HOME/harness/context-output` и
читается через `harness_read_result`; JSON-текст тоже ограничивается, поскольку
артефакт хранит исходный ответ. Маркер исключён из дедупа и сбора digest, а
напоминания guard добавляются уже после усечения и остаются видимыми.
После перехода с файлового плагина на пакет с TUI перезапустите также терминальный
клиент OpenCode, продолжив прежний диалог: старый клиент ещё не загрузил TUI-плагин.
Настройки проекта или выбранного профиля могут иметь приоритет
над глобальными. Чтобы отключить политику, отключите `compaction.auto` и ограничение
input в плагине. Повторная установка harness восстанавливает политику.

## MCP и лимиты вывода

MCP proxy ограничивает обычный MCP text до 13000 bytes на результат, сохраняет
UTF-8 и полный приватный артефакт. При исчерпании бюджета указатель всё равно
виден в text; служебные указатели могут превысить текстовый бюджет.
`_meta.harnessFullResult` дублирует путь. `harness_read_result`
получает диапазон или полный исходный ответ (`full=true`) через MCP без усечения.
JSON text, structuredContent, ошибки и изображения проходят целиком.

Лимиты, приватное хранение и защита свежих артефактов описаны в
[MCP](../mcp/servers.md). Для шумных команд используйте один brief-output.sh вокруг
всего batch: прямой shell-вызов не попадает под лимит истории.

Повторы разрешены лишь для явно перечисленных read-only MCP tools при временной
transport-ошибке, максимум два с backoff. Две одинаковые детерминированные ошибки
открывают circuit для тех же нормализованных аргументов: возвращается исходная
ошибка без вызова backend с пояснением временного подавления. Через 30 секунд
допускается пробный вызов; успех или изменение наблюдаемого индекса снимают
защиту. Неизвестные ошибки circuit не открывают. Writes не повторяются.
graph_root для чужого проекта не удаляется.
