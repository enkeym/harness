инструкции следует применять после завершения операций через `opencode reload`.

## Расходы и готовность optimize

Нативный stats показал 31 сессию, 542 шага и 743 вызова инструментов. Эти
агрегаты смешивают задачи и модели; `execute` скрывает вложенные MCP-вызовы.
Показатель `subagents: 0` не заменяет проверку семейства сессий. Для исторической
сессии Flash выше нативный запрос с фильтром `parentID` вернул пустой список;
сопоставимой выборки с делегированием в этой проверке нет.

Найдены ограничения учёта:

- У Pro в `ses_e68528de7ffeOEchgDBJfMaS1N` ненулевые usage:
  input 28 130, output 1 724, reasoning 2 596, cache read 146 048;
  нативная стоимость равна нулю. Исторические цены не подтверждены, денежный
  расход неизвестен. Счётчики сохранены раздельно, без предположения об их
  пересечении.
- У Flash в `ses_e66616be0ffeZ1Js5LYCvgrwCC` итог сессии input 90 813,
  сумма видимых assistant-сообщений 90 598; разница 215. Также расходятся
  output на 8, reasoning на 72 и cache read на 256. Источник расхождения
  не установлен. Итог сессии не складывался с составляющими сообщениями.
- `tokensave cost today --by-agent --export json` вернул нулевые usage и
  стоимость, пустой `by_model`, но `tokens_saved: 98333`. Это не замер
  оплаченных расходов OpenCode. Оценка retrieval savings сохранена отдельно.
- Санитизированный экспорт скрывает тела `execute` и результаты; по нему
  нельзя проверить обход MCP или оригинальный размер вывода.

Предыдущий `optimize` запрещал выдумывать расходы, но не требовал полной
последовательности действий, сверки итогов, наблюдения делегирования и критерия
готовности плана. Теперь скилл ссылается на
[протокол](../skills/shared/optimization-observations.md): источники и версия,
последовательности вызовов, модели/варианты, повторное чтение, fallback,
компактация, родительские/дочерние сессии, качество и полная стоимость стадий.

Наблюдения сохраняются локально по ID сессии; повторный экспорт обновляет
наблюдение, а не добавляет расход второй раз. Пока нет сопоставимых завершённых
задач с проверенным качеством и сверенным учётом, оптимизационный план отложен.
Следующие данные: естественные сопоставимые задачи без/с делегированием,
экспорты детей, причины расхождения usage, действовавшие цены моделей.
Подагенты ради заполнения таблицы не запускались.

## Проверка изменений

Добавлен общий сборщик `opencode/observations.mjs`: плагин сохраняет наблюдения
после выполнения, перед компактацией и после handoff. Он объединяет увиденные
сообщения по ID, сохраняет связь переноса и дочерние сессии. API плагина отдаёт
только активный контекст; `bin/opencode-observe.mjs` отдельно сверяет все страницы
нативной истории. Неполное покрытие, неподтверждённые цены и расхождения остаются
явными пробелами. Записи приватные, без текста промптов и рассуждений;

## Аудит загрузки скиллов — 2026-11-08

Причина избыточных загрузок — безусловные формулировки в описаниях инструментов
и правилах:

- `opencode/retrieval-routing.mjs` добавлял «First load tokensave-routing» в
  описания read/grep/glob/shell и «Load tokensave-routing before project
  exploration» в описание skill. Модель видела это при любом чтении и при любом
  вызове skill, включая проекты без `.tokensave/` и `.ragsave/rag.db`.
- `opencode/AGENTS.md` требовал `tokensave_status` и `tokensave-routing` до
  первого чтения без проверки индекса.
- `rules/core.md` требовал «Combine workflow and stack skills» без ограничения
  затронутым стеком, поэтому каталог читался как список обязательных загрузок.

Исправление: `tokensave-routing` и MCP включаются только при наличии маркера
индекса в корне проекта и только для навигации по коду; без индекса используются
локальные инструменты. Выбор скиллов ограничен областью задачи: один
workflow-скилл плюс скиллы затронутого стека. Обновлены описания инструментов,
правила Codex/OpenCode, `ask`, `tokensave-routing`, `review`, `task-brief`,
`optimize` и проверяющие тесты.

Проверка: `test-retrieval-routing.mjs`, `test-skill-context.mjs`, полный набор
`ai-hooks/test`, `./install.sh --opencode --check`.

## Дублирующие триггеры остальных скиллов — 2026-11-08

Проверены все описания каталога: та же ошибка была не только у
`tokensave-routing`.

- `review-standards` и `review-security` объявляли загрузку «on the diff before
  every commit», а `skills/commit` и `rules/core.md` повторяли ту же команду.
  Три источника одного действия заставляли грузить оба чека на каждый шаг.
  Теперь загрузка описана как часть workflow `review`/`commit`/`git-flow`,
  ровно один раз на сессию; самостоятельный триггер остался только для
  отдельного качества/безопасности вопроса.
- `test-conventions` требовал загрузку даже для запуска готового набора тестов;
  `python`, `nestjs-backend`, `react-frontend`, `nextjs-app` — для любого
  чтения, включая read-only. Добавлены явные исключения, а `rules/core.md`
  ограничил стековые скиллы записью/исправлением/ревью кода.
- `task-brief`: «module development» в описании и правилах сужен до
  multi-component/contract-changing реализации; добавлен skip для
  single-file changes.
- В `rules/core.md` правило «загружать один раз» было записано дважды
  (строки 13 и 29) — оставлено одно, добавлен явный запрет повторной загрузки
  скилла в сессии.

Проверка отсутствия дублей запуска: установщик сообщает конфликтующие ссылки
skills; `~/.config/opencode/skills` содержит по одной ссылке на скилл;
`instructions: []`, поэтому `rules/core.md` не доставляется дважды;
`opencode/context-cache.mjs` вырезает вторую идентичную выдачу `skill` в одном
запросе; `opencode/loop-guard.mjs` напоминает после compaction не перезагружать
активные скиллы. Добавлен `ai-hooks/test/test-skill-catalog.mjs`: уникальный
`name` каждого SKILL.md, совпадение с каталогом и одна строка описания.
