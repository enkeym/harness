# Проверки и устранение тупиков

Изменения, локальные коммиты и необходимые тесты выполняются в рамках задачи
самостоятельно. Подтверждение харнеса требуется перед push; явная команда push
его уже разрешает. Нативные sandbox и managed approvals действуют отдельно.
Нельзя обещать, что настройка харнеса отменит системные разрешения Codex.

## Индексы

TokenSave: scoped search → read с небольшим диапазоном; дополнительные схемы
открываются по необходимости. Пути, исключённые конфигом индекса, допускают
ограниченный fallback. Собственные исходники `bin/**` харнеса не исключаются:
`node bin/harness-index-config.mjs` исправляет только это известное исключение.
Затем `tokensave sync -f` обновляет существующий граф; первичный init не запускается.

RAG CLI и MCP выбирают ближайший существующий индекс внутри репозитория.
Имена из git разбираются через NUL, включая Unicode, кавычки и переводы строк.
Ссылки на файлы и каталоги не индексируются; чтение запрещает следование по
symlink также во время открытия. При синке старые такие записи удаляются.

Перед выдачей RAG сверяет хеши найденных файлов с индексом. Старый текст,
удалённый файл или ссылка не попадают в ответ; возвращается предупреждение.
`autosync=ok` означает отсутствие запрета, а не доказанное выполнение hook.
`sync_health` различает unknown, failed и recorded. Исполнение hooks отдельно
проверяется через `/hooks`; конфиги не доказывают доверие или запуск.

Чанки ограничены 1600 символами, включая длинные строки. Старые oversized
записи перечитываются при обычном синке, несовместимый кеш не восстанавливается.
Выдача CLI/MCP ограничена 20 hits и 24 000 символами содержимого; дубликаты
с одинаковыми путём, строками и текстом исключаются. Это бюджет текста, не
лимит оплаченных токенов и не подсчёт денег.

## GitLab

`node bin/gitlab-api.mjs --hostname HOST ENDPOINT` использует существующий glab.
Для JSON-записи: `--method POST|PUT --input body.json`. Host указывается явно,
endpoint относительный; тело хранится в JSON-файле с настоящими переводами строк.
Клиент не выполняет login и не читает хранилища credentials. При локальной
недоступности glab допустим токен из окружения: GITLAB_TOKEN, GLAB_TOKEN или
GITLAB_ACCESS_TOKEN. В curl он передаётся по stdin, не в аргументах процесса.
HTTP, JSON и код процесса проверяются, таймауты ограничены. После ответа
сервера или неоднозначного сбоя запись автоматически не повторяется.

Несколько MR проверяются в одной сессии с нативной компакцией. Номер задачи
не выдумывается: необязательный ticket опускается. Посторонние staged/unstaged
изменения сохраняются; `/commit` не делает общий `git add -A`.

## Проверки

```sh
node --test --test-concurrency=1 ai-hooks/test/test-*.mjs
~/.rag-mcp/venv/bin/python -B ragsave/tests/test_ragsave.py
~/.rag-mcp/venv/bin/python -B ragsave/tests/test_regressions.py
./install.sh --check
```

Тесты сокетов и asyncio требуют среды, где эти примитивы разрешены. EPERM
и зависание минимального независимого примера не трактуются как ошибка авторизации.
Счётчики `<synthetic>` TokenSave не являются биллингом текущей сессии.
