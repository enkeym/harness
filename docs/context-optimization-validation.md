Единственный документ с итогами плана оптимизации контекста/расхода (шаги 0–5, ветка `codex`,
16–17.11.2026). Плановые документы удалены: `docs/context-automation-plan.md` и все планы в `.opencode/plans/`,
кроме `active-task-ec83be96.md` — чекпойпта незавершённой задачи другой сессии. Механизм
наблюдения, планов и компакций описан в `docs/context-automation.md`, клиентская интеграция —
в `docs/opencode.md`.

Источник цифр — отчёты `~/.local/state/harness/optimize/opencode/reports/2026-11-14..16`
(`.md` и `usage`/`.toolOutputByTool` в `.json`), перегенерация — `refreshCostReport`.
Байты ≠ биллинговые токены; перевод ~3.2–3.7 Б/токен — оценка, а не тариф. Каждый эффект до
валидационного окна остаётся гипотезой.

- Просадка cache hit 15–16.11 объясняется переписыванием контекста: шаги компакции попадают в кеш
  только на 16.5%, а дни с 9 и 4 компакциями проседали сильнее. После полного применения шагов
  метрика вернулась выше порога; отдельной правки не требует.
- Доля компактаций выросла против 16.11 из-за одной сессии: 23 компакции за день, 18 из них в сессии
  на 874 сообщения. Шаг компакции стоит ≈0.0123 USD; 23 шага = 0.28 USD, около 30% расхода дня.
  `compaction.buffer` 25000 вступил в силу только 17.11, поэтому досрочный revert не применяется:
  срез 19.11 считать и без сессии-выброса, иначе метрика меряет одну сессию, а не buffer.
- Возврат `#high` в build (162 сообщения) — поведение, а не дефект: предупреждение шага 3 сработало.
- `nativeReportedUSD` считает клиент по `priceSnapshot` с `source: opencode-model-registry`, где есть
  только offPeak-ставки (`input` 0.15, `output` 0.6, `cache.read` 0.003). Поэтому нативная цена
  занижает часы peak вдвое, а `pricing-window-mismatch` (17.11: 173, то есть все peak-запросы)
  описывает снапшот клиента, а не наши окна. Окна и ставки `opencode/cost-policy.mjs` сверены с
  документацией DeepSeek 17.11.2026: peak 01:00–04:00 и 06:00–10:00 UTC, Пн–Пт без китайских
  праздников, offPeak — половина peak. Деньги сравнивать по `recomputed*`, а не по native.

## Ожидаемая экономия

- Токены: ≈150–300K input-токенов в день. Составляющие: уже убранные «большие» выводы
  (162 676–773 801 Б → 39 100 Б ≈ 35K токенов), оставшиеся 39 100 Б ≈ 11K токенов, более редкие
  компакции (150 867 токенов input при доле 10.7%; снижение доли до <5% ≈ 80K токенов),
  статическая инжекция ≈450 токенов на запрос, из них recompute-доля ≈7.7% → ≈11K токенов/день.
- Деньги, только тарифицируемый deepseek flash (ставка из отчёта 16.11: input 0.0302601 USD /
  1 411 526 токенов ≈ 0.0214 USD за млн): ≈0.003–0.006 USD/день, т.е. 8–15% наблюдаемых
  0.039982 USD/день. На фоне смешанного рабочего дня это не заявленная гарантия, а проверяемый
  интервал.
- По qwen, kimi и openai денежная экономия не заявляется: `nativeReportedUSD` = 0/null,
  собственный тариф в отчёте отсутствует. Для них фиксируется только снижение токенов, шагов
  и числа компакций.
- Экономия шага 5 по деньгам минимальна (≈0.0002 USD/день, ~0.5% наблюдаемого дня): при cache hit
  92–96% статический префикс почти не пересчитывается. Именно поэтому урезание инжекций шло
  последним приоритетом, а не первым.

## Что дальше (не сейчас)

Валидационное окно 3–5 дней по ежедневным отчётам: large-tool-output-share <20%,
compaction-input-share <20% и число компакций, cache hit ≥95%, failure-streak ≤3,
USD/сообщение flash ≤0.000711, плюс ручная приёмка качества resume после компакции при
buffer 25000. Эффект по −1485 Б статической инжекции для qwen/kimi/openai в деньгах не
заявляется — только как гипотеза до этих цифр. При провале порога — `git revert` конкретного
шага, следующий не начинать.
