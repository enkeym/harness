# Аудит harness, 3 ноября 2026

Проверены исходники и установленный harness в WSL, Codex 0.166.0 и OpenCode
2.2.5. Изменения в vscode и ранее начатые изменения маршрутизации моделей
сохранены. Проверка macOS ограничена анализом переносимости и изолированными
тестами веток Darwin: физического Mac в этой проверке нет.

## Skills и браузер

Проверены 47 верхнеуровневых сессий OpenCode этого проекта за 1–3 ноября.
Полные страницы сообщений прочитаны через нативный API, отдельно от обрезаемого
CLI export. Это не история всех проектов и не полный учёт дочерних сессий.
Каталог навыков и объявление намерения загрузить навык не считались загрузкой.

Найдено 47 явных вызовов skill: 46 успешных и одна ошибка из-за имени `OpenCode`
вместо точного идентификатора `opencode`. Встречаются и чтения SKILL.md через
MCP, поэтому отсутствие вызова skill само по себе не доказывает пропуск навыка.
Исторический навык opencode не входит в текущие 22 общих навыка репозитория.
Три успешных вызова doctor относятся к диагностике кеша/harness и очистке
установки клиента. Наблюдений, что doctor вызывается всегда, нет.

В браузерной сессии `ses_e673788c6ffeOgTN0mvmw4RVH5` после создания вкладки
идут два таймаута browser_click без промежуточного snapshot, затем попытки
browser_run_code_unsafe. Doctor в наблюдаемой последовательности не загружен.
В `ses_e68624a69ffeLis5U1GhpZyvlE` присутствуют JS-ошибка, таймауты и устаревшая
ссылка. Это разные ошибки: исправление аргумента/ref не требует сразу аудита
всей установки, но повторный инфраструктурный блокер требует doctor.

Несколько сессий ограничиваются списком вкладок с Welcome. Среди них есть
диагностические задачи: сам такой список не доказывает провал интернет-поиска.
Сообщения об ошибках внутри результата инструмента проверялись отдельно от
статуса completed внешнего execute.

Изменены описание и границы doctor, общая маршрутизация и инструкции OpenCode:

- Обычное успешное использование MCP, исследование публичного интернета и
  работа в этом репозитории сами по себе не запускают doctor.
- Пропавшие навыки/инструменты, повторные сбои MCP, зависшее подключение
  расширения и сломанные индексы запускают диагностику во время текущей задачи.
- Публичное исследование начинается с поиска/получения страниц. Для браузерной
  задачи нужно перейти к целевой странице и прочитать её; Welcome/about:blank
  и обнаружение инструментов не означают завершение задачи.
- connect.html сохраняется для соединения. Когда browser_tabs new не принимает
  URL, за созданием вкладки следует browser_navigate и свежий snapshot.

У 22 общих навыков проверены name/description, относительные ссылки и установленные
пути Codex/OpenCode: ошибок нет. Имена сопоставлены с доступным каталогом текущей
сессии Codex. Обновление исходника не гарантирует обновления каталога уже запущенной
сессии другого клиента: изменения проверяются в новой сессии либо после штатной
перезагрузки OpenCode по завершении активной работы.

Сессии не покрывают все предметные навыки и все отрицательные сценарии.
Правильное будущее решение модели нельзя доказать проверкой Markdown или ссылок.
Нативные тесты проверяют доставку инструкций, а не гарантированное послушание модели.
Тесты MCP proxy подтверждают: обнаружение инструментов и ping не запускают браузер;
первый настоящий tools/call запускает процесс один раз. Причина наблюдавшихся
блужданий не воспроизведена как ошибка ленивого запуска proxy.

## Кеш

В последних 20 сессиях просуммированы 463 записи assistant без добавления
итогов этих же сессий: input 1 259 484, cache read 23 357 696, cache write 0.
По формуле read / (input + read + write) получается 94,88%.
Это доля входа в наблюдаемых сообщениях, а не общий процент всей истории,
доля удачных задач или подтверждённая экономия денег. Три записи имеют нулевые
счётчики и не рассматриваются как бесплатные завершённые запросы.

В `ses_e64015981ffeosyYa8Bz6g4Cqj` у 69 записей assistant input 163 183,
read 3 955 968: 96,04%. Нативный итог сессии, включающий служебную работу:
input 239 104, read 3 965 952, около 94,31%. Наблюдаемые вспомогательные
сообщения объясняют input 75 784 и read 9 600; остаются нераспределёнными
input 137 и read 384. Эти основания учёта не складывались.

У OpenCode вход и cache read/write разделены; это соответствует опубликованной
[семантике токенов](https://dev.opencode.ai/v2/docs/console/api/inference).
Кеширование DeepSeek включено автоматически и зависит от совпадающего
сохранённого префикса, а не от отдельного флага harness:
[официальные условия](https://api-docs.deepseek.com/guides/kv_cache/).
Сопоставимой выборки Opus здесь нет. Откуда взялась оценка 50%, по этим данным
установить нельзя; нужны её период, модель и знаменатель.

Для следующего измерения стоит отдельно сравнивать первые запросы и продолжения,
служебные запросы и основную работу, одну модель/provider и одинаковый тип задач.
Стабильный префикс инструкций/инструментов и отсутствие лишних повторных загрузок
сохраняют условия попадания в кеш. Проверка гипотезы — нативные hit/miss на
сопоставимых завершённых задачах, вместе с качеством и задержкой. Смена модели,
новая сессия и компактация могут менять префикс; это не основание отключать нужные
переходы ради процента. Политика моделей/компактации и API-флаги ради кеша не менялись.
Размер трёх затронутых инструкций вырос с 13 078 до 15 613 байт; это не токены.

## Установка и сохранность настроек

Повторяющаяся установка файлов объединена в bin/install-files.mjs для обоих
клиентов. Личные AGENTS.md остаются активными, инструкции harness занимают отдельную
управляемую секцию. Hooks объединяются с личными обработчиками. Существующий
TokenSave config не заменяется. Перед изменением создаётся уникальная резервная
копия; повреждённый JSON или секция инструкций отклоняются.

Файлы, каталоги и неизвестные ссылки на месте устанавливаемых инструментов/skills
сохраняются, конфликт возвращает ошибку. Даже оборванная ссылка не доказывает,
что она принадлежит harness. Установка не транзакционная: к моменту сообщения
о конфликте другие неконфликтующие компоненты могут быть установлены.
Оборванные ссылки конфигурации и startup-файлов не создают файл по чужому адресу.
Личная команда OpenCode handoff больше не удаляется установщиком.

Bootstrap bash ставится перед ранним return, точные дубликаты удаляются, остальные
байты сохраняются. Zsh использует ZDOTDIR/.zshenv, sh — .profile; для bash в Darwin
выбирается существующий login profile. Неподдерживаемый shell сообщает ограничение.
Не создаются startup-файлы невыбранной оболочки. Повторная установка идемпотентна,
--check не записывает файлы.

Личные Git identity/include не изменяются — проверено интеграционным тестом.
Общие замки project-init перенесены из неявного CODEX_HOME в XDG_STATE_HOME/harness
с поддержкой AI_HOOKS_STATE_DIR, чтобы OpenCode не создавал лишнюю .codex.
Установка Codex не создаёт конфиг OpenCode. Пути вычисляются от HOME, каталога
репозитория и клиентских переменных. WSL Chrome обнаруживается через PATH/реестр,
нативный macOS использует штатное обнаружение Playwright; личные диски и имена
пользователя в этот механизм не зашиты.

В текущем ~/.bashrc удалён повтор bootstrap с резервной копией. Проверено, что
остальные байты не изменились. Обе установленные конфигурации прошли свой --check.
Доверие и фактическое исполнение lifecycle hooks не доказываются одним --check.

Финальная проверка: `node --test --test-concurrency=1 ai-hooks/test/test-*.mjs`
— 139 passed, 0 failed, 0 skipped. Полный журнал:
`/tmp/harness-output.B6zaH4`. `git diff --check` прошёл. Проверки установленного
Codex и OpenCode завершились с кодом 0. Проверки относительных ссылок навыков
и существующей карты docs/links также прошли.

Локальные исходные журналы и сводки находятся вне Git в приватном каталоге
~/.local/state/harness/optimize/opencode/90277afafe4bf1a0/. Содержимое приватных
страниц, промпты и секреты в этот отчёт не включены.
