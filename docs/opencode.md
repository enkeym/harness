# OpenCode

`./install.sh --opencode` подключает OpenCode v2 к общим правилам, навыкам и реестру MCP harness. `./install.sh --opencode --check` проверяет установку без записи.

Исходный базовый конфиг находится в `opencode/opencode.jsonc`. Установщик сохраняет пользовательские настройки в `~/.config/opencode/opencode.jsonc`, добавляет инструкции и плагин из репозитория. Перед изменениями создаются резервные копии. Авторизация и ключи остаются вне Git.

Каталог задаётся через `OPENCODE_CONFIG_DIR` или `XDG_CONFIG_HOME`. Установщик и MCP-синхронизация принимают JSONC с комментариями и завершающими запятыми. `opencode.json` и `opencode.jsonc` объединяются рекурсивно, значения JSONC имеют приоритет, массивы заменяются. Изменения записываются в JSONC с сохранением комментариев. Удаляемые поля также удаляются из `opencode.json`, если заданы там, чтобы они не восстанавливались при объединении; остальные настройки JSON сохраняются. Перед изменением каждого файла создаётся резервная копия. Повреждённый конфиг отклоняется до записи.

Для JSONC используется `jsonc-parser`, зависимость зафиксирована в `opencode/package-lock.json`. Установка автоматически выполняет `npm --prefix opencode ci --ignore-scripts`, если зависимость отсутствует. `--check` зависимости не устанавливает и сообщает команду для их установки.

`bin/mcp-sync.mjs --opencode` подключает TokenSave, RAGSave и Playwright из `mcp/servers.json`. Плагин `opencode/harness.js` запускает существующие обработчики синхронизации индексов при загрузке с прогревом RAG. Каталог берётся из `context.location.directory`, а не из рабочего каталога общего сервера. События `session.execution.succeeded`, `session.execution.failed` и `session.execution.interrupted` запускают повторную синхронизацию обоих индексов после ответа. Подписка V2 читается как асинхронный поток. Правила `rules/core.md` доставляются контекстным хуком.

Полные правила `rules/core.md` и подсказка поиска из `opencode/AGENTS.md` добавляются однократно через `session.hook("context")` в окончательный системный контекст каждого запроса агентного цикла, включая продолжения после инструментов. Установщик удаляет эти два пути из нативного `instructions`, сохраняя остальные пользовательские инструкции. Это охватывает и пользовательский `ask`: его файл мог перезаписывать `system`, добавленный через `agent.transform`. Вывод `debug agents` не содержит дополнений этого хука; доставку проверяет нативный тест с локальным провайдером для `ask`, `build` и `plan`.

Подсказка требует загрузить `tokensave-routing`, обнаружить схемы MCP через поиск каталога инструментов и использовать TokenSave для кода, RAGSave для смыслового поиска. Документация и `SKILL.md` тоже могут быть индексированы. Встроенные `read`/`grep`/`glob` остаются доступны для файлов вне индекса и обоснованного fallback. Это инструкции модели, а не блокирующий guard. Для применения изменений используйте `opencode reload` после завершения активных операций: перезагрузка может отменить взаимодействия текущей location с сообщением `Interaction cancelled because the location shut down`. Изолированные проверки выполняйте отдельным сервером `opencode serve`.

Перед fallback модель должна назвать конкретный сбой MCP или доказательство отсутствия покрытия и ограничить локальное чтение этой областью. Продолжение после handoff и известный путь не отменяют правила. Если `tokensave_files` отсутствует в каталоге установленной версии, проверка известного пути выполняется через `tokensave_read`, поиск — через доступные MCP-инструменты. Отсутствие одного необязательного инструмента не означает отказ всего MCP.

`optimize` использует [протокол наблюдений](../skills/shared/optimization-observations.md). Плагин OpenCode 2.2.5 автоматически сохраняет измерения после завершения, ошибки и прерывания выполнения, а также перед компактацией. Каталог: `$XDG_STATE_HOME/harness/optimize/opencode/<digest>/sessions/`, по умолчанию `~/.local/state/harness/optimize/opencode/<digest>/sessions/`. Каталоги имеют права 700, файлы — 600; запись атомарная, повторный сбор обновляет запись сессии и сохраняет `assessment`. Промпты, рассуждения, аргументы и результаты инструментов не сохраняются; остаются их метаданные, размеры и хеши. Сбор не вызывает модель.

API плагина отдаёт только активный контекст после компактации: снимки объединяются по ID, а `messageCoverage: active-context` и `gaps` обозначают необходимость полной сверки. Для полной истории конкретной сессии и её подагентов выполните `node ~/.config/harness/repo/bin/opencode-observe.mjs ses_ID`. Команда читает все страницы нативных сообщений и дочерних сессий, проверяет схему и версию, сохраняет компактные записи. Ошибка, неизвестная версия и циклическая пагинация не превращаются в нулевые измерения. Старые `observations.json` остаются отдельным источником; складывать повторяющиеся итоги нельзя.

Запись содержит последовательность моделей, агентов, инструментов, времени, повторов и компактаций, исходные счётчики, сумму по ответам, разницу с итогом сессии, дочерние ID и снимок тарифов реестра. Упоминание MCP в коде `execute` не считается доказательством выполненного вызова. Нативный успех не означает приёмку задачи: `$optimize` заполняет `assessment` по фактическим проверкам и классифицирует сопоставимые задачи. Команда harness `/handoff` сохраняет явную связь с новой сессией в `handoff.targetID`; полная сверка сохраняет эту связь. Другие переносы требуют нативных данных: отсутствие продолжения в дочерних ID не доказывает отсутствие его затрат.

`money.nativeReportedUSD` сохраняет исходную сумму; `validatedUSD` остаётся `null` без подтверждённой цены. Нулевой расход при ненулевых токенах и расхождение суммы по ответам отмечаются в `gaps`. Компактации учитываются отдельно при наличии нативных счётчиков; заголовки и другие вспомогательные запросы могут оставлять необъяснённый остаток. Итог родителя с подагентами не складывается, пока семантика включения детей не проверена. Тарифы DeepSeek зависят от времени; снимок реестра не подтверждает применённый тариф и не позволяет переписать старые нули как точный счёт. Неполные данные оставляют соответствующий план оптимизации отложенным. Результаты проверки приведены в [аудите](opencode-retrieval-audit.md).

Локальные провайдеры `deepseek` и `apimira` заданы в пользовательском конфиге. Ключи хранятся в `~/.config/opencode/keys/` с правами 600 и подключены через `{file:...}`; они не зависят от окружения фонового сервера и не попадают в Git. DeepSeek использует chat-completions, Apimira — Responses. Настройки провайдеров сохраняются установщиком.

Модель и effort выбирает пользователь. Установщик сохраняет глобальную модель,
удаляет прежние команды и агентов `harness-brief`, `harness-plan`,
`harness-review`, `harness-review-flash` и старые привязки встроенных агентов
к DeepSeek Flash/Pro. Настройки других провайдеров и пользовательских агентов
сохраняются; повторная установка идемпотентна.

Скиллы задают процедуры независимо от модели. Планирование выполняется в текущей
сессии. Полное ревью запускается только по явному запросу пользователя через
`/review` на выбранной модели; отдельные ревьюеры требуют явного запроса.
Правила работы с подготовленными MR — в
[mr-delegation.md](../skills/review/reference/mr-delegation.md).

Перед коммитом выполняются проверки стандартов и безопасности текущего diff,
обязательные проверки проекта и необходимые тесты затронутого поведения.
Подтверждённые ошибки, уязвимости, секреты и нарушения обязательных правил
блокируют коммит; косметические предложения его не задерживают.
При создании или обновлении MR запускаются полные тесты и обязательные проверки
проекта, затем выполняется push и доставка MR. Отдельный анализ покрытия и полное
ревью автоматически не запускаются. Успешные проверки повторяются только при
изменении входных данных.

Временный план хранится в `.opencode/plans/<task-id>.md`; явный путь пользователя
имеет приоритет. После завершения задачи удаляется только её временный план,
при Handoff передаётся точный путь незавершённого плана.

Ручной `/handoff` генерирует сводку на текущей модели и сохраняет её в продолжении.
Автоматического перехода на Pro после тупика нет. Старые маркеры
`HARNESS-ROUTE` удаляются из сводки и не влияют на модель. Для DeepSeek сохранён
явный ручной аргумент `--route=pro|flash`; без него модель и variant сохраняются.
Продолжение получает сводку без старой истории.

Проверки: `opencode debug config --standalone`, `opencode mcp list --standalone`, `opencode debug agents --standalone`. В OpenCode v2 список MCP в отдельном сервере до инициализации проектной location может быть пустым. Проверяйте доступность вызовом инструмента из сессии нужного проекта; наличие конфигурации само по себе не подтверждает выполнение плагина или доступность MCP.

`experimental.background_compaction` выключен; автоматическая компактация остаётся включённой с прежними порогами. После review координатор использует доказательства исполнителя; дополнительное чтение требует назвать конкретный пробел или изменившуюся ревизию. Шумные проверки с первого запуска проходят через `brief-output.sh`. Инструкция разрешает повторное использование успешной проверки только при совпадении команды, отпечатка релевантных исходников и конфигурации, lockfiles, toolchain и значимого окружения, с сохранённым полным логом. Один SHA не покрывает незакоммиченные изменения. Автоматического кеша произвольных shell-команд нет.

Кеш Handoff проверяет существование продолжения перед повторным открытием. Удалённая сессия создаётся заново; временная ошибка доступа останавливает перенос. При неудачной отправке повтор проверяет, не был ли точный restore-запрос уже принят, чтобы не дублировать контекст. Если продолжение уже содержит историю, но получение запроса подтвердить нельзя, например после compaction, повторная отправка останавливается до проверки этой сессии. Незавершённая сводка хранится до 24 часов; очистка просроченного текста выполняется при загрузке плагина и повторном обращении к записи. Успешная отправка сразу удаляет текст из записи. Операционный список прежних ID ограничен 32; связи, уже собранные для учёта, сохраняются в приватных observations. Числа заданы в `opencode/cache-policy.mjs`. Файл `HANDOFF.md` остаётся пользовательским артефактом и по TTL не удаляется.

`opencode/instructions.mjs` перечитывает core и OpenCode AGENTS для каждого запроса и ключа Handoff; сводка и compaction также читают актуальный handoff skill. Плагин оставляет одну свою копию инструкций и маршрутизации в запросе. `opencode/context-cache.mjs` заменяет повторный идентичный полный текст MCP-чтения или native skill размером от 512 байт ссылкой на первый tool call только внутри фактически отправляемого запроса. История на диске не меняется, выполнение инструмента не пропускается. После compaction, Handoff или перехода в другую сессию отсутствие исходного текста автоматически запрещает сокращение. Изменившиеся результаты, обрезанный вывод, JSON, ошибки и вложенные файлы не кешируются. Кеш ответов модели не добавлен. Для загрузки нового кода плагина нужен перезапуск OpenCode; после этого изменения текстовых инструкций подхватываются без перезапуска.

Для отложенной задачи DeepSeek: `node ~/.config/harness/repo/bin/opencode-offpeak.mjs -- --agent build 'задание'`. Предварительный просмотр времени без запроса модели: добавьте `--check` перед `--`. Скрипт ждёт окончания будничного пикового окна UTC 01–04 или 06–10, затем запускает `opencode run`; без явной модели выбирает Flash `#high`. Интерактивные сессии не откладываются. Расписание взято из [тарифов DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/); календарь китайских праздников не подключён, контролируется только время старта. Это не гарантирует тариф для всех запросов длинной задачи.

Сборщик уменьшает страницу сообщений со 100 до 10 и 1 только при невалидном JSON, сохраняя курсор. Учёт разделяет ответы (`messageSum`), доступные вспомогательные сообщения, включая компактации (`auxiliarySum`), и необъяснённый остаток (`residual`). Неизвестные счётчики остаются неизвестными. Метаданные инструментов включают текстовые байты, строки и применение `brief-output.sh`. Снимок расписания DeepSeek помечен как непроверенный для биллинга. Экономия в деньгах требует сравнения сопоставимых задач и сверки со счётом провайдера; размеры вывода и нативные суммы OpenCode такой сверкой не являются.

Дневной отчёт обновляется после автоматического сбора и запуска `opencode-observe.mjs`; без активности дня отдельного фонового задания нет. Просмотр: `node ~/.config/harness/repo/bin/opencode-costs.mjs report`, другой день — `--date YYYY-MM-DD`, JSON — `--json`. Приватные JSON и Markdown лежат в `$XDG_STATE_HOME/harness/optimize/opencode/reports/`. День определяется временем сообщения в настроенном часовом поясе. Сообщения с одинаковыми ID учитываются один раз; итоги родителя и детей не складываются. Модели, варианты, агенты, компактации, отдельные счётчики токенов, самые дорогие наблюдаемые сессии и пробелы покрытия доступны в отчёте. Старые записи без отпечатков вывода не дают данных для поиска повторов.

`node ~/.config/harness/repo/bin/opencode-costs.mjs init` создаёт `~/.config/harness/opencode-costs.json`, сохраняя имеющиеся настройки. По умолчанию: `timeZone: Europe/Moscow`, предупреждение `dailyProviderCNY: 25`, `dailyNativeUSD: null`, `sessionAssistantMessages: 100`, `repeatedToolCalls: 3`, `consecutiveFailures: 3`. `null` отключает соответствующий порог. Уведомления локальные, не прерывают задачи и повторяются не чаще одного раза за день для типа, сессии и порога. Предупреждение CNY опирается только на введённый счёт провайдера; автоматического доступа к биллингу нет. USD относится к непроверенной нативной оценке. Кандидаты повторов имеют одинаковые хеши входа и результата инструмента; компактация и явная запись файла сбрасывают область сравнения. Это повод проверить повтор, а не доказательство лишней работы или разрешение вернуть старый результат.

Для внесения суммы провайдера подготовьте приватный JSON с `date`, `currency` (`CNY` или `USD`), `cost`, необязательными `apiRequests`, `tokens`, `accountScope`, `timeZone` и выполните `node ~/.config/harness/repo/bin/opencode-costs.mjs billing --file /путь/счёт.json`. Последний импорт той же даты, валюты, области и часового пояса заменяет прежний; разные точки и исходные `billing-baseline-*.json` показываются отдельно, не суммируются и не считаются сверенными с сессиями.

Качество задачи отмечается вручную: `node ~/.config/harness/repo/bin/opencode-costs.mjs assess ses_ID --file /путь/оценка.json`. Поля: `accepted` (boolean или null), `workload`, `comparisonKey`, `phase` (`before` или `after`), `checksPassed`, `checksFailed`, `correctionCount`. Неизвестная приёмка не превращается в успех. Одинаковый `comparisonKey` задаёт вручную сопоставимую область, сложность, ревизию, состояние кэша и критерии проверки. Сравнение включает уникальные наблюдаемые запросы всего связанного семейства, включая подагентов и явные продолжения Handoff. Отсутствие члена или полной истории оставляет среднюю оценку неизвестной. Оценку ставят одной сессии семейства; неоднозначные семейства с несколькими оценками не участвуют в сравнении. Число образцов и результаты проверок сохраняются; процент экономии без сверенных цен не вычисляется.

Handoff повторно использует уже созданное продолжение, а после сбоя записи сводки, создания сессии или отправки продолжения — готовую сводку. Ключ включает исходный контекст, модель, агента, разрешения, параметры переноса и правила harness. Изменение этих данных сбрасывает кэш; предыдущие ID продолжений сохраняются для учёта. Сводка не разделяется между сессиями, результаты инструментов и обычные ответы модели не подменяются кэшем. Изменения репозитория вне истории сессии не проверяются этим ключом: кэш сохраняет только наблюдённую сводку разговора, а продолжение заново читает инструкции и проверяет код.

Агент `ask` восстановлен из истории `origin/main` перед коммитом `844226d`. Исходник — `opencode/agent/ask.md`; установщик подключает его в `<config>/agents/ask.md`. Выберите `ask` через Tab или запустите `opencode run --agent ask 'вопрос'`. Он отвечает и показывает готовый код в чате. Нативные разрешения запрещают редактирование файлов, делегирование и MCP-замены TokenSave. Shell-команды разрешены для исследования и проверок; запрет изменять через них файлы задан инструкцией агенту, без технической блокировки. Playwright MCP доступен для просмотра сайтов; чувствительные действия требуют подтверждения по `rules/core.md`. Старое исключение для подагента `commit` удалено в соответствии с режимом без изменений.

При диагностике проверяйте не только `opencode mcp list`, но и разрешения выбранного агента в `opencode debug agents`. Запрет `playwright_*: deny` скрывает инструменты браузера даже при подключённом сервере. После изменения агента выполните `opencode reload` и проверьте реальный вызов из `ask`. Инструменты MCP находятся через нативный поиск каталога OpenCode по пространству `playwright`; отсутствие инструмента в исходном контексте ещё не означает отсутствие MCP. Успешный вызов браузера не подтверждает вход в Cloudflare: это проверяется отдельно в нужной вкладке.
