# OpenCode

`./install.sh --opencode` подключает OpenCode v2 к общим правилам, навыкам и реестру MCP harness. `./install.sh --opencode --check` проверяет установку без записи.

Исходный базовый конфиг находится в `opencode/opencode.jsonc`: в нём заданы провайдер `deepseek`, модели и модель по умолчанию `deepseek/deepseek-flash`. Установщик объединяет его с пользовательским `~/.config/opencode/opencode.jsonc` (пользовательские значения приоритетнее), добавляет инструкции и плагин из репозитория. Перед изменениями создаются резервные копии. Авторизация и ключи остаются вне Git.

Каталог задаётся через `OPENCODE_CONFIG_DIR` или `XDG_CONFIG_HOME`. Установщик и MCP-синхронизация принимают JSONC с комментариями и завершающими запятыми. `opencode.json` и `opencode.jsonc` объединяются рекурсивно, значения JSONC имеют приоритет, массивы заменяются. Изменения записываются в JSONC с сохранением комментариев. Удаляемые поля также удаляются из `opencode.json`, если заданы там, чтобы они не восстанавливались при объединении; остальные настройки JSON сохраняются. Перед изменением каждого файла создаётся резервная копия. Повреждённый конфиг отклоняется до записи.

Для JSONC используется `jsonc-parser`, зависимость зафиксирована в `opencode/package-lock.json`. Установка автоматически выполняет `npm --prefix opencode ci --ignore-scripts`, если зависимость отсутствует. `--check` зависимости не устанавливает и сообщает команду для их установки.

Общие файлы устанавливаются через `bin/install-files.mjs`: существующий TokenSave config сохраняется, конфликтующие файлы и ссылки skills/инструментов остаются активными, установка сообщает ошибку. Повторная установка не дублирует shell bootstrap; bash, zsh/ZDOTDIR и macOS login shell описаны в `docs/opencode.md` и `bin/shell-install.mjs`. Общая индексация хранит замки в `$XDG_STATE_HOME/harness` или `AI_HOOKS_STATE_DIR`. Git config, авторизация, пользовательские провайдеры и сторонние MCP сохраняются.

`bin/mcp-sync.mjs --opencode` подключает TokenSave, RAGSave и Playwright из `mcp/servers.json`. Плагин `opencode/harness.js` запускает существующие обработчики синхронизации индексов при загрузке с прогревом RAG. Каталог берётся из `context.location.directory`, а не из рабочего каталога общего сервера. События `session.execution.succeeded`, `session.execution.failed` и `session.execution.interrupted` запускают повторную синхронизацию обоих индексов после ответа. Подписка V2 читается как асинхронный поток. Правила `rules/core.md` доставляются контекстным хуком.

Полные правила `rules/core.md` и подсказка поиска из `opencode/AGENTS.md` добавляются однократно через `session.hook("context")` первым сообщением транскрипта каждого запроса агентного цикла, включая продолжения после инструментов. Установщик удаляет эти два пути из нативного `instructions`, сохраняя остальные пользовательские инструкции. Это охватывает и пользовательский `ask`: его файл мог перезаписывать `system`, добавленный через `agent.transform`. Нативная компактация получает тот же блок и промпт Handoff в конце сообщений, поэтому системный промпт и префикс транскрипта совпадают с обычным запросом и кэш провайдера переиспользуется. Вывод `debug agents` не содержит дополнений этого хука; доставку проверяет нативный тест с локальным провайдером для `ask`, `build` и `plan`.

В проекте с индексом подсказка требует загрузить `tokensave-routing`, обнаружить схемы MCP через поиск каталога инструментов и использовать TokenSave для кода, RAGSave для смыслового поиска; без индекса скилл не загружается, а встроенные инструменты используются напрямую. Документация и `SKILL.md` тоже могут быть индексированы. Встроенные `read`/`grep`/`glob` остаются доступны для файлов вне индекса и обоснованного fallback. Это инструкции модели, а не блокирующий guard. Для применения изменений используйте `opencode reload` после завершения активных операций: перезагрузка может отменить взаимодействия текущей location с сообщением `Interaction cancelled because the location shut down`. Изолированные проверки выполняйте отдельным сервером `opencode serve`.

`opencode/question-guard.mjs` переносит прежний Stop-хук вопроса: после `session.execution.succeeded` плагин читает последний ход и, если ответ кончается вопросом или ожиданием решения пользователя текстом без вызова `question`, отправляет в сессию synthetic-сообщение с причиной. Один и тот же ход повторно не проверяется, подагенты, ход с уже вызванным `question` и однострочное приветствие первого хода не судятся. Порог контекста здесь не проверяется: о длинной сессии плагин только уведомляет пользователя, а Handoff запускается вручную.

`opencode/retrieval-routing.mjs` добавляет правила выбора прямо в описания инструментов: MCP перед проектным чтением только при наличии индекса, загрузка скилла только по области задачи, ссылки скилла относительно возвращённого `Base directory`, без поиска по `/` и домашнему дереву, без shell-заглушек и делегирования без явного запроса. Схемы, выполнение и разрешения инструментов сохраняются. Надпись `SubagentsShellTerminals` в интерфейсе сама по себе не доказывает запуск подагента: проверяйте фактические вызовы и дочерние сессии.

Перед fallback модель должна назвать конкретный сбой MCP или доказательство отсутствия покрытия и ограничить локальное чтение этой областью. Продолжение после handoff и известный путь не отменяют правила. Если `tokensave_files` отсутствует в каталоге установленной версии, проверка известного пути выполняется через `tokensave_read`, поиск — через доступные MCP-инструменты. Отсутствие одного необязательного инструмента не означает отказ всего MCP.

`optimize` использует [протокол наблюдений](../skills/shared/optimization-observations.md). Плагин OpenCode 2.2.5 автоматически сохраняет измерения после завершения, ошибки и прерывания выполнения, а также перед компактацией. Каталог: `$XDG_STATE_HOME/harness/optimize/opencode/<digest>/sessions/`, по умолчанию `~/.local/state/harness/optimize/opencode/<digest>/sessions/`. Каталоги имеют права 700, файлы — 600; запись атомарная, повторный сбор обновляет запись сессии и сохраняет `assessment`. Промпты, рассуждения, аргументы и результаты инструментов не сохраняются; остаются их метаданные, размеры и хеши. Сбор не вызывает модель.

API плагина отдаёт только активный контекст после компактации: снимки объединяются по ID, а `messageCoverage: active-context` и `gaps` обозначают необходимость полной сверки. Для полной истории конкретной сессии и её подагентов выполните `node ~/.config/harness/repo/bin/opencode-observe.mjs ses_ID`. Команда читает все страницы нативных сообщений и дочерних сессий, проверяет схему и версию, сохраняет компактные записи. Ошибка, неизвестная версия и циклическая пагинация не превращаются в нулевые измерения. Старые `observations.json` остаются отдельным источником; складывать повторяющиеся итоги нельзя.

Запись содержит последовательность моделей, агентов, инструментов, времени, повторов и компактаций, исходные счётчики, сумму по ответам, разницу с итогом сессии, дочерние ID и снимок тарифов реестра. Упоминание MCP в коде `execute` не считается доказательством выполненного вызова. Нативный успех не означает приёмку задачи: `$optimize` заполняет `assessment` по фактическим проверкам и классифицирует сопоставимые задачи. Команда harness `/handoff` больше не создаёт новую сессию, поэтому новые записи `handoff.targetID` не появляются; полная сверка продолжает учитывать legacy-связи. Другие переносы требуют нативных данных: отсутствие продолжения в дочерних ID не доказывает отсутствие его затрат.

`money.nativeReportedUSD` сохраняет исходную сумму; `validatedUSD` остаётся `null` без подтверждённой цены. Нулевой расход при ненулевых токенах и расхождение суммы по ответам отмечаются в `gaps`. Компактации учитываются отдельно при наличии нативных счётчиков; заголовки и другие вспомогательные запросы могут оставлять необъяснённый остаток. Итог родителя с подагентами не складывается, пока семантика включения детей не проверена. Тарифы DeepSeek зависят от времени; снимок реестра не хранит применённый к сообщению тариф, хотя формула и расписание сверены с почасовым счётом провайдера, и старые нули не переписываются как точный счёт. Неполные данные оставляют соответствующий план оптимизации отложенным. Результаты проверки приведены в [аудите](opencode-retrieval-audit.md).

Провайдер `deepseek` с моделями `deepseek-v4-pro`, `deepseek-flash` и модель по умолчанию заданы в базовом `opencode/opencode.jsonc`. В `cost` обеих моделей указан непиковый тариф DeepSeek, поэтому отчёт о стоимости в пиковое окно занижен вдвое; плагин предупреждает об этом при выборе модели. Установщик удаляет из live-конфига устаревшие ключи `*-offpeak` и `*-peak`, перенаправляя ссылки на `model` и модели агентов на обычные идентификаторы. API-ключ подключается через `{file:~/.config/opencode/keys/deepseek}`, хранится с правами 600 и не попадает в Git; значение не зависит от окружения фонового сервера. DeepSeek использует chat-completions. Остальные пользовательские провайдеры и их ключи сохраняются в live-конфиге. Значения окружения MCP записываются ссылками `{env:NAME}`, поэтому токены не попадают в конфиг открытым текстом; OpenCode раскрывает их при чтении конфига.

Провайдеры `kimi-for-coding-oauth` и `openai` подключены по подписке/OAuth, поэтому тариф за токен для них не задаётся: расход считается по плану провайдера, и выдуманный `cost` только исказил бы отчёты. Экономичный пресет для них задаёт `settings.reasoningEffort: "low"` на уровне провайдера; явный вариант (`#high`, `#max`) в сессии по-прежнему перекрывает это значение. Ограничения контекста и вывода для этих моделей не переопределяются: у OpenAI при входе через ChatGPT OpenCode применяет собственные кэпы, а у Kimi каталог уже содержит корректные лимиты. Плагин ограничивает рабочий ввод и вывод всех моделей теми же значениями, что и для DeepSeek.

Модель и effort выбирает пользователь. Effort циклически переключается по `ctrl+o`
и прежнему `ctrl+t`, а открытие недавних сессий перенесено на `<leader>o` в
`~/.config/opencode/cli.json`; установщик подключает этот файл симлинком на
`opencode/cli.json`, не изменяя его содержимое. В интегрированном
терминале VS Code `alt+[KeyO]` из `vscode/keybindings.json` отправляет `\u000f`
по scan code, поэтому сочетание работает и в русской раскладке: xterm.js не
передаёт base-layout клавишу, и нативный fallback OpenCode для нелатинских
раскладок в TUI не срабатывает. По тому же scan code `alt+[KeyP]` отправляет
`ctrl+x`, затем `m` — это привязка `model.list`, поэтому открывается меню
выбора модели, а не текст в промпте. Установщик сохраняет глобальную модель,
удаляет прежние команды и агентов `harness-brief`, `harness-plan`,
`harness-review`, `harness-review-flash` и старые привязки встроенных агентов
к DeepSeek Flash/Pro. Настройки других провайдеров и пользовательских агентов
сохраняются; повторная установка идемпотентна.

Скиллы задают процедуры независимо от модели. Для `task-brief` политика harness
сжимает контекст в той же сессии и сохраняет агент, модель и variant; планирование
и реализация идут на модели сессии. Для существенных открытых вопросов используется
`question` с вариантами и рекомендацией; ответы сохраняются в плане перед
реализацией. Переход вызывает инструмент `brief_transition` через execute,
загрузка скилла его не заменяет. Настройка и ограничения описаны в
[context-automation.md](context-automation.md#бриф-и-сжатие-контекста).
Полное ревью запускается только по явному запросу пользователя через
`/review` на выбранной модели; отдельные ревьюеры требуют явного запроса.
Правила работы с подготовленными MR — в
[mr-delegation.md](../skills/review/reference/mr-delegation.md).

Перед коммитом выполняются проверки стандартов и безопасности текущего diff,
обязательные проверки проекта и необходимые тесты затронутого поведения.
Подтверждённые ошибки, уязвимости, секреты и нарушения обязательных правил
блокируют коммит; косметические предложения его не задерживают.
При создании или обновлении MR запускаются полные тесты и обязательные проверки
проекта, затем выполняется push и доставка MR. Отдельный анализ покрытия и полное
ревью автоматически не запускаются. Успешные проверки повторяются только при
изменении входных данных.

Временный план хранится в `.opencode/plans/<task-id>.md`; явный путь пользователя
имеет приоритет. Плагин привязывает managed-план к сессии и при Handoff передаёт
только его точный путь. Явный аргумент `/handoff <карта>.md` привязывает
существующий файл как user-owned; checkpoint и оставшиеся шаги остаются в нём, а
prune такой файл не удаляет. После завершения задачи удаляется только её временный
план.

Ручной `/handoff` находит managed-план сессии или создаёт его из сводки, затем
запускает сжатие контекста в той же сессии; новая сессия не создаётся. Модель и
variant сессии сохраняются, сводка использует `agents.compaction.model`.
Автоматического перехода на Pro после тупика нет. Старые маркеры `HARNESS-ROUTE`
удаляются из сводки и не влияют на модель. После сжатия плагин отправляет ссылку
на план и продолжает первый незавершённый шаг; тело плана в запрос не копируется,
поэтому завершённые шаги удаляются из раздела оставшихся шагов, а не переносятся.

Инструмент `context_cache` сохраняет выбранные уже полученные диапазоны TokenSave в
`.opencode/context-cache/`, с Git ignore и приватными правами. Он хранит только
доказательства и путь managed-плана; checkpoint остаётся в плане и в кеш не
копируется. `save` принимает необязательный `sources` из `{file, lines: "A-B"}`;
без `sources` прежний выбор сохраняется, `[]` очищает его. Лимиты: 8 диапазонов по
160 строк, 24 КБ доказательств. Перед Handoff плагин автоматически дополняет кеш
последними прочитанными диапазонами TokenSave в пределах тех же лимитов, даже если
агент пропустил `save`. Сохранённые выбранные диапазоны имеют приоритет; обрезанные
результаты, внешние, удалённые и изменившиеся строки пропускаются. Это сохранение
работает и для обоих переходов `brief_transition`. Файлы появляются
в `.opencode/context-cache/` после `save`, сжатия или native compaction новой
версией плагина; старые переносы кеш задним числом не создают. После обновления кода
требуется `opencode service restart` без активной работы; `reload` может сохранить
старый модуль. Кеш остаётся привязан к той же сессии, поскольку новая не создаётся.
Перед native compaction плагин также сохраняет доступные диапазоны TokenSave, даже
без `save`. Ссылка на кеш и путь плана включаются в запрос на сводку. Handoff и
compaction получают перечень путей с диапазонами без исходников и без checkpoint;
обычный запрос не получает содержимое кеша. Повторную ссылку на кеш получает только
первый запрос после compaction: перечень диапазонов, активные skill и требование
первой правки, без checkpoint. Checkpoint читается из плана, а не из кеша.
Плагин считает чтения без правки: предупреждение после 20 вызовов, требование
правки после 40 и полное отключение инструментов на 60; счётчик сбрасывается на
edit, write и правку через `tokensave_multi_str_replace`. Выводы встроенных
инструментов длиннее 20 КБ усекаются в `execute.after` с маркером `full_result=`
и полным артефактом в `$XDG_STATE_HOME/harness/context-output`.
`restore` возвращает перечень диапазонов и только явно выбранные строки, проверив хеш всего текущего
файла, включая незакоммиченные изменения. Устаревшие строки требуют нового MCP-чтения.
`complete` удаляет только кеш этой задачи после завершения работы и проверок.
При загрузке плагина и после завершения ответа (`session.execution.*`, не чаще
`taskPruneMs`) плагин проверяет кеши и managed-планы старше 24 часов бездействия.
Если сессия ещё существует, файл и привязка продлеваются; кеш или план закрытой
сессии удаляются вместе с привязкой, осиротевшие файлы и устаревшие привязки
очищаются. Пользовательские планы не затрагиваются. Истёкший кеш не включается и
в первый запрос после паузы. Закрытие терминала не завершает сессию OpenCode,
поэтому свежий кеш незавершённой задачи сохраняется для продолжения. Выбор для
следующего шага через `save` и завершение вызывает агент по инструкциям: плагин не
определяет окончание задачи по событию успешного ответа. Весь старый контекст
автоматически не копируется.

Проверки: `opencode debug config --standalone`, `opencode mcp list --standalone`, `opencode debug agents --standalone`. В OpenCode v2 список MCP в отдельном сервере до инициализации проектной location может быть пустым. Проверяйте доступность вызовом инструмента из сессии нужного проекта; наличие конфигурации само по себе не подтверждает выполнение плагина или доступность MCP.

`experimental.background_compaction` выключен; автоматическая компактация остаётся включённой, пороги задаёт `contextPolicy.opencode` (135000 / buffer 15000 / keep 10000). Встроенный агент `plan` отключён, `ask` и `build` сохранены. После review координатор использует доказательства исполнителя; дополнительное чтение требует назвать конкретный пробел или изменившуюся ревизию. Шумные проверки с первого запуска проходят через `brief-output.sh`. Инструкция разрешает повторное использование успешной проверки только при совпадении команды, отпечатка релевантных исходников и конфигурации, lockfiles, toolchain и значимого окружения, с сохранённым полным логом. Один SHA не покрывает незакоммиченные изменения. Автоматического кеша произвольных shell-команд нет.

Legacy-связи `handoff.targetID` и `handoff.targetIDs` сохраняются в наблюдениях и учитываются при анализе расходов, но новые `/handoff` и `brief_transition` их не создают: контекст сжимается в той же сессии. Временная ошибка доступа к сессии не превращается в нулевые измерения; отсутствие продолжения в дочерних ID не доказывает отсутствие его затрат. Числа заданы в `opencode/cache-policy.mjs`. Файл `.opencode/HANDOFF.md` больше не создаётся и остаётся только пользовательским артефактом.

`opencode/instructions.mjs` перечитывает core и OpenCode AGENTS для каждого запроса и ключа Handoff; сводка и compaction также читают актуальный handoff skill. Плагин оставляет одну свою копию инструкций и маршрутизации в запросе. `opencode/context-cache.mjs` заменяет повторный идентичный полный текст MCP-чтения или native skill размером от 512 байт ссылкой на первый tool call только внутри фактически отправляемого запроса. История на диске не меняется, выполнение инструмента не пропускается. После compaction, Handoff или перехода в другую сессию отсутствие исходного текста автоматически запрещает сокращение. Изменившиеся результаты, обрезанный вывод, JSON, ошибки и вложенные файлы не кешируются. Кеш ответов модели не добавлен. Для загрузки нового кода плагина нужен перезапуск OpenCode; после этого изменения текстовых инструкций подхватываются без перезапуска.

Для отложенной задачи DeepSeek: `node ~/.config/harness/repo/bin/opencode-offpeak.mjs -- --agent build 'задание'`. Предварительный просмотр времени без запроса модели: добавьте `--check` перед `--`. Скрипт ждёт окончания будничного пикового окна UTC 01–04 или 06–10, затем запускает `opencode run`; без явной модели выбирает Flash `#high`. Модель не подменяется: скрипт только переносит старт в непиковое окно и сообщает это в `--check`. Интерактивные сессии не откладываются. Расписание взято из [тарифов DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/); календарь китайских праздников учитывается в `isPeakAt`, но не гарантирует тариф для всех запросов длинной задачи.

Сборщик уменьшает страницу сообщений со 100 до 10 и 1 только при невалидном JSON, сохраняя курсор. Учёт разделяет ответы (`messageSum`), доступные вспомогательные сообщения, включая компактации (`auxiliarySum`), и необъяснённый остаток (`residual`). Неизвестные счётчики остаются неизвестными. Метаданные инструментов включают текстовые байты, строки и применение `brief-output.sh`. Снимок расписания DeepSeek сверен с почасовым счётом провайдера: суммы за 2026-11-02 совпали до четвёртого знака. Экономия в деньгах требует сравнения сопоставимых задач и сверки со счётом провайдера; размеры вывода и нативные суммы OpenCode такой сверкой не являются.

Сумма USD в интерфейсе OpenCode 2.2.5 берётся из учёта сессии. Если провайдер
передал стоимость в поддерживаемом поле ответа, используется она; иначе OpenCode
рассчитывает её по тарифам модели и счётчикам обычного входа, чтения/записи кеша,
выхода и reasoning. Механизм проверен по [SessionUsage.record](https://github.com/anomalyco/opencode/blob/v2.2.5/packages/core/src/session/usage.ts).
Это не запрос списаний с баланса. Устаревший каталог, неполные счётчики или
тарифы по времени могут исказить оценку. Например, на 2026-11-03 пиковые тарифы
DeepSeek вдвое выше непиковых; расчёт только по непиковому каталогу занижает такую
часть расходов вдвое. Нативные суммы в отчёте остаются непроверенными; фактический
счёт провайдера импортируется отдельно. Файловый кеш `context_cache` не является
кешем провайдера и сам по себе не даёт скидку на переданные модели токены.

Поэтому отчёт дополнительно пересчитывает USD по каждому сообщению: берёт тариф
Flash или Pro, проверяет пиковое окно по `time.created` и раздельно считает
обычный вход, чтение кеша и выход с reasoning. В отчёте видны сумма, компоненты,
число сообщений без тарифа и расхождение с нативной оценкой. Команда `/cost` в TUI
показывает тот же пересчёт для открытой сессии, не перезаписывая число в нижней
панели, текущее окно тарифа (пик с временем окончания по MSK или непик) и цену
сообщения по паре модель/агент. В дневном отчёте у моделей и агентов есть колонка
`USD/сообщение`, а запросы из кабинета сравниваются с локально наблюдёнными
сообщениями: расхождение означает, что видна не вся активность аккаунта. При ручном
выборе Pro плагин показывает предупреждение о его цене; сам harness Pro не выбирает
и не подменяет модель — планировщик брифа наследует модель открытой сессии. Базовые записи моделей в
`opencode.jsonc` хранят пиковые цены, алиасы
`-offpeak` — непиковые; расписание выбирает алиас только для отложенного запуска.

Дневной отчёт обновляется после автоматического сбора и запуска `opencode-observe.mjs`; без активности дня отдельного фонового задания нет. Просмотр: `node ~/.config/harness/repo/bin/opencode-costs.mjs report`, другой день — `--date YYYY-MM-DD`, JSON — `--json`. Приватные JSON и Markdown лежат в `$XDG_STATE_HOME/harness/optimize/opencode/reports/`. День определяется временем сообщения в настроенном часовом поясе. Сообщения с одинаковыми ID учитываются один раз; итоги родителя и детей не складываются. Модели, варианты, агенты, компактации, отдельные счётчики токенов, самые дорогие наблюдаемые сессии и пробелы покрытия доступны в отчёте. Для поиска повторов достаточно отпечатка входа инструмента; отпечаток вывода не требуется.

`node ~/.config/harness/repo/bin/opencode-costs.mjs init` создаёт `~/.config/harness/opencode-costs.json`, сохраняя имеющиеся настройки. По умолчанию: `timeZone: Europe/Moscow`, предупреждение `dailyProviderCNY: 25`, `dailyNativeUSD: null`, `sessionAssistantMessages: 100`, `repeatedToolCalls: 2`, `consecutiveFailures: 3`. `null` отключает соответствующий порог. Уведомления локальные, не прерывают задачи и повторяются не чаще одного раза за день для типа, сессии и порога. Предупреждение CNY опирается только на введённый счёт провайдера; автоматического доступа к биллингу нет. USD относится к непроверенной нативной оценке. Кандидаты повторов имеют одинаковые имя инструмента и хеш входа; результат может отличаться. Компактация и явная запись файла сбрасывают область сравнения. Это повод проверить повтор, а не доказательство лишней работы или разрешение вернуть старый результат.

Для внесения суммы провайдера подготовьте приватный JSON с `date`, `currency` (`CNY` или `USD`), `cost`, необязательными `apiRequests`, `tokens`, `accountScope`, `timeZone` и выполните `node ~/.config/harness/repo/bin/opencode-costs.mjs billing --file /путь/счёт.json`. Последний импорт той же даты, валюты, области и часового пояса заменяет прежний; разные точки и исходные `billing-baseline-*.json` показываются отдельно, не суммируются и не считаются сверенными с сессиями.

Качество задачи отмечается вручную: `node ~/.config/harness/repo/bin/opencode-costs.mjs assess ses_ID --file /путь/оценка.json`. Поля: `accepted` (boolean или null), `workload`, `comparisonKey`, `phase` (`before` или `after`), `checksPassed`, `checksFailed`, `correctionCount`. Неизвестная приёмка не превращается в успех. Одинаковый `comparisonKey` задаёт вручную сопоставимую область, сложность, ревизию, состояние кэша и критерии проверки. Сравнение включает уникальные наблюдаемые запросы всего связанного семейства, включая подагентов и явные продолжения Handoff. Отсутствие члена или полной истории оставляет среднюю оценку неизвестной. Оценку ставят одной сессии семейства; неоднозначные семейства с несколькими оценками не участвуют в сравнении. Число образцов и результаты проверок сохраняются; процент экономии без сверенных цен не вычисляется.

Handoff переиспользует managed-план, привязанный к сессии, и создаёт его из сводки только при отсутствии. Модель, агент, разрешения и параметры сессии сохраняются; отдельного кеша сводки или продолжения больше нет. Сводка не разделяется между сессиями, результаты инструментов и обычные ответы модели не подменяются кешем. После сжатия план перечитывается в той же сессии, поэтому изменения репозитория и инструкций проверяются заново.

Агент `ask` восстановлен из истории `origin/main` перед коммитом `844226d`. Исходник — `opencode/agent/ask.md`; установщик подключает его в `<config>/agents/ask.md`. Выберите `ask` через Tab или запустите `opencode run --agent ask 'вопрос'`. Он отвечает и показывает готовый код в чате. Нативные разрешения запрещают редактирование файлов, делегирование и MCP-замены TokenSave. Shell-команды разрешены для исследования и проверок; запрет изменять через них файлы задан инструкцией агенту, без технической блокировки. Playwright MCP доступен для просмотра сайтов; чувствительные действия требуют подтверждения по `rules/core.md`. Старое исключение для подагента `commit` удалено в соответствии с режимом без изменений.

При диагностике проверяйте не только `opencode mcp list`, но и разрешения выбранного агента в `opencode debug agents`. Запрет `playwright_*: deny` скрывает инструменты браузера даже при подключённом сервере. После изменения агента выполните `opencode reload` и проверьте реальный вызов из `ask`. Инструменты MCP находятся через нативный поиск каталога OpenCode по пространству `playwright`; отсутствие инструмента в исходном контексте ещё не означает отсутствие MCP. Успешный вызов браузера не подтверждает вход в Cloudflare: это проверяется отдельно в нужной вкладке.
