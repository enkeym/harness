# OpenCode

`./install.sh --opencode` подключает OpenCode v2 к общим правилам, навыкам и реестру MCP harness. `./install.sh --opencode --check` проверяет установку без записи.

Исходный базовый конфиг находится в `opencode/opencode.jsonc`. Установщик сохраняет пользовательские настройки в `~/.config/opencode/opencode.jsonc`, добавляет инструкции и плагин из репозитория. Перед изменениями создаются резервные копии. Авторизация и ключи остаются вне Git.

Каталог задаётся через `OPENCODE_CONFIG_DIR` или `XDG_CONFIG_HOME`. Установщик и MCP-синхронизация принимают JSONC с комментариями и завершающими запятыми. `opencode.json` и `opencode.jsonc` объединяются рекурсивно, значения JSONC имеют приоритет, массивы заменяются. Изменения записываются в JSONC с сохранением комментариев. Удаляемые поля также удаляются из `opencode.json`, если заданы там, чтобы они не восстанавливались при объединении; остальные настройки JSON сохраняются. Перед изменением каждого файла создаётся резервная копия. Повреждённый конфиг отклоняется до записи.

Для JSONC используется `jsonc-parser`, зависимость зафиксирована в `opencode/package-lock.json`. Установка автоматически выполняет `npm --prefix opencode ci --ignore-scripts`, если зависимость отсутствует. `--check` зависимости не устанавливает и сообщает команду для их установки.

`bin/mcp-sync.mjs --opencode` подключает TokenSave, RAGSave и Playwright из `mcp/servers.json`. Плагин `opencode/harness.js` запускает существующие обработчики синхронизации индексов при загрузке с прогревом RAG. Каталог берётся из `context.location.directory`, а не из рабочего каталога общего сервера. События `session.execution.succeeded`, `session.execution.failed` и `session.execution.interrupted` запускают повторную синхронизацию обоих индексов после ответа. Подписка V2 читается как асинхронный поток. Правила `rules/core.md` подключены через нативный `instructions`.

Маршрутизация навыков из `rules/core.md` и подсказка поиска из `opencode/AGENTS.md` добавляются через `session.hook("context")` в окончательный системный контекст каждого запроса агентного цикла, включая продолжения после инструментов. Это охватывает и пользовательский `ask`: его файл мог перезаписывать `system`, добавленный через `agent.transform`. Вывод `debug agents` не содержит дополнений этого хука; доставку проверяет нативный тест с локальным провайдером для `ask`, `build` и `plan`.

Подсказка требует загрузить `tokensave-routing`, обнаружить схемы MCP через поиск каталога инструментов и использовать TokenSave для кода, RAGSave для смыслового поиска. Документация и `SKILL.md` тоже могут быть индексированы. Встроенные `read`/`grep`/`glob` остаются доступны для файлов вне индекса и обоснованного fallback. Это инструкции модели, а не блокирующий guard. Для применения изменений используйте `opencode reload` после завершения активных операций: перезагрузка может отменить взаимодействия текущей location с сообщением `Interaction cancelled because the location shut down`. Изолированные проверки выполняйте отдельным сервером `opencode serve`.

Перед fallback модель должна назвать конкретный сбой MCP или доказательство отсутствия покрытия и ограничить локальное чтение этой областью. Продолжение после handoff и известный путь не отменяют правила. Если `tokensave_files` отсутствует в каталоге установленной версии, проверка известного пути выполняется через `tokensave_read`, поиск — через доступные MCP-инструменты. Отсутствие одного необязательного инструмента не означает отказ всего MCP.

`optimize` использует [протокол наблюдений](../skills/shared/optimization-observations.md). Плагин OpenCode 2.2.5 автоматически сохраняет измерения после завершения, ошибки и прерывания выполнения, а также перед компактацией. Каталог: `$XDG_STATE_HOME/harness/optimize/opencode/<digest>/sessions/`, по умолчанию `~/.local/state/harness/optimize/opencode/<digest>/sessions/`. Каталоги имеют права 700, файлы — 600; запись атомарная, повторный сбор обновляет запись сессии и сохраняет `assessment`. Промпты, рассуждения, аргументы и результаты инструментов не сохраняются; остаются их метаданные, размеры и хеши. Сбор не вызывает модель.

API плагина отдаёт только активный контекст после компактации: снимки объединяются по ID, а `messageCoverage: active-context` и `gaps` обозначают необходимость полной сверки. Для полной истории конкретной сессии и её подагентов выполните `node ~/.config/harness/repo/bin/opencode-observe.mjs ses_ID`. Команда читает все страницы нативных сообщений и дочерних сессий, проверяет схему и версию, сохраняет компактные записи. Ошибка, неизвестная версия и циклическая пагинация не превращаются в нулевые измерения. Старые `observations.json` остаются отдельным источником; складывать повторяющиеся итоги нельзя.

Запись содержит последовательность моделей, агентов, инструментов, времени, повторов и компактаций, исходные счётчики, сумму по ответам, разницу с итогом сессии, дочерние ID и снимок тарифов реестра. Упоминание MCP в коде `execute` не считается доказательством выполненного вызова. Нативный успех не означает приёмку задачи: `$optimize` заполняет `assessment` по фактическим проверкам и классифицирует сопоставимые задачи. Команда harness `/handoff` сохраняет явную связь с новой сессией в `handoff.targetID`; полная сверка сохраняет эту связь. Другие переносы требуют нативных данных: отсутствие продолжения в дочерних ID не доказывает отсутствие его затрат.

`money.nativeReportedUSD` сохраняет исходную сумму; `validatedUSD` остаётся `null` без подтверждённой цены. Нулевой расход при ненулевых токенах и расхождение суммы по ответам отмечаются в `gaps`. Title/compaction могут добавлять расходы вне сообщений assistant. Итог родителя с подагентами не складывается, пока семантика включения детей не проверена. Тарифы DeepSeek зависят от времени; снимок реестра не подтверждает применённый тариф и не позволяет переписать старые нули как точный счёт. Неполные данные оставляют соответствующий план оптимизации отложенным. Результаты проверки приведены в [аудите](opencode-retrieval-audit.md).

Локальные провайдеры `deepseek` и `apimira` заданы в пользовательском конфиге. Ключи хранятся в `~/.config/opencode/keys/` с правами 600 и подключены через `{file:...}`; они не зависят от окружения фонового сервера и не попадают в Git. DeepSeek использует chat-completions, Apimira — Responses. Настройки провайдеров сохраняются установщиком.

Если глобальная модель относится к `deepseek`, установщик включает маршрут из `opencode/model-routing.mjs`: основная сессия, `build`, `plan`, вспомогательные агенты и компактация работают на Flash. Явные настройки агентов другого провайдера сохраняются. `harness-brief`, `harness-plan` и `harness-review` — нативные подагенты Pro; команды `/harness-brief <задача>`, `/harness-plan <задача>` и `/harness-review <область изменений>` запускают их с отдельным контекстом. Имена `harness-*` принадлежат установщику; остальные команды, настройки провайдеров и разрешения сохраняются. Дополнительно устанавливается `harness-review-flash` на Flash для одного подготовленного MR; очередь запускается через `/review mr` в основной сессии. Повторная установка идемпотентна.

В сессиях DeepSeek агентов `build`, `plan` и `general` плагин передаёт инструкции автоматического делегирования. Для новой задачи выбирается один Pro-подагент брифа либо плана. Основная сессия сохраняет принятый план в `.opencode/plans/<task-id>.md` с уникальным именем задачи и отмечает выполненные пункты; явный путь пользователя имеет приоритет. После завершения задачи и проверок агент удаляет только её временный план. Незавершённый или заблокированный план сохраняется, при Handoff передаётся его точный путь; пользовательские планы и файлы других задач остаются. Хранение и удаление выполняет модель по инструкции, отдельного сборщика файлов нет. Выполнение готового плана не запускает Pro повторно; новое планирование требуется при изменении требований или обнаружении несостоятельности плана. Для `/review mr` основная сессия координирует очередь и запускает отдельного подагента на каждый MR с фиксированными SHA: `harness-review-flash` для доказуемо локальных изменений без рисков, иначе `harness-review` на Pro. Количество строк не влияет на выбор. При обнаружении риска Flash возвращает `needs_pro`, координатор запускает Pro с теми же SHA и собранными доказательствами. Оба исполнителя проходят полный чеклист; правила и ограничения описаны в [mr-delegation.md](../skills/review/reference/mr-delegation.md). Остальные режимы review сохраняют отдельный вызов Pro. Выбор момента делегирования и краткого содержания задачи выполняет модель по инструкции; это не детерминированный классификатор текста. Нативная конфигурация фиксирует модель подагента, а команды дают явный способ запуска. `ask` сохраняет запрет делегирования.

Pro получает только переданное задание, ограничения, область diff и необходимые пути; историю родительской сессии нативный вызов команды не переносит. Подагентам запрещены `edit`, вложенные подагенты и MCP-замены TokenSave. Запрет записи через shell и другие инструменты задан инструкцией, а не универсальной технической блокировкой. Нативный тест с локальным провайдером проверяет модель каждого специалиста и отсутствие контрольной строки родительской истории во входе Pro.

Ручной `/handoff` генерирует сводку на Flash; автоматическая компактация сохраняет модель сессии. Для DeepSeek модель продолжения выбирается по финальному маркеру `HARNESS-ROUTE: progress=advancing|stalled next=done|concrete|investigate`: Pro — при `progress=stalled` и `next!=done`, иначе Flash. Неизвестная причина при наличии прогресса не включает Pro. Маркер удаляется из `HANDOFF.md` и продолжения. Исходная сессия Pro остаётся на Pro; явный `--route=pro|flash` переопределяет выбор, отсутствие маркера оставляет Flash. Исходная сессия сохраняется. Если пользователь вручную выбрал Pro, ручной Handoff временно использует Flash для сводки и восстанавливает исходную модель даже при ошибке генерации. Продолжение получает сводку без старой истории. Планирование Pro автоматически перед каждым переносом не повторяется.

После двух последовательных циклов гипотеза → проверка без новых фактов или сужения поиска Flash должна завершить шаг сводкой проверенных гипотез, результатов и оставшейся неопределённости с финальным маркером `HARNESS-ROUTE: progress=stalled next=investigate`. Оценку прогресса делает модель по инструкции. Плагин обрабатывает `session.execution.succeeded` и вызывает тот же Handoff с `--route=pro` для основной сессии Flash агентов `build`, `plan` и `general` в текущем проекте. Ошибочные и прерванные шаги, завершённая работа и ожидание пользователя, разрешений или внешней зависимости не запускают переход. Нативный тест с локальным провайдером проверяет автоматическое создание и запуск продолжения Pro.

DeepSeek [кэширует совпадающие префиксы автоматически](https://api-docs.deepseek.com/guides/kv_cache/), без гарантии попадания в кэш. Управляемый TTL не документирован; [Responses API](https://api-docs.deepseek.com/guides/responses_api/) не поддерживает `prompt_cache_retention`, `prompt_cache_key` и `previous_response_id`. Подмена этих параметров не устраняет оплату. Такой маршрут уменьшает повторную обработку длинной истории на Pro, но запрос планирования, review, сводка Flash и чтение файлов остаются платными. Вызов подагента может включать несколько запросов API для инструментов: один запуск планирования не означает один тарифицируемый запрос. Реальную стоимость нужно оценивать по usage провайдера; гарантировать отсутствие дополнительных расходов нельзя.

Проверки: `opencode debug config --standalone`, `opencode mcp list --standalone`, `opencode debug agents --standalone`. В OpenCode v2 список MCP в отдельном сервере до инициализации проектной location может быть пустым. Проверяйте доступность вызовом инструмента из сессии нужного проекта; наличие конфигурации само по себе не подтверждает выполнение плагина или доступность MCP.

Агент `ask` восстановлен из истории `origin/main` перед коммитом `844226d`. Исходник — `opencode/agent/ask.md`; установщик подключает его в `<config>/agents/ask.md`. Выберите `ask` через Tab или запустите `opencode run --agent ask 'вопрос'`. Он отвечает и показывает готовый код в чате. Нативные разрешения запрещают редактирование файлов, делегирование и MCP-замены TokenSave. Shell-команды разрешены для исследования и проверок; запрет изменять через них файлы задан инструкцией агенту, без технической блокировки. Playwright MCP доступен для просмотра сайтов; чувствительные действия требуют подтверждения по `rules/core.md`. Старое исключение для подагента `commit` удалено в соответствии с режимом без изменений.

При диагностике проверяйте не только `opencode mcp list`, но и разрешения выбранного агента в `opencode debug agents`. Запрет `playwright_*: deny` скрывает инструменты браузера даже при подключённом сервере. После изменения агента выполните `opencode reload` и проверьте реальный вызов из `ask`. Инструменты MCP находятся через нативный поиск каталога OpenCode по пространству `playwright`; отсутствие инструмента в исходном контексте ещё не означает отсутствие MCP. Успешный вызов браузера не подтверждает вход в Cloudflare: это проверяется отдельно в нужной вкладке.
