# harness — что это и зачем

Обзор подхода. Как раскатать и проверить — `README.md`, устройство хуков —
`ai-hooks/README.md`, смысловой поиск — `ragsave/README.md`.

## Коротко

harness — **надстройка над агентом**, а не новый агент. Модель остаётся той
же (Claude Code или OpenCode), меняется среда, в которой она работает:

- что она знает с первой секунды сессии (правила);
- какие знания она подгружает по ходу и когда (скиллы);
- чем она ищет код и сколько текста при этом попадает в окно (индексы
  tokensave и ragsave);
- что ей не дадут сделать, даже если она забудет правило (хуки);
- как измеряется цена её работы (журналы и отчёты по транскриптам).

Всё это лежит в одном репозитории и раскатывается симлинками в `~/.claude`,
`~/.config/opencode`, `~/.ai-hooks`: правка здесь сразу меняет поведение
всех сессий на машине.

## Какую проблему решает

Агент «из коробки» на реальном проекте ведёт себя предсказуемо плохо:

| Симптом | Почему это дорого |
| --- | --- |
| Читает файлы целиком, чтобы найти одну функцию | Окно забивается кодом, который не нужен для задачи |
| Ищет `grep`-ом по имени, не видит неявных связей | Правит функцию и ломает её потребителей: событие, ключ кеша, cron |
| Держит в голове все правила сразу или забывает их | Длинный системный промпт размывает внимание; короткий — правило теряется |
| Правит SKILL.md или коммитит «по памяти», без ревью | Ошибки уходят в push, `Co-Authored-By` в сообщении нарушает политику |
| Задаёт вопрос текстом в конце ответа | Вопрос висит, пока человек его не заметит |
| Работает в одной сессии до упора | Каждый ход перечитывает весь накопленный контекст |
| Запускает субагентов на «исследование» | Субагент стартует с холодным контекстом и перечитывает то же самое — токены дважды |

Главное наблюдение, на котором построен проект, — из замеров по транскриптам
(`ai-hooks/README.md`, «Стоимость контекста»):

> За 30 дней чтение кеша контекста дало ~63% суммы, генерация — ~10%.
> Цену хода определяет не сложность вопроса и не модель, а **объём
> накопленного контекста, умноженный на число шагов**.

Отсюда два следствия, на которых держится всё остальное:

1. **Меньше токенов = дешевле.** Каждый лишний килобайт в окне оплачивается
   на каждом следующем шаге.
2. **Меньше токенов = точнее.** Модель, у которой в окне только нужный код и
   только правила текущей области, реже путается, чем модель, утопленная в
   целых файлах и справочниках на все случаи.

## Из чего состоит

```
                 ┌────────────────────────────────────────────┐
  старт сессии → │ ПРАВИЛА: rules/core.md + CLAUDE.md/AGENTS.md│  всегда в окне, ~3k токенов
                 │ + описания скиллов (по 2 предложения)       │
                 └────────────────────────────────────────────┘
                                   │ задача попала в область
                                   ▼
                 ┌────────────────────────────────────────────┐
                 │ СКИЛЛЫ: skills/<имя>/SKILL.md              │  тело грузится по требованию
                 └────────────────────────────────────────────┘
                                   │ нужен код / контекст
                                   ▼
                 ┌────────────────────────────────────────────┐
                 │ ИНДЕКСЫ (MCP): tokensave — граф кода       │  отдают фрагмент, а не файл
                 │                ragsave  — смысловой поиск  │
                 └────────────────────────────────────────────┘
                                   │ любое действие
                                   ▼
                 ┌────────────────────────────────────────────┐
                 │ ХУКИ: ai-hooks/                            │  проверяют, режут, считают
                 │ гарды · роутеры · счётчик контекста · учёт │
                 └────────────────────────────────────────────┘
```

| Слой | Где | Роль |
| --- | --- | --- |
| Правила | `rules/core.md` (общие), `claude/CLAUDE.md`, `opencode/AGENTS.md` | Гейты поведения и маршрутизация: какой инструмент на какой вопрос, какой скилл в какой момент |
| Скиллы | `skills/` | Знание по областям: NestJS, React, Next.js, тесты, ревью, git, SEO, копирайтинг, передача сессии |
| Индексы | `tokensave` (сторонний бинарь), `ragsave/` (свой MCP-сервер) | Поиск кода по структуре и по смыслу без чтения файлов целиком |
| Хуки | `ai-hooks/` | Превращают правила, которые модель забывает, в проверки; экономят контекст; ведут журнал |
| Конфиги | `claude/settings.json`, `opencode/opencode.json`, `mcp/servers.json` | Регистрация хуков, прав и MCP-серверов для обоих агентов |
| Окружение | `shell/`, `git/`, `install.sh` | Раскатка на новой машине одной командой |

Логика хуков одна на оба агента (`ai-hooks/*-core.mjs`), а `ai-hooks/claude/` и
`ai-hooks/opencode/` — тонкие адаптеры под формат каждого.

## Токены: куда они уходят и как их экономят

### Стартовая цена

Ещё до первого ответа сессия стоит в среднем ~25–33k токенов, тяжёлая — до
44k (замер `bin/start-cost.mjs`, цифры — в «Что показывают замеры»). В
тяжёлом случае ≈28k — системный промпт Claude Code со схемами встроенных инструментов,
остальное — схемы MCP, список скиллов, правила, память. Подвластны пользователю
≈8k, и они урезаны:

- выключены синхронизация скиллов и плагинов claude.ai, коннекторы и
  инструмент Artifact — их описания больше не грузятся в каждую сессию;
- правила — **указатели, а не справочники**: ужатие проектного `CLAUDE.md` с 24k
  до 2k символов сняло 14k со старта;
- инструменты tokensave грузятся частично: остальные — отложенные, по
  `ToolSearch`, когда понадобятся.

### Рост по ходу сессии

| Мера | Механизм | Что экономит |
| --- | --- | --- |
| Чтение через индекс | `read-router` запрещает `Read` файла, который есть в индексе tokensave, и отсылает к `tokensave_body` / `tokensave_read` с диапазоном строк | Вместо файла на 15k токенов — функция на 400 |
| Ограничитель вывода | `output-clip` оборачивает шумные команды (`npm`, `tsc`, `docker`, `find`…): в окно — голова и хвост, середина — в файл, путь называется | Логи сборки и тестов не заливают окно; код возврата сохраняется |
| Отсечка вставок | `paste-guard` блокирует промпт длиннее 40k символов | Одна вставленная выгрузка БД открывала сессию сразу на 200k |
| Карта связей по требованию | `links-context` подключает домен карты неявных связей только при **правке** файла из его `paths:`, один раз за сессию | Сессия без правок карту не оплачивает |
| Без субагентов | Инструмент `Agent` запрещён правами | Субагент перечитывал то, что основная сессия уже знала |
| Счётчик контекста | `context-meter` (между ходами) и `context-step` (посреди хода) | См. ниже |

### Пороги и передача сессии

Занятость окна считается по `usage` последнего хода. Пороги в токенах:

| Порог | Что агенту говорят |
| --- | --- |
| `SOFT` 90k | Закрыть текущий шаг, новый не начинать |
| `HAND` 150k | Довести шаг и закончить ход передачей по скиллу `handoff` |
| `HARD` 220k | Новую работу не начинать, задачу сузить |

Передача — это снимок задачи (что сделано, что осталось, какие решения
приняты), который переносится в чистую сессию. `/clear` дешевеет ровно
настолько, насколько не страшно его нажать: если состояние задачи сохранено,
новая сессия продолжает с ~25k вместо 200k.

Тексты порогов короткие (одна строка и до трёх команд): длинные объяснения
модель принимала за инъекцию в выводе инструмента и отказывалась им следовать.

### Как проверяется, что экономия реальна

Решения принимаются по замерам, а не по ощущениям:

- `bin/usage-report.mjs` (`/usage`) — токены и стоимость по моделям, проектам,
  инструментам; какие файлы и инструменты реально легли в окно;
- `bin/tool-share.mjs` — доля tokensave/ragsave против `Read`/`grep` до и после
  изменения. Пример: правила текстом не удержали долю tokensave — она упала с
  81% до 27%, — поэтому появился `read-router`, который делает это проверкой;
- `bin/start-cost.mjs` — из чего складывается стартовая цена.

## Получение нужного контекста

Задача агента — найти **ровно тот код, который нужен**, и не притащить
остальное. Для этого два индекса, которые не конкурируют:

| | tokensave | ragsave |
| --- | --- | --- |
| Что это | Граф кода: символы, вызовы, импорты | Гибридный поиск: векторы (локальная модель `multilingual-e5-large`) + полнотекстовый BM25 |
| На какой вопрос отвечает | «Где `UserService.create`», «кто его вызывает», «что сломается» | «Как настроен деплой», «где переменные для почты» |
| По каким файлам | Код | Всё текстовое: документация, yaml/json, миграции, SQL, CI |
| Что отдаёт | Тело функции, сигнатуру, диапазон строк, список вызывающих | Фрагменты с `файл:строка` |

Маршрут выбора записан в `rules/core.md` таблицей «вопрос → инструмент», а
детали — в скилле `tokensave-routing`. Пустой ответ означает неверную
догадку об имени, а не отсутствие кода: лестница `rag_search` → grep → чтение
вероятного файла.

### Что граф не видит: карта неявных связей

Граф знает прямые вызовы, но не знает, что строка `'order.paid'` в одном модуле
и подписчик на неё в другом связаны, или что миграция и сущность должны
меняться вместе. Такие связи записываются в карту проекта (`docs/links/` или
`.claude/links/`), разбитую на домены. Перед коммитом каждый изменённый символ
проходит через `tokensave_impact`/`callers` **и** карту — каждое попадание
заканчивается как «не затронуто», «исправлено» или «покрыто тестом». Зелёные
тесты на изменённой функции ничего не говорят о её потребителях.

Карту заводит `/impact-map`, кандидатов в неё подбирает
`bin/seed-impact-map.mjs`, актуальность сверяет `bin/check-impact-map.mjs`.

## Скиллы: знание в нужный момент

### Почему не положить всё в системный промпт

Правила для NestJS, React, тестов, ревью, git и SEO вместе — десятки тысяч
токенов. Если загрузить их все в начале:

- каждая сессия платит за всё, даже если правит одну опечатку в README;
- правило ревью безопасности соседствует с правилом стилей формы — модель
  хуже понимает, какое из них относится к текущему действию;
- к моменту, когда правило нужно, оно лежит далеко в начале окна.

### Как устроено

1. **На старте в окне только описания** — по два предложения на скилл: что
   покрывает и когда грузить (~2k токенов на всю коллекцию).
2. **Таблица триггеров** в `rules/core.md` связывает действие со скиллом:
   «трогаешь контроллер или DTO → `nestjs-backend`», «перед коммитом →
   `review-standards`, `review-security`, `git-flow`».
3. **Тело скилла грузится до первого действия в его области**, один раз за
   сессию. Правило оказывается в окне рядом с действием, к которому
   относится.
4. **Общие куски** (`skills/shared/*.md`) не имеют описания и ничего не стоят
   на старте — на них ссылаются скиллы.

### Как гарантируется, что скилл действительно загружен

Правило «загрузи скилл до действия» модель забывает чаще прочих. Поэтому на
двух областях, где цена забывания видна сразу, оно стало проверкой
(`skill-gate`):

| Действие | Без чего запрещено |
| --- | --- |
| Правка `SKILL.md`, `CLAUDE.md`, `AGENTS.md`, `rules/*.md`, команд, агентов | `skill-authoring` |
| `git commit` в любой форме | `review-standards`, `review-security`, `git-flow` |

`skill-track` отмечает загруженные скиллы по сессии; после `/clear` сессия
новая, и скилл надо загрузить снова — как и в контексте модели.

### Как пишется скилл, чтобы он помогал, а не мешал

Скилл — справочная карточка, а не статья (`skills/skill-authoring`): читает
его модель, которая уже знает предметную область. Каждая строка — правило,
которое она иначе нарушила бы, или факт, который она не выведет сама.
25–130 строк, императив, одна причина — только там, где правило неочевидно.
Новый скилл появляется только под наблюдённую ошибку: нет ошибки — нет скилла.

## Хуки: правило, которое нельзя забыть

Текстовое правило — просьба. Хук — проверка. В harness правило переезжает в
хук, когда по транскриптам видно, что модель его нарушает:

| Хук | Что держит |
| --- | --- |
| `security-guard` | Секреты, доступ к БД и проду, отправка наружу: `deny` насмерть или `ask` человеку |
| `bash-router` (shell-гард) | Shell запускает команды, а не читает и правит файлы: `cat`/`sed -i`/`> файл` идут мимо проверок и диффа |
| `read-router` | Файл из индекса читается через tokensave |
| `skill-gate` | Скилл загружен до правки инструкций и до коммита; сообщение коммита с пустой строкой после заголовка |
| `question-guard` | Вопрос пользователю — через меню, а не прозой в конце ответа |
| `ask-guard` | Режим «только ответ в чате»: правки запрещены |
| `project-bootstrap` | Сообщает, чего не хватает проекту: `CLAUDE.md`, CI, husky, карты связей |
| `ragsave-sync` | Фоновая синхронизация смыслового индекса на старте и конце хода |

Все решения хуков (`deny`, `ask`, `block`, падения, медленные вызовы) пишутся
в `ai-hooks/logs/hooks.jsonl`: по нему восстанавливается «запрет → что модель
попробовала дальше». Упавший хук не блокирует работу (fail-open), но
оставляет след.

## Как выглядит задача целиком

1. Старт сессии: в окне ~25–33k — системный промпт, правила-указатели, описания
   скиллов. `project-bootstrap` называет пропуски проекта.
2. Задача про сервис NestJS → грузится `nestjs-backend`.
3. Поиск: `tokensave_search` / `tokensave_context` находят символ, `body`
   отдаёт функцию, `rag_search` — конфиг и миграцию. Файлы целиком не читаются.
4. Правка через `tokensave_str_replace`; если файл попал в домен карты связей,
   домен подключается в контекст.
5. Тесты — через ограничитель вывода: в окне итог, а не 3000 строк лога.
6. Impact-проход: `tokensave_impact` + карта связей.
7. `review-standards` → `review-security` → `git-flow` → коммит и push.
   Без загруженных скиллов `skill-gate` коммит не пропустит.
8. Окно дошло до `HAND` → шаг доводится, `handoff` переносит задачу в чистую
   сессию.

## Что показывают замеры

Снято 6 октября 2026 скриптами из `ai-hooks/bin/` по транскриптам и журналам
этой машины: Claude Code, проекты `web_groza`, `dual-vpn`, `trader`,
`tunel-vpn`, `harness` и другие. Повторить:

```bash
node ai-hooks/bin/usage-report.mjs --days 60   # токены и цена по моделям, проектам, инструментам
node ai-hooks/bin/tool-share.mjs               # доля индекса и контекст на ход, до/после границы
node ai-hooks/bin/start-cost.mjs               # стартовая цена сессии по слоям
jq -r '[.hook,.decision]|join(" ")' ai-hooks/logs/hooks.jsonl | sort | uniq -c
```

### Куда уходят деньги — 60 дней, 193 сессии, ≈$331

| | Токены | Доля цены |
| --- | --- | --- |
| Чтение контекста из кеша | 413.5M | ≈45% |
| Запись контекста в кеш | 17.6M | ≈36% |
| Генерация ответа | 3.4M | ≈19% |

На каждый сгенерированный токен модель перечитывает ~120 токенов контекста.
**Контекст — это ~81% цены**, ответ — меньше пятой части. Поэтому любая мера
против лишнего текста в окне окупается сильнее, чем выбор модели подешевле.

Доли посчитаны по прайсу из `ai-hooks/claude/usage-log.mjs` (`PRICES`) — это
оценка по ценам API, а не счёт подписки.

### Стартовая цена — 331 сессия

| Выборка | Средний старт |
| --- | --- |
| Все сессии | ≈32.6k токенов |
| Последние 81 сессия (Claude Code 2.1.289+) | ≈25.4k токенов |

Из этого правила (`core.md`, `CLAUDE.md`, память) — ≈2.7k, описания всех
скиллов — ≈2.5k. Полные тексты скиллов в старт не входят: они грузятся по
требованию.

### Контекст на ход — 339 сессий

`tool-share.mjs` делит сессии границей — коммит `a0ec8f2` (22.09.2026), после
которого правила выбора инструментов переписаны, а позже добавлены
`read-router`, `output-clip`, пороги контекста:

| | Сессий | Ходов | Средний контекст на ход | Доля индекса в поиске |
| --- | --- | --- | --- | --- |
| До | 94 | 9 278 | 111k | 70% |
| После | 245 | 21 806 | **86k (−23%)** | 62% |

Каждый ход стал в среднем на 25k токенов легче — при цене «размер ×
шаги» это почти четверть счёта за чтение контекста. Доля индекса при этом упала:
текстовое правило «ищи через tokensave» модель соблюдает нестабильно, и именно
это показало, что правило нужно превратить в проверку (`read-router`).
Сравнение не лабораторное: задачи и модели в двух периодах разные.

### Что поймали хуки — 22.09–06.10.2026, 940 решений

| Хук | Срабатываний | Что было бы без него |
| --- | --- | --- |
| `read-router` | 252 запрета в 112 сессиях | 252 чтения файла целиком вместо функции или диапазона |
| `bash-router` | 223 запрета | Чтение и правка файлов через `cat`/`sed` мимо диффа и проверок |
| `security-guard` | 123 запрета, 285 вопросов человеку | 97 рекурсивных удалений, 17 чтений `.env`, 2 чтения `~/.git-credentials` |
| `skill-gate` | 27 запретов | Коммиты без ревью: не загружены `review-standards` (11), `review-security` (12), `git-flow` (8); 2 сообщения без пустой строки |
| `question-guard` | 26 блоков | 26 вопросов прозой в конце ответа, которые ждали бы, пока их заметят |

До `skill-gate` модель в 8 из 119 коммитов склеивала заголовок с телом и
чинила это `--amend` и force-push уже после публикации.

## Почему ответ точнее, чем без harness

Прямого A/B по качеству ответов нет — есть механизмы и косвенные замеры
выше. Механизмы такие.

**1. Внимание модели конечно.** Окно в 200k токенов не значит, что модель
одинаково хорошо видит всё, что в нём лежит. Чем больше в окне постороннего
кода, логов и правил чужих областей, тем выше шанс, что она опрётся на
нерелевантный фрагмент или пропустит нужный в середине. Функция на 400 токенов
вместо файла на 15k и итог сборки вместо 3000 строк лога — это не только
экономия, это меньше шума, в котором теряется сигнал.

**2. Правило лежит рядом с действием.** Скилл ревью безопасности грузится
перед коммитом, а не в начале сессии в общем пакете из десятка областей. Когда
модель принимает решение, нужное правило — недавний и единственный текст по
теме, а не одна строка из тридцати конкурирующих справочников.

**3. Код берётся из кода, а не из памяти.** `tokensave_body` отдаёт настоящую
сигнатуру и тело, `tokensave_callers` — настоящих потребителей. Модель меньше
додумывает API, имена полей и поведение, потому что ей дешевле посмотреть, чем
угадать.

**4. Неявные связи проверяются, а не предполагаются.** Impact-проход и карта
связей заставляют закрыть каждого потребителя изменённой функции: событие,
ключ кеша, миграцию. Без этого «тесты зелёные» означает лишь, что сама функция
работает, — сломанный соседний модуль всплывает уже после push.

**5. Забытое правило не проходит.** Модель забывает правила — это видно по
цифрам: 27 коммитов без ревью, 26 вопросов прозой, 252 попытки прочитать файл
целиком за две недели. Хук превращает каждый такой случай в немедленную
поправку, и результат не зависит от того, вспомнила ли модель правило на этом
ходу.

**6. Короткая сессия думает яснее длинной.** Пороги и `handoff` не дают нити
дорасти до 300k, где ранние решения и детали задачи уже размыты. Новая сессия
со снимком задачи начинает с ~25k и с точной формулировкой того, что
осталось.

**7. Скилл содержит только то, где модель ошибается.** Правило
`skill-authoring` — «нет наблюдённой ошибки — нет скилла» — держит скиллы
короткими. Модель не тратит внимание на пересказ того, что знает сама, и
видит только поправки к своему поведению.

## Итог

harness не делает модель умнее — он убирает из её окна всё лишнее и
подкладывает нужное в момент, когда оно нужно:

- **контекст** — фрагмент кода вместо файла, итог команды вместо лога;
- **знания** — скилл области при входе в неё, а не все скиллы сразу;
- **дисциплина** — проверка хуком там, где текстового правила не хватило;
- **цена** — пороги и передача сессии вместо одной бесконечной нити.

Каждое из этих решений обосновано замером по реальным транскриптам и
пересматривается следующим замером.
