# ~/.ai-hooks — общие хуки Claude Code и OpenCode

Гарды безопасности, ask mode, гейт скиллов, shell-гард, учёт и уборка.
Логика в `*-core.mjs`, адаптеры под формат каждого агента — в `claude/` и
`opencode/`.

Shell-гард держит одно правило: **shell запускает команды, файлы читает
`Read`, правит `Edit`/`Write`.** `cat`/`head`, `sed -i`, `> файл`, `tee`,
`node -e`/`python -c` с путём, heredoc в интерпретатор — то же действие мимо
проверок агента и без диффа в чате. Критерий — файл существует на диске:
проект, индекс и расширение роли не играют.

Разбор нарочно грубый: распознаются формы, а не синтаксис shell. Всё
нераспознанное проходит — `git diff`, `tsc`, `eslint`, `grep`/`rg` над теми же
путями работают. Grep по коду в индексе судит родной хук tokensave
(`hook-pre-tool-use`, matcher `Agent|Grep|Bash|Glob`); он же печатает, как себя
снять — `TOKENSAVE_DISABLE_GREP_HOOK=1`. Эту переменную в любом месте команды
и `git grep` внутри индексированного проекта (родной хук его не видит) гард
запрещает: отказ окончательный. `node <файл>` без `-e`/`-p`/heredoc — запуск скрипта, а не
чтение: иначе команды этого README блокировались бы. Команду на сегменты режет
`shell-core.mjs`, общий с гардом безопасности: `a & cat файл`, `$(cat файл)`,
`( … )`, `then cat`, `sudo -u root cat`, `xargs cat` видны как `cat`; тело
heredoc (`node <<EOF … EOF`) остаётся в сегменте интерпретатора
(`keepHeredoc`). Тот же гард висит на `mcp__ide__executeCode`: канал мимо
Bash, результат тот же.

tokensave и ragsave — MCP-серверы, а не гарды: агент зовёт их по своему выбору.
tokensave синхронизирует индекс сам (при подключении и перед вызовами), у
ragsave своей синхронизации нет — её делает `bin/ragsave-sync.sh` на
SessionStart и Stop (в OpenCode — `session.created` и `session.idle`).

Фоновые задачи молчаливы по устройству — уходят в `setsid`, их вывод оседает в
логе конкретного проекта. Чтобы упавшая индексация не оставалась незамеченной,
все четыре скрипта при ненулевом коде возврата дописывают запись в
`logs/errors.log`: время, источник, проект, код и хвост лога задачи. Это первое
место, куда стоит смотреть при жалобе на баг tokensave или ragsave.

Две записи туда не попадают, иначе журнал перестаёт быть сигналом. Первая —
`another sync is already in progress`: конкурентный sync это штатный пропуск
(параллельная сессия или git-хук уже держат замок), следующий проход подхватит
изменения. У ragsave пропуск узнаётся по коду 3, без строки в логе: каждый
запуск `ragsave-sync.sh` пишет в свой `sync.log.<pid>`, при коде 3 удаляет его, иначе
переносит в `sync.log` — раньше `>sync.log` обнулял лог идущего синка ещё до
проверки замка. Держатель замка по отметке `.ragsave/.sync.again`, которую
оставил пришедший, проходит ещё раз, так что правки хода не ждут следующего
Stop. Вторая — вывод спиннеров:
ANSI-последовательности и повторы `copying DB` чистятся, строки обрезаются до 200 символов. До этой фильтрации из
25 записей журнала реальными отказами были 3.

`ragsave-sync.sh` обслуживает смысловой индекс (`~/.rag-mcp`, см. его README):
уходит в фон на SessionStart и Stop, замок держит не скрипт, а сам `ragsave` — один и тот же
для хука, терминала и MCP. tokensave такого скрипта не требует: его сервер
синхронизирует граф сам, а `post-commit` git-хук tokensave зовёт `sync`.

`claude/links-context.mjs` — не гард, а контекст: карта неявных связей проекта
(`docs/links/` или `.claude/links/`, формат — `skills/shared/impact-map.md`) разбита
на файлы доменов, и каждый открывается frontmatter `paths:` в формате `.claude/rules`.
Родное path-scoped правило тут не работает: зонд показал, что оно срабатывает на
встроенном `Read` и молчит на `tokensave_read`. Хук висит на `PostToolUse` инструментов чтения и правки
(`Read|Edit|Write` и `tokensave_read|body|str_replace|multi_str_replace`), берёт путь
из `tool_input` (`file_path` / `file` / `path`; для `tokensave_body` — поле `file` из
ответа), сверяет с глобами через `path.matchesGlob` и добавляет тело совпавшего
файла домена как `additionalContext`. Один домен — один раз на сессию (метки
`~/.claude/state/links-context/`, ключ — сессия + проект + домен): второй показ —
тот же текст в контексте дважды. `INDEX.md` хук не подключает — его читает impact-проход
и OpenCode, у которого такого хука нет. Глоб без файлов (переехавший каталог) ловит
`bin/check-impact-map.mjs`, иначе домен молча перестал бы подключаться.

Адаптеры не содержат логики — только перевод формата конкретного агента в вызов
`guard-core`. Меняешь правило — меняешь `guard-core.mjs`, оба агента получают его сразу.

## Индексация только ручная

`ragsave-sync.sh` поддерживает **уже существующий** индекс. Первичный
`tokensave init` / `ragsave init` не запускает никто, кроме человека, и каталоги
`.tokensave` / `.ragsave` хуки не создают.

Автоматический init нельзя было отменить и он не отличал проект от контейнера:
`~/main` — сам git-репозиторий с вложенными проектами, и сессия, открытая в нём,
запускала индексацию всего дерева (`tokensave init | ~/main | exit=101` в `errors.log`). Пустой каталог `.tokensave`, созданный «на всякий
случай», при этом выглядел для остальных хуков как инициализированный проект.

## Выбор проекта для MCP

`bin/mcp-serve.sh` — обёртка, через которую в `~/.claude.json` объявлены оба
сервера. Она ищет индекс от каталога сессии вверх и передаёт найденный корень
явно (`serve -p <root>`), а без индекса не поднимает сервер вовсе.

Без неё сервер наследовал cwd процесса `claude` и, запущенный вне проекта, брал
**первый по алфавиту** из соседних инициализированных проектов — молча. Сессия в
`~/main/web_groza` получала граф `~/main/dual-vpn` — молча. Отсутствующий
инструмент видно сразу, чужой граф — никогда, поэтому «не запускать» здесь
лучше, чем «запустить наугад».

## Журнал решений

`logs/hooks.jsonl` — след конкретной сессии. errors.log знает, где упала
фоновая задача, а сами запреты (ask-guard, security-guard, bash-router), их
причины и время работы хука не писались никуда, и `/doctor` не мог
восстановить последовательность «запрет → что модель попробовала дальше →
снова запрет».

Строка на **решение**, не на вызов: `sid`, `hook`, `tool`, `target`,
`decision`, `reason` (обрезана до 160), `ms` — время от старта процесса хука.
Решения: `deny`, `ask`, `block` (ход не завершён — `question-guard`), `slow`
(разрешённый вызов, хук работал дольше 800 мс — медленный хук ощущается как
«спотыкание» не хуже запрещающего) и `crash`.
Разрешённые вызовы не пишутся — в тихой сессии файл не растёт.

`crash` — падение самого хука. Раньше исключение внутри обработчика роняло
процесс с ненулевым кодом: Claude показывал «hook error», шёл дальше, а причина
не оставалась нигде. Теперь `hook-io` ловит его на уровне процесса, пишет
строку в hooks.jsonl и стек в errors.log (`exit=crash`, тот же формат, что у
`log-error.sh`) и выходит с кодом 0 — вызов пропускается, как при любом другом
отказе инфраструктуры (fail-open). Контекст (сессия, хук, инструмент) ставит
`readInput`.

Тесты, запускающие настоящие хук-скрипты, импортируют `test/env-isolate.mjs`
первым: он уводит в temp `AI_HOOKS_HOOKS_LOG`, `AI_HOOKS_LOG_DIR` и
`AI_HOOKS_STATE_DIR`, иначе каждый прогон test-security дописывал бы сотню
выдуманных запретов в общий журнал, а метки — в состояние живых сессий.
Он же ставит `TMPDIR` в свой каталог и удаляет его при выходе — песочницы
теста и его дочерних процессов не копятся в `/tmp`; так его импортирует и
любой тест с `mkdtemp`. Тест, которому состояние нужно под своим `HOME`,
передаёт `AI_HOOKS_STATE_DIR: ''`.
Ротация — `bin/cleanup.mjs`, хвост 2000 строк.

## Гейт скиллов

CLAUDE.md велит грузить скилл до первого действия в его области, и это
правило модель забывает чаще прочих: правит SKILL.md по памяти, коммитит без
ревью. `claude/skill-gate.mjs` (PreToolUse `Edit|Write|MultiEdit|NotebookEdit|Bash`)
делает из правила запрет для двух областей, где цена забывания видна сразу:

| Действие | Требует |
| --- | --- |
| правка `skills/*/SKILL.md`, `skills/*/reference/*.md`, `commands/*.md`, `agent/*.md`, `rules/*.md` (под `.claude/`, `.opencode/`, `opencode/` или `harness/`), любого `CLAUDE.md` или `AGENTS.md` | `skill-authoring` |
| `git … commit` в любом сегменте команды (пайп, `&&`, фоновый `&`, `$(…)`, `-C`, за `sudo`/`env X=1`) | `review-standards`, `review-security`, `git-flow` |

`git-flow` в списке не ради стиля: без него в сообщение попадает
`Co-Authored-By`, а это политика компании. Список гейтов — `GATES` в
`skill-core.mjs`; разбор shell общий с security-guard (`shell-core.mjs`).

Метку «загружен» ставит `claude/skill-track.mjs` — на PreToolUse инструмента
`Skill` и на `UserPromptSubmit` с промптом `/name` (пользовательский вызов
через `Skill` не проходит). Состояние — `~/.claude/state/skills-loaded.json`,
по `session_id`: после `/clear` сессия новая, и скилл в ней снова не загружен,
как и в контексте модели. Запрет пишется в hooks.jsonl (`hook: skill-gate`),
текст называет недостающий скилл и `Skill(<name>)`; выключатель в тексте не
упоминается намеренно. Отключить: `touch ~/.claude/state/skill-gate.off`
(cleanup уберёт через 7 дней) или `AI_HOOKS_SKILL_GATE_OFF=1`.

Тесты: `test/test-skill-gate.mjs`.

## Вопрос только через меню

`core.md` велит задавать вопрос пользователю через `AskUserQuestion`: вопрос
текстом в конце ответа висит, пока человек его не заметит. Правило модель
нарушала, проверки не было. `claude/question-guard.mjs` на `Stop` читает
последний ход транскрипта (от последней реплики человека) и возвращает
`{"decision":"block","reason":…}`, если последняя строка прозы кончается `?`
или хвост ответа — список из двух и больше вариантов после вопроса. Модель
получает причину и продолжает ход: задаёт вопрос меню или переписывает
риторическую концовку.

Не судятся: `?` в код-блоке, инлайн-коде и цитате `>`; ход, где уже был
`AskUserQuestion` или `ExitPlanMode`; повторный Stop того же хода
(`stop_hook_active: true`) — не больше одного блока на ход, иначе петля.
Текст ответа берётся из `last_assistant_message` входа, если он есть, —
последняя запись транскрипта может не успеть на диск. Блок пишется в
hooks.jsonl (`decision: block`). Логика — `question-core.mjs`, тесты —
`test/test-question-guard.mjs`.

## Ask mode

Режим «только ответ в чате»: правки файлов, write-инструменты tokensave,
изменяющие shell-команды, публикация артефактов и субагенты, умеющие писать, —
запрещены; чтение, поиск и тесты доступны. Встроенные режимы Claude Code
(manual / accept edits / plan / auto) зашиты в бинарь и конфигом не расширяются,
поэтому режим собран из хуков: `ask-guard.mjs` запрещает, `ask-reminder.mjs`
объясняет правило до первого отказа, `statusline.mjs` показывает состояние.

Состояние — файл на сессию (`sess-<session_id>`) в `~/.claude/state/ask-mode/`,
плюс `default` для всех новых сессий (значение задаёт
`bin/ask-mode.mjs default on|off`). Хуки и statusline берут `session_id` из
входного JSON, `ask-mode.mjs` — из `CLAUDE_CODE_SESSION_ID`. Новая сессия и
`/clear` дают новый id — режим по умолчанию; `resume`/`compact` сохраняют id и
режим. Две сессии в одном каталоге режим не делят. Без сессии (запуск из
терминала) ключ — корень проекта (`dir-<hash>`). Переключение:
`/ask`, `/ask-off` или `bin/ask-mode.mjs on|off|toggle|reset|default on|off`.
Команда проходит, только если сама запускает `ask-mode.mjs`: имя скрипта в
соседнем сегменте (`rm -rf src; echo ask-mode.mjs`) режим не обходит.

Разбор shell общий с security-guard (`shell-core.mjs`): запись ловится и за
`&`, `( … )`, `$(…)`, `sudo -u …`, в `bash -c "…"`/`eval`, `find -delete`/`-exec`,
`git -C dir commit`, `git branch -D`/`-m`/создании ветки, `prettier --write`,
`eslint --fix` (и через `npx`/`pnpm exec`).

## Субагентов нет

Ролевые агенты (`scout`, `backend-dev`, `frontend-dev`, `tester`, `reviewer`,
`security-reviewer`, `devops`), скилл `/team` и хук `subagent-context.mjs` на
`SubagentStart` удалены 10 сентября 2026: пользователь работает только
скиллами, а субагент стартует с холодным контекстом и перечитывает то, что
основная сессия уже знает, — токены уходили дважды. Ревью, которое делали
`reviewer` и `security-reviewer`, теперь выполняет сама сессия по скиллам
`review-standards` и `review-security` перед каждым коммитом.

CLAUDE.md запрещает любой вызов `Agent`, включая встроенные `Explore`, `Plan`
и `general-purpose`. Ask mode подстраховывает: `ask-guard.mjs` пропускает в
режиме только встроенные читающие типы из `READONLY_AGENTS` в `ask-core.mjs`
(`Explore`, `Plan`, `claude-code-guide`, `statusline-setup`), остальные —
запрет. `opencode run` считается изменяющей командой (`MUTATING_SUBCMDS`).

checkout»: индексы `.tokensave/` и `.ragsave/` лежат в каталоге проекта, и
новый каталог означал бы полную переиндексацию.

## Гард безопасности

`security-core.mjs` отвечает на вопрос «что будет, если это выполнить», и
поэтому устроен иначе, чем гарды tokensave. Там запрет означает «возьми
другой инструмент», и предохранитель пропускает повторный вызов, чтобы не
загнать агента в тупик. Здесь запрет означает «у действия есть последствия»,
и предохранителя нет: «со второй попытки можно» отменяло бы сам запрет.

Два уровня ответа. `deny` — там, где законной причины нет, а безопасная
альтернатива есть: чтение `.env` и производных (`.env.local`, `.env-prod`),
`.envrc`, ключей (`id_ed25519_github`, `master.key`), сертификатов,
`secrets.yaml`, Terraform state и `*.tfvars`, `/proc/*/environ`, `auth.json`, `.git-credentials`, `.pgpass`, учётных данных CLI
(`~/.claude/.credentials.json`, `~/.aws/credentials`, `~/.docker/config.json`,
`~/.kube/config`, `gh/hosts.yml`, `glab-cli/config.yml`), в том числе через
shell (`cat`, `dd if=`, `perl`, `hexdump`, `iconv` …), `scp`, перенаправление
ввода (`… < .env`) и `Grep` — по `path` и по `glob` (`.env*`). Тот же список держит
ragsave, чтобы секрет не попал в индекс (`ragsave/config.py`). Секрет,
попавший в контекст, остаётся в транскрипте навсегда и уезжает в каждый
следующий запрос, поэтому альтернатива — `.env.example` или значение от
пользователя. `.env.example`, `.env.template` и прочие примеры не секреты и
проходят.

`ask` — там, где операция законная, но нужен человек: `pg_dump` и другие
выгрузки, клиент БД на неместном хосте (`-h`, слитный `-hHOST`, `--host`, URL,
строка подключения `host=…`, `PGHOST=`/`MYSQL_HOST=` в любом месте команды),
`git push` в main/dev/prod (в том числе `HEAD:refs/heads/main` и любым из нескольких refspec), force push (`-f`,
`-uf`, `+refspec`), удаление ветки (`--delete`, `:ветка`), `--all`/`--mirror`,
шаблон `*`, push без явной ветки, в `HEAD`/`@` или в ветку из `$…`/`` `…` ``,
`docker compose` с прод-конфигом, `kubectl apply`, команды через
`ssh`, `curl`/`wget` с телом запроса (`-d`, слитный `-dfoo`, `-F`, `-T`,
`--post-*`, `--body-*`) на внешний хост, с URL или без схемы.
В `permissionDecision` это отдельное значение, и оно возвращает подтверждение
даже в auto mode — в этом вся ценность: там всё остальное проходит само.

Ещё один `ask` — правка самого харнеса (Edit/Write/MultiEdit/NotebookEdit в
`~/harness`, в том числе через симлинки `~/.ai-hooks`, `~/.claude/…`) из
сессии, корень которой (`CLAUDE_PROJECT_DIR`) вне харнеса. `Edit(~/harness/**)`
в `permissions.allow` пускает такую правку молча, а она применяется сразу:
prompt injection из файлов чужого проекта снимала бы гарды одной правкой
`security-core.mjs`. Из сессии в `~/harness` правки идут как раньше.

В OpenCode тот же гард вызывается из плагина (`opencode/tokensave-guard.mjs`,
`tool.execute.before`) раньше гардов tokensave: `read`, `grep`, `edit`,
`write`, `multiedit`, `bash` переводятся в `Read`/`Grep`/`Edit`/`Bash` ядра,
`patch` — в `Edit` на каждый файл из `patchText`, остальные
(MCP `tokensave_tokensave_read` и однотипные) — в `mcp__opencode__<имя>`, корень
сессии — `directory`. Блокируется только `deny`: спросить человека из плагина нельзя,
поэтому `ask` там держат правила `permission.bash` в `opencode.json` и агентах
(у `@commit` — запреты force push, `+refspec`, удаления ветки, `--mirror`,
`--all`). Шаблоны OpenCode не разбирают хосты и refspec, поэтому спрашивают
грубее ядра (`psql* -h*` и на localhost, `git push*` целиком); что каждое
`ask` ядра накрыто шаблоном, проверяет `test-opencode-plugin.mjs` — новое
`ask`-правило добавляется туда примером вместе с шаблоном. Ошибка самого гарда вызов не блокирует — fail-open, как в адаптере
Claude.

Гард закрывает и путь мимо `Read`: MCP-инструменты, отдающие содержимое файла
(`tokensave_read`, `tokensave_body` и однотипные), проверяются тем же
правилом — иначе он запирал бы парадную дверь при открытом чёрном ходе.
Так же — браузер Playwright: `browser_navigate` на `file://` и файлы
`browser_file_upload`. Read, Edit и MCP-читатели судят и по реальному пути:
симлинк `config.txt` → `.env` запрещён, как сам `.env`. Рекурсивный `grep`
(`-r`, `-R`, склейки вроде `-rn`, `--recursive`) без `--include` запрещён: он
читает каждый файл дерева, `.env` тоже, а имени секрета в команде нет; отказ
сразу называет `tokensave_search` для индексированного проекта, чтобы поиск
символа не шёл через два запрета подряд (наш и родной хук tokensave).
Отдельный случай — команды, печатающие окружение целиком (`env`, `printenv`,
`docker compose config`): секрет приходит там не из файла, а из вывода, и по
имени файла его не поймать.

Обёртки разбираются рекурсивно, иначе гард ловил бы `cat .env`, но пропускал
всё, чем эту же команду пишут естественно: `bash -c "…"`, удалённую команду
`ssh`, тело `find -exec`, команду внутри контейнера (`exec`, `run`), `eval`.
Разбор общий — `shell-core.mjs`: сегменты режутся и по фоновому `&`, по
скобкам `( … )`, `{ …; }`; тело `$(…)`, `` `…` ``, `<(…)` проверяется как
отдельная команда; ключевые слова (`then`, `do`, `!`) и обёртки с опциями
(`sudo -u root`, `env -i`, `xargs -0`, `timeout 5s`, `nice`) пропускаются до
настоящей команды, у `ssh`, `docker exec`/`run`, `kubectl exec` — опции с
аргументом до цели (`-p 2222`, `-u root`, `-n prod`). Окружение целиком
печатают и `sudo env`, `printenv` без имени, `set`, `export -p`, `declare -x`.
Пути ищутся разрезом строки, а не regex-поиском: команда в 200 КБ разбирается
за доли секунды. Отдельно закрыт git:
`git show HEAD:.env` и `git cat-file` читают секрет из истории, даже когда
файла нет в рабочей копии. Читающая команда из пайпа ищет путь по всей строке —
в `echo .env | xargs cat` путь и читатель лежат в разных сегментах.

Чего гард не умеет принципиально: он судит о команде, а не о её выводе. `git
diff`, показывающий строку с ключом, или чужой скрипт, печатающий токен,
пройдут — от этого защищает не гард, а то, что секреты лежат в gitignored
файлах.

Разбор грубый, как и в гардах tokensave: распознаются формы команд, а не
синтаксис shell, и нераспознанное проходит. Задача не поймать любой обход, а
закрыть удобный путь и поставить человека там, где цена ошибки высока.

## Автоматизация проекта и учёт

`claude/project-bootstrap.mjs` на `SessionStart` (`startup|clear`) смотрит
корень репозитория и сообщает в контекст, чего нет: CLAUDE.md проекта,
`.env.example` при наличии `.env`, husky, CI и dependabot для GitHub-remote,
`.gitlab-ci.yml` для GitLab, карты неявных связей (`docs/links/` или
`.claude/links/`) в проекте с индексом tokensave или ragsave. Что делать —
скилл `hooks-guards`: каждый пропуск предлагается одной строкой в первом
ответе (для карты — `/impact-map`), сам агент ничего не создаёт.
Про husky/CI/карту хук напоминает раз в неделю на проект (метки в
`~/.claude/state/bootstrap/`), про CLAUDE.md — пока файла нет.

Отсутствие бывает осознанным. `<проект>/.claude/bootstrap-ignore` перечисляет
по строке на пункт (`claude-md`, `husky`, `ci`, `dependabot`, `env-example`,
`impact-map`, `#` — комментарий), и о перечисленном хук молчит. Без этого
намеренно удалённый файл давал бы напоминание на каждом старте сессии — тот
самый шум, против которого недельный дроссель и вводился.

`claude/usage-log.mjs` на `Stop` читает транскрипт сессии и транскрипты
субагентов рядом с ним, считает токены по моделям (одно сообщение — один
`message.id`, хотя строк в транскрипте несколько), вызовы инструментов и
оценку стоимости по прайсу API (`PRICES` внутри), и пишет одну запись на
сессию в `logs/usage.jsonl` (upsert). Там же `context_sources`: размер каждого
`tool_result` в символах, привязанный к `tool_use` по id и просуммированный по
инструменту, для `Read` — ещё и по файлу. Это то, что реально легло в окно
контекста, а не число вызовов; отдельный PostToolUse-хук для этого не нужен —
данные уже в транскрипте. `bin/usage-report.mjs` — отчёт за период по
моделям, проектам, инструментам и источникам контекста (топ-10 инструментов
по объёму результатов и топ-10 файлов через `Read`, ~токены = символы / 4);
в Claude Code — `/usage`. Цены — оценка, не счёт подписки: нужны пропорции,
а не бухгалтерия.

Частично это дублирует встроенный `tokensave cost` (он же ходит по сессиям
локальных агентов и знает долю попаданий в кэш), поэтому `/usage` показывает
оба: `tokensave cost` — за деньги и кэш по всем агентам, свой отчёт — за
разбивку по проектам, вызовам инструментов и субагентам, которой у tokensave
нет. Цифры расходятся: прайс-таблицы разные, своя лежит в `PRICES`.

## Стоимость контекста

Замеры за 30 дней: у Opus 5 вышло 61 МТокен чтения кеша против 204 КТокенов
вывода — чтение контекста дало около 63% суммы, генерация около 10%. Значит
цену хода определяет не сложность вопроса и не выбранная модель, а объём
накопленного контекста, который перечитывается целиком на каждом ходу. Одна
длинная сессия по инфраструктуре стоила дороже, чем все рабочие сессии месяца
вместе.

Замер за следующую неделю уточнил механику: 66.6 МТокена чтения кеша на ~540
вызовов инструментов. Значит счёт — это произведение «размер контекста × число
шагов», и каждый лишний вызов стоит всего накопленного контекста целиком.
Отсюда три меры ниже.

Автоматического предупреждения о цене контекста здесь нет: хук `context-cost`
удалён по просьбе пользователя как шум. Замер остаётся в силе, но вывод из него
делает человек, а не подсказка на каждом двенадцатом ходу. Отчёт по факту —
`bin/usage-report.mjs`.

**Передача между сессиями.** `/clear` дешевеет ровно настолько, насколько не
страшно его нажать. Занятость окна считается по `usage` последнего хода основной
нити (`context-core.mjs`), пороги заданы в токенах: `SOFT` 90k — закрыть шаг и
не начинать новый, `HAND` 150k — собрать передачу по скиллу `handoff` (вопросы
и коммит незакоммиченного шага — через `AskUserQuestion` до снимка, сам агент
коммит не решает; есть план task-brief — отметить в нём шаги;
снимок записать в файл, который назовёт plan mode, и выйти через
`ExitPlanMode` — с планом и без), `HARD` 220k —
собрать немедленно.

Меряется в двух точках. `claude/context-meter.mjs` на `UserPromptSubmit` — на
границе ходов. `claude/context-step.mjs` на `PostToolUse` — посреди хода, между
вызовами инструментов: автономный ход на сотню вызовов проходит все три порога,
ни разу не вернувшись к пользователю, и без этой точки порогов для него не
существует (замерено: сессия выросла с 27k до 318k на одном промпте, и первое
предупреждение прозвучало на 303k). Посреди хода требование другое: не бросать
ответ на половине, а довести текущий шаг до коммита с пушем и отдать новой
сессии следующий; обрыв посредине оставил бы грязное дерево и половину шага,
которую нечем описать в блоке.

Порог звучит один раз (леджер объявлений у обеих точек общий), старший звучит
поверх младшего, а `HARD` повторяется: на границе ходов — каждый ход, посреди
хода — каждые `STEP_REPEAT` (20k) роста, иначе напоминание стоило бы дороже
того, что экономит.

Сессия, где ещё ничего не изменено, на `SOFT` блока не собирает: передавать
нечего, новая сессия прочла бы то же самое и упёрлась в тот же порог — это
петля, а не передача. Вместо этого там просят сузить чтение и дойти до
результата. От `HAND` такая сессия — чаще обсуждение, чем подготовка к правке
(по транскриптам 4 из 28 сессий, дошедших до `SOFT`, не сделали ни одной правки
и всё равно доехали до 200k+): коммитить ей нечего, поэтому блок просят из
выводов — что выяснено, что отвергнуто, что осталось — без перечня прочитанного;
на `HARD` вдобавок — сказать пользователю, что задачу нужно сузить. «Работа»
— это правка файла или коммит, видные хуку по имени инструмента; чтение и
поиск ею не считаются намеренно.

Файлов передача не создаёт и `/clear` не зовёт: пользователь либо переносит блок
в новую сессию руками (история старой остаётся в `claude --resume <id>`), либо
просто очищает контекст. Индикатор в статусной строке показывает те же пороги
цветом — в контекст оттуда ничего не уходит.

Пороги ловят рост, но не старт. Стартовая цена сессии — `cache_creation` первой
записи ассистента, по слоям её считает `bin/start-cost.mjs` — раскладывается так (trader, opus, короткий промпт, 44k):
≈28k системный промпт Claude Code со схемами встроенных инструментов, ≈4k
схемы поднятых tokensave-инструментов, 5k список скиллов (свои 2k, скиллы
claude.ai 1.3k, встроенные 1.8k), 2.7k инструкции (`core.md`, `CLAUDE.md`,
память), 1.2k имена отложенных инструментов, 0.8k инструкции MCP. Из этого
пользователю подвластны ≈8k: в `claude/settings.json` выключены синхронизация
скиллов и плагинов claude.ai, коннекторы claude.ai и инструмент Artifact —
документы делаются из приложения, не из CLI. Проектный `CLAUDE.md` — указатель,
не справочник: его ужатие с 24k до 2k символов сняло 14k со старта.

Единственное, что пороги не поймали бы и что стоит дороже всей базы, — дамп в
промпте: три сессии из 35 открылись сразу на 200k, потому что под блок передачи
вставили выгрузку БД на 250k символов. `claude/paste-guard.mjs` на
`UserPromptSubmit` отвечает `decision: block` на промпт длиннее
`AI_HOOKS_PASTE_LIMIT` (40k символов; нормальная передача — до 6k): вставка не
попадает в окно, пользователь видит причину — данные в файл, путь в промпт.

**Ограничитель вывода.** `claude/output-clip.mjs` на `PreToolUse(Bash)` заменяет
команду на `bin/clip-output.sh <метка> -- '<команда>'`, если она из шумных
(`npm`, `tsc`, `docker`, `cargo`, `make`, `find` и подобные). Скрипт печатает
голову и хвост, а середину складывает в файл, путь к которому называет:
понадобилась — `grep`, а не чтение целиком.

Что намеренно не оборачивается:

- `git log|diff|show|blame` и `npm audit` — ими верифицируют, и середина там и
  есть содержание: обрезанный `git diff main...HEAD` показал бы начало и конец,
  а правка посреди ветки уехала бы в push непросмотренной;
- всё составное — конвейеры, редиректы, подстановки, `&&`, вторая строка, фон.
  `cd client && npm ci` не оборачивается отдельно: `cd` в дочернем `bash -c` не
  переживает вызов, и следующая команда сессии ушла бы не в тот каталог;
- следящие режимы (`--watch`, `-f`) и всё, что может спросить ввод: `npm
  publish`, `npx create-*`, `sudo`/`su`, `docker … prune` и подобные. Вывод
  уходит в файл, приглашение не видно, команда виснет — а для `sudo` это ещё и
  пароль, набранный вслепую в невидимый диалог.

Метка перед `--` — имя команды и подкоманда. Она не исполняется, а нужна затем,
что правила разрешений сопоставляются по префиксу строки: без неё все обёрнутые
команды выглядели бы одинаково, и «больше не спрашивать» для `npm test` молча
разрешило бы `npm run deploy` и `make`.

Код возврата сохраняется исходный — иначе `npm test` с упавшими тестами вернул
бы ноль, и агент отчитался бы о зелёном прогоне. По той же причине размер файла
ограничивается после выполнения, а не конвейером с `head -c`: конвейер закрыл бы
поток, и статус стал бы 141 (SIGPIPE) вместо настоящего.

Полные выводы живут в `~/.claude/state/clip-output/` и убираются через двое
суток (`bin/cleanup.mjs`): вывод сборки или compose-конфига может содержать
секрет, и здесь он лежал бы дольше самого транскрипта.

Совета «возьми модель дешевле» там намеренно нет. Кеш привязан к модели:
переключение сбрасывает его, и на выросшем контексте возврат стоит дороже
разовой экономии. Менять модель имеет смысл на старте сессии, а не внутри неё —
и harness это подтверждает, переключить модель хуком нельзя вовсе
(`PreModelSwitch` умеет только заблокировать чужое переключение).

## Уборка

`bin/cleanup.mjs` висит на `Stop` и проходит раз в сутки (метка
`~/.claude/state/.cleanup-stamp`). Убирает то, что мертво по устройству: метки
подсказок ragsave (дроссель внутри — 15 минут, метка старше двух суток
бессмысленна), метки диагностики проектов и ask mode по сессиям (`default` не трогает), метки
подключённых доменов карты связей (`links-context`, старше двух суток), служебные
метки в корне состояния, неотправленную телеметрию
Claude Code, кеш вставок,
окружение и снимки shell завершённых сессий, планы plan mode
(`~/.claude/plans`, бриф по скиллу `task-brief`) без правок две недели —
живой план правится по ходу, отмечая сделанные шаги. Первый проход снял
160 файлов и 14 МБ.

Журнал расходов не удаляется, а сворачивается: записи старше 90 дней
складываются в одну строку на месяц с суммами по моделям. Файл перестаёт расти
линейно по числу сессий, а картина за год остаётся. Журнал отказов обрезается
хвостом при превышении 2 МБ.

Транскрипты, историю правок и индексы уборщик не трогает: первыми управляет сам
Claude Code через `cleanupPeriodDays`, на второй держится отмена правок, у
третьих собственные GC, а внешнее удаление стоит переиндексации.

Отдельный случай — кеш эмбеддингов ragsave. Его чистка по возрасту и количеству
не спасала от разового всплеска: если корневой репозиторий однажды затянул
соседние каталоги, кеш свежий и по числу версий далеко до лимита, а на диске
сотни мегабайт навсегда. Добавлен предел по отношению кеша к живому индексу
(`gc_cache` в `~/.rag-mcp/ragsave/store.py`). На `~/main` это дало 163 МБ →
19 МБ. Весь кеш, однако, у большого проекта не доходил до порога: у web_groza
(9 529 живых фрагментов) 4 432 мёртвые версии занимали 122 МБ. Теперь предел
считает только мёртвые версии — их хеша нет среди живых файлов: перешли число
фрагментов в индексе (минимум 2 000) — режутся до половины, чтобы `VACUUM` не
шёл на каждом синке.

## Откат

Каталог под git (`logs/` исключён; рантайм-состояние живёт не здесь, а в
`~/.claude/state/`) — это единственная страховка при правке хуков: сломанный
гард не падает с ошибкой, а меняет поведение всех сессий молча, и замечаешь это
через день. Правка ядра — отдельным коммитом, после неё прогон тестов; красный
тест — `git revert`, а не «дочиню».

всегда даёт `allow`. Тест ask mode пишет состояние во временный каталог и
глобальное умолчание не меняет.

seed-impact-map, `fake-indexer.mjs` записывает вызовы фоновых синков.
