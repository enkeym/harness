# handoff

Record the objective, constraints, decisions, completed changes, test results and next concrete step in the managed task plan. Include branch, affected paths and log locations, not copied source or full logs. Record applicable skills and instruction paths so the receiving agent can load them. Carry existing authorization, latest user steering and unresolved questions forward. Include a short remaining plan and pending processes or uncertain writes; never replay them blindly.

The task plan file (`.opencode/plans/<task-id>.md`) is the single canonical source of the objective, decisions, checkpoint and remaining steps. Handoff, summary and context cache reference its path instead of copying its content. Keep the checkpoint in the plan: phase, current unfinished step, authorization, verified contracts with paths/symbols, missing facts and next edit or check. Update it after a completed step or changed decision; do not regenerate the whole plan.

Carry only unfinished steps into the remaining plan; never repeat completed phases as next steps, never copy the executed part of the checklist, and do not tell the receiver to re-read the whole plan or reload already-loaded skills to rediscover progress.

For manual invocation, the harness plugin compacts the current session and reuses the bound plan and evidence cache; it creates no separate note or new session. An explicit user plan path remains user-owned and is not pruned. If no managed plan exists, the plugin generates a summary in at most 3000 characters and persists it as the plan objective before compacting. For native compaction, the plan path and cache reference are added to the summary request; do not create another file. Automatic maintenance and continuation are authorized by the installed context policy; do not request confirmation for them. Use supported client compaction only, never a shell worker or invented subagent; do not delete history, switch models outside an explicitly configured routing policy, or manufacture token measurements.

After compaction, read the plan path and continue the next authorized action without waiting for another user message. Keep completed and blocked tasks stopped. OpenCode `/handoff` compacts the same session, keeps model and variant, and appends a plan reference; the TUI does not open another session. Client controls and thresholds are documented in [context automation](../../docs/context-automation.md).

An adequate authorized implementation plan resumes in implementation. Treat the plan checkpoint as authoritative. Recover missing applicable instructions, verify the working tree and read the current edit target and only its necessary dependencies; do not reread the entire plan or rebuild project context. Reuse recorded decisions and contracts unless changed requirements or contradictory evidence invalidate them. Name a specific missing fact before expanding retrieval. If the same step survives another compaction without progress, narrow it to the smallest coherent edit and check, or report its concrete blocker; do not repeat the same preparation cycle or make an unrelated edit merely to show activity. Progress can be a verified decision or resolved blocker during analysis, not only a code change.

When `context_cache` is available, save only needed already-observed ranges before compaction; the tool stores evidence, not a checkpoint. During native compaction, retain its reference without tools. On resume, restore selected ranges first; never load the entire evidence cache. The tool validates source hashes; stale evidence requires a scoped MCP read. Call `action=complete` only after the whole task and checks finish, not after each answer.

When a separate summary is still required, rebuild it from current state in at most 3000 characters; replace the previous snapshot instead of appending. Keep only decisions, affected contracts and verification the remaining work needs. Use exact paths/symbols, absolute dates and the next executable action. Read the named ranges on resume; load applicable skills whose instructions are missing; do not reload all project files or rerun unchanged successful checks. For native compaction, preserve the same essentials and point to the plan.
