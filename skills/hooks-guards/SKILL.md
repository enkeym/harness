# hooks-guards

Harness installs only SessionStart/Stop handlers for background RAG sync of existing indexes. MCP search routing is guidance; do not install a blocking search guard. For a refusal, distinguish native sandbox/approval policy from user or project hooks and inline definitions. Inspect only the relevant configuration and handler; check current official hook documentation before changing its protocol. Keep native sandbox and approvals active; never retry a denied action through another tool. Request native escalation only when supported and required. A previous user authorization remains valid within its scope. Hook trust is reviewed through /hooks, not granted by editing trust state. Do not promise a confirmation dialog from a hook.
