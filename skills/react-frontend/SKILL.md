# React frontend — конвенции

Проект главнее списка: сначала посмотри соседние компоненты и повтори их
способ (`tokensave_context` с `path_include` на клиент).

## Компоненты

- Функциональные компоненты, именованные экспорты, один компонент — один
  файл; файл называется как компонент.
- Props — интерфейс `XProps` рядом с компонентом; `children` типизирован явно.
- Компонент показывает, хук считает: логика загрузки, преобразования и
  побочных эффектов — в кастомном хуке `useX`, компонент остаётся разметкой.
- Не плоди состояние: то, что выводится из props или другого state,
  вычисляется, а не хранится. `useEffect` для синхронизации с внешним миром,
  не для «пересчёта state».

## Данные и состояние

- Запросы к API — тем способом, который уже есть в проекте (клиент API, хук
  данных, стор). Новый способ рядом со старым не заводится.
- Состояние держи максимально близко к месту использования; в глобальное
  выносится только то, что реально нужно в нескольких деревьях.
- Состояния загрузки, ошибки и пустого списка обрабатываются всегда, не
  только «happy path».

## Формы

- Существующая библиотека форм проекта и её схема валидации; сообщения об
  ошибках рядом с полем; кнопка отправки блокируется на время запроса.

## Стили

- Только токены и переменные проекта: цвета, отступы, шрифты, радиусы,
  z-index. Значение в px или hex в компоненте — сигнал, что нужен токен;
  нет токена — скажи об этом в отчёте, а не хардкодь.
- Повторяй существующий способ стилизации (CSS-модули, styled, utility
  классы) — не смешивай.

## Доступность и UX

- Интерактивные элементы — настоящие `button`/`a`/`input`, не `div` с
  `onClick`; у иконок-кнопок `aria-label`; фокус видим.
- Тексты для пользователя — в том месте, где проект хранит строки
  (i18n или константы), не в JSX-литералах, если проект так делает.

## Тесты

- Testing Library: запросы по роли и тексту, как видит пользователь;
  `userEvent`, не `fireEvent`, где важна последовательность событий.
- Мокается граница (API-клиент, таймеры), не внутренние хуки компонента.

## Типы

- `any` запрещён. Ответы API типизированы интерфейсами, общими с сервером,
  если проект их шарит.
