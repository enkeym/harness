# Working rules

- Reply in Russian; briefly state the next action before commands or edits. Preserve unrelated user changes.
- Before coding, load project rules and inspect scripts, types and configs. Search the module, shared code and installed packages; read the closest implementation and callers. Reuse or extend it; a second use requires one shared implementation and updated callers within module boundaries. No speculative abstractions.
- Never add or rewrite code/documentation comments, including JSDoc, TODOs and suppression directives, unless explicitly requested by the user; project permission and examples do not lift this ban. Preserve unrelated comments; explain in chat or external docs.
- Reuse constants, enums, config and UI tokens; environment-dependent values belong in the config layer, not new local constants. Use precise types or narrowed unknown, never TypeScript any; DTOs for service inputs, interfaces for responses.
- Follow tokensave-routing for indexed search/read and shell fallbacks. Before judging code, check index freshness (tokensave_status, stale_commits); Stop sync can lag one commit.
- Discover only needed MCP schemas through the current client's discovery mechanism before the first call. Reuse schemas; never dump catalogs or repeated server descriptions.
- Read the intended target immediately before editing; use the available patch/edit tool and never edit the same file concurrently. After every write, re-read changes, validate JSON where applicable and explicitly report verification.
- Batch independent reads/searches; reuse passing checks until inputs change and poll sensibly. For noisy commands use bash ~/.ai-hooks/bin/brief-output.sh <command> [args...], inspect errors and retain complete review evidence; never wrap interactive commands.
- Keep notes as paths, decisions and next actions; logs in files. Compact current state without accumulated snapshots. No subagents unless requested.
- Load each relevant rule/skill once while its contents remain in the current context; reload only missing or changed instructions and schemas. For harness-context see ~/.config/harness/repo/docs/context-automation.md; a persistent digest alone does not prove retained content.
- Complete authorized edits, local commands, tests and commits autonomously; infer routine choices and ask for information only when blocked.
- Ask before push, publication, deployment, data deletion, irreversible Git operations and secret changes. Reuse explicit authorization within its named scope; routine edits and local checks need no confirmation.
- Secrets never enter Git: ignore their file or store values in ~/.config/harness/env and reference them by name.
- Before handoff, fix duplicated logic, hardcoded values, added comments and unused scaffolding in the diff. Briefly report reuse evidence (searched scope → reused symbol, or why new code was needed); run focused checks, full suites/coverage only when project rules or impact require them.

## Browser and internet
- Use web search and page retrieval for internet research and public documentation. Use Playwright MCP for browser interaction, authenticated account/dashboard inspection (including Cloudflare DNS), UI reproduction and browser checks, or when explicitly requested. Follow an explicitly requested source/tool. Discover browser tools directly, not through plugins or project indexes.
- With Playwright, start with browser_tabs list and work in an already open target tab of the Playwright group ("Playwright" or "Playwright · <client>"): select it by current title/URL and take browser_snapshot. Only when no group tab matches, open the supplied URL in a new tab; preserve other tabs. If the user names a page that is open but absent from the group, ask them to drag it into the group instead of guessing a tab.
- The extension page (chrome-extension://<id>/connect.html, title "Welcome") holds the connection: never navigate, close or use it as the target. When it is the only tab, open a new tab for the supplied URL and work there.
- After navigation/tab changes, use fresh snapshots and refs; refresh stale refs before retrying, never guess or reuse another tab's refs. Reading/searching needs no confirmation; sensitive actions follow the rule above. If required browser access is unavailable, report the limitation; public search cannot verify private account settings. Never infer private settings from project logs.

## Skills and hooks
Before each task and when its scope changes, select skills by intent and affected stack from the current client's skill catalog and briefly name the selected skills. Read applicable SKILL.md only when its contents are missing from the current context or have changed, before its workflow begins. Do not reread unchanged instructions still present in context. No slash command is required. A plan, catalog entry or remembered summary does not replace reading the instructions. Combine workflow and stack skills; load newly applicable skills before continuing and restore missing instructions after compaction or session transfer. Keep explicitly requested workflows within scope.
- Task analysis, planning, solution design and evaluation of improvements: task-brief; harness installation/skills/MCP/index health: doctor; hook refusals/trust/sandbox: hooks-guards; context/tool overhead: optimize; navigation: tokensave-routing; skills/instruction files: skill-authoring. General code or architecture analysis does not invoke doctor unless harness health is in scope.
- Before analyzing, diagnosing, writing, reviewing or testing affected code: NestJS server → nestjs-backend; React UI → react-frontend; Next.js App Router → also nextjs-app; Python → python. Reviews: review; quality/impact: review-standards; security: review-security; load both review checks before every commit.
- Tests: test-conventions; requested coverage: also test-coverage; explicitly requested browser QA: test-browser. Branches/commits/MR/Jira: git-flow; explicit commit-and-push: commit (push still needs authorization).
- Requested implicit-links map creation/seeding: impact-map; implementation/review uses existing docs/links through shared/impact-map.md for affected contracts, without seeding. Russian website copy: copywriting; requested SEO: seo; session transfer: handoff.
- After skill changes, validate source names, references, installed links and the active client's available-skills catalog. Use that client's installer check; another client's successful check does not cover its installation.
Shared skills apply across models and clients. Resolve skill paths, tools, session controls and approval capabilities from the active environment; do not assume another client's commands or data formats. Skills are instructions, not hook handlers; shared/ holds references. SessionStart delivers skill routing instructions; UserPromptSubmit delivers only the Skill reminder below. The agent reads applicable SKILL.md as needed under the rule above. SessionStart/Stop maintain existing indexes and warm RAG at startup. Check hook trust and execution through the active client's supported diagnostics: file presence or successful manual execution does not prove lifecycle execution.
