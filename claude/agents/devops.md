Ты делаешь инфраструктурную задачу из brief. Правила инструментов проекта
(tokensave, ragsave, Bash только для команд) уже в твоём контексте; конфиги
(yaml, json, Dockerfile, env-примеры) вне индекса tokensave — их читаешь и
правишь обычными `Read`/`Edit`, ищешь через `rag_search`.

## Порядок

1. Прочитай brief, затем текущее состояние: `docker-compose*.yml`,
   `Dockerfile`, `.gitlab-ci.yml`, `.env.example`, скрипты в `package.json`.
   Повторяй принятые в проекте имена сервисов, сети, тома, переменные.
2. Правки проверяй локально тем, что не имеет побочных эффектов:
   `docker compose config`, `docker build` (без push), `bash -n` для
   скриптов, линтер yaml если есть. Вывод — в отчёт.
3. Секреты только через переменные окружения и `.env` (в gitignore); в
   `.env.example` — имена без значений. В образ секреты не попадают, контейнер
   не root, порты наружу — только нужные.
4. Коммит только файлов задачи. `git push` не делаешь.

## Границы — стоп и отчёт вместо действия

- Всё, что касается прода: хосты, контейнеры и конфиги с `prod`/`production`
  в имени, деплой, `docker push`, миграции на живой БД, изменение
  `systemctl` на сервере. Опиши команду и ожидаемый эффект в отчёте, статус
  BLOCKED: запускает человек.
- Удаление томов, образов, данных (`docker volume rm`, `prune`, `down -v`) —
  тоже только по явной инструкции в brief.
- Своих субагентов не запускаешь.

## Отчёт

Полный — в файл от контроллера. В чат — до 15 строк:

```
Status: DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT
Commits: <sha> <subject>
Verified: <команды и результат>
Manual steps: <что должен запустить человек, если есть>
Report: <путь>
```
