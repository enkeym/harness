## 3. Сверка тарифов DeepSeek (root-cause расхождения native ≈ 2× recompute)

### Факты (проверено по бэкапам конфига)
- `cost`-блоки моделей в `~/.config/opencode/opencode.jsonc` **впервые появляются
  в бэкапе `opencode.jsonc.bak-1793798338623` от 2026-11-04 16:18 MSK** (ранее —
  бэкапы Nov 1–2 — блоков `cost` нет). Рядом есть «ручной» бэкап
  `opencode.jsonc.bak-manual-1793817079` (~Nov 4 21:31) — правка внесена вручную.
- Значения `cost` во всех последующих бэкапах (Nov 5–6) **идентичны и корректны**:

| модель | input | output | cache.read | соответствие |
|---|---|---|---|---|
| `deepseek-v4-pro` (peak) | 1.32 | 3.96 | 0.044 | = `deepseekTokenRates` peak |
| `deepseek-v4-pro-offpeak` | 0.66 | 1.98 | 0.022 | = off-peak (½) |
| `deepseek-flash` (peak) | 0.30 | 1.20 | 0.006 | = peak |
| `deepseek-flash-offpeak` | 0.15 | 0.60 | 0.003 | = off-peak (½) |

- `opencode/cost-policy.mjs` `deepseekTokenRates` и `peakWindowsUTC: [[1,4],[6,10]]`
  соответствуют официальному DeepSeek (пик 01:00–04:00 и 06:00–10:00 UTC пн–пт,
  off-peak = ½). Ошибок в ставках кода нет.

### Вывод (ключевой)
Расхождение «native ≈ 2× recompute» — **не ошибка биллинга harness**.
Причина: OpenCode вычисляет native-оценку стоимости по **статическому** `cost`-блоку
модели. Модель по умолчанию `deepseek/deepseek-flash` несёт пиковую ставку, поэтому
native-оценка всегда по пику (во все часы), тогда как harness-пересчёт
(`recomputedUSD` в `cost-policy.mjs`) корректно учитывает пик/off-peak по времени.
Отсюда 136 предупреждений `pricing-window-mismatch` в отчёте 2026-11-07: native
(статический пик) расходится с часами off-peak, где работает harness-пересчёт.

Уточнение для окончательного отчёта: зафиксированный по session-записям переход
native off-peak→peak ~2026-11-03 (а не 04) объясняется тем, что до внесения
`cost`-блоков native брался из каталога моделей (models.dev), а после ручного
внесения блоков — из них. Точный момент смены источника — Nov 3–4.

## 4. Семантика `compaction.buffer` (OpenCode 2.2.6)

Проверено по официальной документации OpenCode v2:
- `compaction.keep.tokens = 20000` — примерный объём недавнего разговора,
  сохраняемый рядом с саммари (больше = больше деталей, меньше места новым).
- `compaction.buffer = 30000` — токены, оставляемые свободными **ниже лимита**
  модели; больше значение = автоматическая компактификация начинается раньше.

Текущие значения (`keep.tokens: 20000`, `buffer: 30000`, `auto: true`) валидны.
Ключи v1 `reserved`/`prune` удалены (см. issue anomalnyco/opencode#49132 про
устаревшие ключи в опубликованной схеме config.json).
