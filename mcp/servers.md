# MCP

servers.json — единый список stdio-серверов.
node bin/mcp-sync.mjs регистрирует их для выбранного клиента: по умолчанию
через Codex CLI, с --opencode — в opencode.jsonc.
--check сообщает расхождения без изменений для выбранного клиента.
Поддерживаются только --codex и --opencode; --qwen, неизвестные аргументы
и одновременный выбор двух клиентов отклоняются до записи настроек.
Пути ~/ раскрываются относительно HOME; сторонние серверы не удаляются.

TokenSave работает через `ai-hooks/bin/mcp-proxy.mjs --compact`: общий текст
маршрутизации убирается из `initialize.instructions` (Codex добавляет его к каждому
описанию инструмента) и из описаний `tools/list`, включая дополнительные инструменты.
Схемы backend и уведомления сохраняются; правила поиска
остаются в `rules/core.md` и skill `tokensave-routing`.
Для символьных инструментов TokenSave proxy переводит `name` в `symbol` и `id`
в `node_id`; инструменты, где `name` — собственный параметр, не затрагиваются.

Playwright закреплён на `@playwright/mcp@0.0.83` и в WSL подключается к Windows
Chrome через расширение в профиле текущего пользователя. Для Codex глобальная
запись задаётся в user scope; proxy отдаёт сохранённый каталог и запускает `npx`
при первом браузерном вызове, поэтому неиспользуемый браузер не поднимает backend.
Первый браузерный вызов ждёт готовности этого процесса.
Подключение автоматическое по `PLAYWRIGHT_MCP_EXTENSION_TOKEN`: значение берётся
из `~/.config/harness/env` и передаётся клиентам ссылкой `{env:...}`.
Без токена браузерные вызовы сразу возвращают ошибку, а backend не запускается;
токен создаётся кнопкой Generate new token на странице расширения.
Группа Playwright начинается со служебной вкладки `connect.html`, которая держит
соединение; рабочие вкладки пользователь добавляет в эту группу.
При подключении переместите уже открытую вкладку в группу нужного клиента.
`browser_tabs` показывает только вкладки, доступные данному MCP-клиенту, и отмечает
выбранную как `(current)`. Чтобы агент работал в уже открытой вкладке, переместите
её в группу этого клиента; после этого он выбирает её по названию или URL.
Расширение не предоставляет агенту произвольную активную вкладку вне группы.
Повторные вызовы в подключённой вкладке не требуют нового запуска `npx`.
Proxy принимает `browser_tabs` без `action` как `list`, `browser_click` с `ref`
как `target`, `browser_evaluate` с `expression` как функцию и screenshot без
`scale` с масштабом `css`.
Создание вкладок через `browser_tabs(action=new)` отключено: подключите нужную
существующую вкладку к группе клиента и выберите её через `browser_tabs`.
Proxy запускает backend с версией MCP из каталога, уже сообщённой клиенту, даже если
клиент изначально предложил более новую.
Каталог не содержит исходников проекта или результатов браузерных вызовов.
Маршрутизация интернет-запросов и выбор вкладки описаны в `rules/core.md`.
В Codex для работы Playwright без повторных MCP-подтверждений в `~/.codex/config.toml`
задать `default_tools_approval_mode = "approve"` в `[mcp_servers.playwright]`.
Это разрешение инструментов; чувствительные действия по-прежнему требуют
авторизации по общим правилам. После изменения конфигурации начать новую сессию.
Синхронизация существующих серверов Codex использует native `config/batchWrite`,
сохраняя approval mode, enabled, timeouts и пользовательское окружение.
После смены версии обновить `servers.json`, затем выполнить
`node bin/mcp-catalog.mjs playwright`; проверить без записи — с `--check`.
Команда и аргументы должны совпадать с каталогом, иначе proxy завершится с ошибкой.

TokenSave и RAG проходят через общий proxy с прежним `mcp-serve.sh` и выбором
проекта. Ссылки на переменные окружения в env сохраняются при синхронизации;
значения из локального окружения не подставляются вместо существующих ссылок.
После синхронизации настроек переподключите MCP или начните новую сессию.

Путь Chrome и профиль не закреплены в реестре: Playwright использует настройки
текущего пользователя. В WSL синхронизация ищет `chrome.exe` в `PATH`, затем
в Windows App Paths текущего пользователя и системы и переводит путь через
`wslpath`. Явный `PLAYWRIGHT_MCP_EXECUTABLE_PATH` в env сервера имеет приоритет;
профиль можно выбрать через `PLAYWRIGHT_MCP_PROFILE_DIR_NAME`. Эти переменные
можно задать в `.env.local`; после изменения запустите синхронизацию MCP.

По умолчанию обычный текст ограничен 13000 UTF-8 bytes на результат; это не токены.
JSON text (включая JSON-строки), structuredContent, ошибки, медиа и смешанные
блоки не ограничиваются. Полный исходный MCP result сохраняется до усечения
в `$XDG_STATE_HOME/harness/context-output` (по умолчанию `~/.local/state`).
Путь и исходный размер видны в тексте и `_meta`; остальные поля сохраняются.
Каталог приватный (0700), файлы 0600. При недоступности артефакта возвращается
полный успешный ответ backend с краткой диагностикой в stderr.

Каждый proxy добавляет инструмент `harness_read_result`:

```json
{"path":"/path/from/full_result.json","offset":0,"bytes":4096}
```

Смещения и размеры заданы в UTF-8 bytes; `nextOffset` позволяет продолжить чтение.
Смещение должно попадать на границу символа. `full=true` вместо диапазона возвращает
исходный MCP result целиком и обходит ограничение вывода. Этот вызов обслуживает
сам proxy: локальный путь не обязан быть доступен клиенту. Вход ограничен приватными
артефактами proxy; произвольные файлы и symlinks не читаются.

Хранение ограничено 64 файлами/16 MiB с исключением для одного большого целого
результата. Артефакты моложе 60 секунд защищены от очистки другими proxy. Если
лимит занят свежими результатами, новый ответ передаётся целиком без усечения.
Старые файлы очищаются при сохранении следующего результата; открытый файл
остаётся читаемым при параллельной очистке.

Только перечисленные read-only TokenSave/RAG операции повторяются при явной
временной транспортной ошибке: максимум два повтора, задержки 100 и 200 мс.
Writes, смешанные и неизвестные операции не повторяются. Две одинаковые ошибки
аргументов, доступа или отсутствия файла/индекса открывают защиту на 30 секунд
для backend, проекта, инструмента и нормализованных аргументов. Ответ сохраняет
исходный класс ошибки и поясняет временное подавление. После срока допускается
один пробный вызов; успех очищает защиту. Изменение наблюдаемой базы индекса/WAL
даёт новый ключ. Неизвестные ошибки не считаются детерминированными.

Любой запрос к backend ограничен `requestTimeoutMs` (по умолчанию 120 секунд,
включая повторы). При превышении proxy возвращает ошибки всем ожидающим запросам.
В режиме каталога (`--catalog`) proxy остаётся подключённым: он завершает группу
процессов backend и запускает его заново при следующем вызове. В прямом режиме
соединение закрывается, требуется переподключение MCP. Итог операции неизвестен;
автоматического повтора после такого таймаута нет.
Отмена со стороны клиента (`notifications/cancelled`) снимает запрос с ожидания и
передаётся backend: таймаут не срабатывает, backend не перезапускается, отменённый
id остаётся без ответа, а запланированный повтор по нему не выполняется.
Закрытие backend допускает `shutdownGraceMs` (1000 мс) на EOF и столько же
на SIGTERM, после чего используется SIGKILL для собственной группы процессов
backend, включая потомков обёрток. На Windows дерево завершается через taskkill.
Временный файл атомарной записи удаляется и при ошибке записи или переименования.
`--check` сообщает о неприватных правах `.env.local` без изменения файла;
исправление прав выполняется только при синхронизации.

Общая политика находится в `ai-hooks/mcp-policy.json`. Для диагностики задайте
`HARNESS_MCP_POLICY_FILE` с путём к JSON, содержащему нужные переопределения:

```json
{"outputEnabled":false,"errorsEnabled":false,"digestsEnabled":false}
```

Поля `resultBytes`, `turnBytes`, `artifactCount`, `artifactBytes`, `artifactGraceMs`,
`retries`, `retryDelayMs`, `circuitMs`, `failureEntries`, `readEntries`,
`requestTimeoutMs`, `shutdownGraceMs` меняют лимиты.
Остальные параметры берутся из общей политики; неизвестные и неверные значения
вызывают ошибку запуска. Передавайте переменную в env MCP-сервера, если клиент
фильтрует окружение. Изменение вступает в силу при новом подключении.

Без lifecycle proxy не подставляет `if_digest` и не расходует вечный бюджет
процесса. Явный `if_digest` и принудительное чтение сохраняются. Generation и
бюджет хода предоставляет только `harness-context`; потеря состояния выключает
соответствующую оптимизацию. Подробности: [контекст](../docs/context-automation.md).

Меньше текста в истории, меньше вызовов backend и серверный prompt cache — разные
эффекты. Proxy не кеширует ответы модели и не переносит KV-кеш. Сокращение байтов
не доказывает экономию токенов, стоимости подписки или ускорение генерации.
