# MCP-серверы

Единый список — [`servers.json`](servers.json). Claude Code получает серверы из
него в `~/.claude.json` (scope user, вперемешку с историей проектов, в
репозиторий не кладётся) через `claude mcp add-json -s user`; руками там ничего
не правится.

## Команды

```bash
node bin/mcp-sync.mjs --check   # отчёт; код 1 при расхождении
node bin/mcp-sync.mjs           # привести ~/.claude.json к servers.json
```

`./install.sh` вызывает первое в `--check` и второе при раскатке.

## Формат

```json
{
  "<имя>": { "command": "<путь или бинарь>", "args": ["..."], "env": { "K": "V" } }
}
```

`~/` в `command` раскрывается в домашний каталог. Голое имя без `/`
(`foo-mcp`) ищется по PATH того, кто запускает синк: не нашлось —
сервер пропускается с ошибкой, код выхода 1. Серверы, которых нет в списке, не
удаляются — скрипт только предупреждает.

В `~/.claude.json` (вне репозитория) ложится абсолютный путь: `~/` раскрыт,
голое имя заменено найденным. После смены версии node из nvm `--check`
покажет устаревший путь, и `./install.sh` его обновит.

## Заметки

- `tokensave` и `ragsave` запускаются только через
  `~/.ai-hooks/bin/mcp-serve.sh`: он выбирает проект по каталогу сессии и не
  поднимает сервер без индекса. Голый `tokensave serve` вне проекта молча берёт
  первый по алфавиту соседний граф (см. `../ai-hooks/README.md`, «Выбор проекта
  для MCP»). Без индекса в каталоге сессии оба сервера в `mcp list` будут
  `failed` — так и задумано.
- `ragsave` подключится только после `./install.sh --venv`. `tokensave` —
  сторонний бинарь, ставится отдельно (см. `../README.md`).
- Playwright MCP в списке нет: на каждой сессии он брал бы ~70 МБ и добавлял
  имена `browser_*`. Регистрируется в проекте руками, вне его git — команды в
  `../README.md`. Синк такие записи не видит и не трогает.
- Проверка: `claude mcp list`.
