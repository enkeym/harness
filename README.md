# ~/.ai-hooks — общие гард-хуки tokensave для Claude Code и OpenCode

Единая точка истины для политики «Tokensave-First». Правило одно:

> **Файл есть в индексе tokensave (таблица `files` в `.tokensave/tokensave.db`)
> → читать и править только через tokensave. Нет в индексе → обычные
> инструменты агента, без ограничений.**

Индекс — единственный критерий. Списка «что считать исходником» нет: если
tokensave файл не проиндексировал, он его и не отдаст, а запрет без рабочей
альтернативы — тупик, из которого агент начинает искать обходные пути
(`node -e`, `jq`, heredoc). Поэтому гард молчит везде, где tokensave бессилен:
нет `.tokensave/` → нет индекса → нет запретов; новый файл не в индексе →
`Write` разрешён; json/yaml/конфиги не индексируются → `Read`/`Grep` напрямую.

`Bash` проверяется по тому же критерию. Раньше не проверялся — считалось, что
ловить `cat`/`sed`/`node -e` регулярками бессмысленно, а запрет на shell-обходы
удержит промпт. Не удержал: инструкция — мягкое ограничение, и при первом же
затыке агент уходил в `cat`/`sed -i`/`node -e`, минуя `edit-router`. Гонка
вооружений тут и не нужна — задача не «поймать любой обход», а убрать самый
удобный путь, пока рядом есть честный.

Разбор нарочно грубый: распознаются формы (`cat`/`head`, `sed -i`, `> файл`,
`tee`, `node -e`/`python -c`, `grep`/`rg`), а не синтаксис shell. Всё
нераспознанное проходит — `git diff`, `tsc`, `eslint` над теми же путями
работают, замены им в tokensave нет. Тот же гард висит на
`mcp__ide__executeCode`: канал мимо Bash, результат тот же.

## Структура

```
guard-core.mjs              # вся логика: что в индексе, что — конфиг агента,
                            # где корень проекта, БД активной ветки, тексты запретов
ask-core.mjs                # ask mode: состояние режима и что считается изменением
claude/hook-io.mjs              # общий ввод/вывод PreToolUse + предохранитель повторов
claude/read-search-router.mjs   # адаптер Claude: PreToolUse(Read|Grep)
claude/edit-router.mjs          # адаптер Claude: PreToolUse(Edit|Write)
claude/bash-router.mjs          # адаптер Claude: PreToolUse(Bash|mcp__ide__executeCode)
claude/ask-guard.mjs            # адаптер Claude: PreToolUse(*) — запрет изменений в ask mode
claude/ask-reminder.mjs         # правило ask mode в промпт (UserPromptSubmit)
claude/ask-session.mjs          # сброс режима к значению по умолчанию (SessionStart)
claude/statusline.mjs           # каталог, ветка, модель, индикатор ask mode
claude/subagent-context.mjs     # правило tokensave/ragsave в контекст субагента (SubagentStart)
claude/project-bootstrap.mjs    # чего не хватает проекту: CLAUDE.md, husky, CI (SessionStart)
claude/usage-log.mjs            # токены, стоимость, инструменты по сессии → logs/usage.jsonl (Stop)
security-core.mjs               # что запрещено насмерть, что требует человека
claude/security-guard.mjs       # адаптер Claude: PreToolUse(*) — секреты, БД, прод, отправка наружу
bin/delegate.mjs                # делегирование задачи внешним CLI (DeepSeek, GLM) + health
bin/usage-report.mjs            # отчёт по usage.jsonl: /usage
bin/ask-mode.mjs                # переключатель: on | off | toggle | reset | default
opencode/tokensave-guard.mjs    # адаптер OpenCode: плагин (tool.execute.before и др.)
bin/tokensave-branch.sh         # ветки/первичный init — на новом сообщении пользователя
bin/tokensave-sync.sh           # инкрементальный sync — по завершении ответа
bin/ragsave-sync.sh             # смысловой (RAG) индекс: init при отсутствии, иначе sync
claude/ragsave-reminder.mjs     # подсказка про rag_search на смысловых промптах (не гард)
bin/log-error.sh                # общая запись отказов фоновых задач
logs/errors.log                 # журнал отказов обоих инструментов (ротация 5 МБ)
test/test-guards.mjs            # прогоняет одни сценарии через оба адаптера
test/test-ragsave-reminder.mjs  # когда напоминание про rag_search молчит, когда говорит
test/test-subagent-context.mjs  # контекст субагента есть в проекте и отсутствует вне его
test/test-project-bootstrap.mjs # список пропусков проекта и недельный дроссель напоминаний
test/test-security.mjs          # что deny, что ask, что проходит молча
```

Фоновые задачи молчаливы по устройству — уходят в `setsid`, их вывод оседает в
логе конкретного проекта. Чтобы упавшая индексация не оставалась незамеченной,
все четыре скрипта при ненулевом коде возврата дописывают запись в
`logs/errors.log`: время, источник, проект, код и хвост лога задачи. Это первое
место, куда стоит смотреть при жалобе на баг tokensave или ragsave.

Две записи туда не попадают, иначе журнал перестаёт быть сигналом. Первая —
`another sync is already in progress`: конкурентный sync это штатный пропуск
(параллельная сессия или git-хук уже держат замок), следующий проход подхватит
изменения. Вторая — вывод спиннеров: ANSI-последовательности и повторы
`copying DB` чистятся, строки обрезаются до 200 символов. До этой фильтрации из
25 записей журнала реальными отказами были 3.

`ragsave-sync.sh` относится не к гардам, а ко второму индексу — смысловому
(`~/.rag-mcp`, см. его README). Он висит на тех же двух событиях, что и пара
tokensave-скриптов, и так же уходит в фон; замок при этом держит не скрипт, а
сам `ragsave` — один и тот же для хука, терминала и MCP. Гардов у ragsave
нет и не будет: запрещать нечего — он не альтернатива опасному пути, а
дополнительный инструмент поиска.

Но одной синхронизации оказалось мало. У tokensave три гарда плюс собственный
`hook-prompt-submit`, то есть агенту напоминают о нём в каждом промпте; у ragsave
не было ни одного напоминания в момент выбора инструмента. Итог предсказуемый:
на смысловом вопросе («как настроен деплой») агент шёл угадывать имя символа в
`tokensave_search`, получал пусто и добивал `Grep`'ом — при том что ответ лежал в
доке или конфиге, которых в графе tokensave нет вовсе.

`claude/ragsave-reminder.mjs` закрывает эту асимметрию, не становясь гардом: на
`UserPromptSubmit` он добавляет к промпту короткий контекст с указанием начать с
`rag_search`. Голос подаёт узко — только когда в промпте есть вопрос словами
(«как / где / почему», RU и EN) и **нет** имени файла, символа, `snake_case`,
camelCase или бэктиков. Молчит: если нет `.ragsave/rag.db`; если вопрос
структурный (кто вызывает, что сломается — это точный ответ tokensave, а не
похожие фрагменты); на слэш-командах; и повторно в той же сессии по тому же
проекту — дроссель 15 минут, чтобы подсказка осталась сигналом, а не фоном.
Метки дросселя: `~/.claude/state/ragsave-reminder/`. Любая ошибка → выход без
вывода: пропущенная подсказка дешевле сломанного промпта.

Адаптеры не содержат логики — только перевод формата конкретного агента в вызов
`guard-core`. Меняешь правило — меняешь `guard-core.mjs`, оба агента получают его сразу.

## Когда гард молчит

Запрет полезен, только пока у агента есть работающая альтернатива. Там, где
tokensave заведомо не даст верного ответа, гард пропускает обычный инструмент:

- **Идёт `sync`/`init`/`branch add`** (процесс виден в `/proc`) — гард ждёт его
  до `TS_GUARD_SYNC_WAIT_MS` (по умолчанию 6 с) и судит уже по свежему графу.
  Не уложился — молчит: ждать дольше дороже, чем разово пропустить.
- **Ветка не отслеживается** в `branch-meta.json` или detached HEAD — MCP ответил
  бы графом другой ветки. Раньше этого не проверялось: гард всегда открывал
  `tokensave.db`, то есть БД ветки по умолчанию, и на `dev` судил по `main`.
- **Тот же вызов запрещён повторно** (та же цель, та же сессия, окно 3 минуты) —
  второй отказ не сообщает ничего нового, а даёт цикл: в логах это семь
  одинаковых `Edit` подряд. Метки: `~/.ai-hooks/state/guard-breaker.json`.

`bin/tokensave-branch.sh` ждёт общий лок (`flock -w 900`), а не пропускает
добавление ветки: `flock -n` молча терял `branch add`, если в этот момент шёл
sync, и дальше MCP отвечал графом родительской ветки.

## Ask mode

Режим «только ответ в чате»: правки файлов, write-инструменты tokensave,
изменяющие shell-команды, публикация артефактов и субагенты, умеющие писать, —
запрещены; чтение, поиск и тесты доступны. Встроенные режимы Claude Code
(manual / accept edits / plan / auto) зашиты в бинарь и конфигом не расширяются,
поэтому режим собран из хуков: `ask-guard.mjs` запрещает, `ask-reminder.mjs`
объясняет правило до первого отказа, `statusline.mjs` показывает состояние.

Состояние — файл на каталог в `~/.claude/state/ask-mode/`, плюс `default` для
всех новых сессий (значение задаёт `bin/ask-mode.mjs default on|off`). Решение каталога живёт до конца сессии:
`ask-session.mjs` сбрасывает его на `SessionStart` при `startup`/`clear`, но не
при `resume`/`compact` — иначе режим менялся бы под руками. Переключение:
`/ask`, `/ask-off` или `bin/ask-mode.mjs on|off|toggle|reset|default on|off`.

## Субагенты и Superpowers

Плагин Superpowers (`claude plugin install superpowers@superpowers-marketplace`)
выполняет планы через субагентов: имплементер и ревьюер на каждую задачу,
`general-purpose` с явной моделью. Субагент стартует с пустым контекстом —
CLAUDE.md, напоминания `UserPromptSubmit` и `hook-prompt-submit` tokensave до
него не доходят, а гарды `PreToolUse` действуют на него так же, как на основную
сессию (в их вход приходят `agent_id` и `agent_type`). Без подготовки первый
`Read` по проиндексированному файлу — отказ, который субагент видит впервые.

`claude/subagent-context.mjs` на `SubagentStart` кладёт в контекст субагента
короткое правило: какие инструменты tokensave брать для чтения, поиска и правки,
что Bash только для команд, что отказ гарда — указание, а не препятствие, и что
своих субагентов он не запускает. Вне tokensave/ragsave-проекта хук молчит, как
и гарды. Встроенный `tokensave hook-pre-tool-use` на `Agent` ничего в промпт не
добавляет (проверено: отвечает `{"permission":"allow"}`), поэтому нужен свой.

Ролевые агенты живут в `~/.claude/agents/` (`scout`, `backend-dev`,
`frontend-dev`, `tester`, `reviewer`, `security-reviewer`, `devops`), их скиллы —
в `~/.claude/skills/` (`nestjs-backend`, `react-frontend`, `testing-ts`,
`team` — оркестрация без файла-плана). У ролей `Agent` отключён: оркестратор —
основная сессия.

Ask mode на субагентов распространяется через `ask-guard.mjs`: пишущие типы
(`general-purpose`, `backend-dev`, `frontend-dev`, `tester`, `devops`) в режиме
запрещены, читающие (`Explore`, `Plan`, `scout`, `reviewer`, `security-reviewer`)
проходят — список `READONLY_AGENTS` в `ask-core.mjs`. Выполнение плана возможно
только после `/ask-off`; обсуждение дизайна (`brainstorming`) и ревью в ask mode
работают. `opencode run` считается изменяющей командой (`MUTATING_SUBCMDS`):
через него скилл `/commit` запускает агента `commit` OpenCode, который коммитит
и пушит.

Worktree Superpowers не создаёт — CLAUDE.md объявляет предпочтение «ветка в том
же checkout»: индексы `.tokensave/` и `.ragsave/` лежат в каталоге проекта, и
новый каталог означал бы полную переиндексацию.

## Гард безопасности

`security-core.mjs` отвечает на вопрос «что будет, если это выполнить», и
поэтому устроен иначе, чем гарды tokensave. Там запрет означает «возьми
другой инструмент», и предохранитель пропускает повторный вызов, чтобы не
загнать агента в тупик. Здесь запрет означает «у действия есть последствия»,
и предохранителя нет: «со второй попытки можно» отменяло бы сам запрет.

Два уровня ответа. `deny` — там, где законной причины нет, а безопасная
альтернатива есть: чтение `.env` и производных, ключей, сертификатов,
`auth.json`, `.git-credentials`, в том числе через shell и `scp`. Секрет,
попавший в контекст, остаётся в транскрипте навсегда и уезжает в каждый
следующий запрос, поэтому альтернатива — `.env.example` или значение от
пользователя. `.env.example`, `.env.template` и прочие примеры не секреты и
проходят.

`ask` — там, где операция законная, но нужен человек: `pg_dump` и другие
выгрузки, клиент БД на неместном хосте, `git push` в main/dev/prod, force
push и push без явной ветки, `docker compose` с прод-конфигом, `kubectl
apply`, команды через `ssh`, `curl`/`wget` с телом запроса на внешний хост.
В `permissionDecision` это отдельное значение, и оно возвращает подтверждение
даже в auto mode — в этом вся ценность: там всё остальное проходит само.

Разбор грубый, как и в гардах tokensave: распознаются формы команд, а не
синтаксис shell, и нераспознанное проходит. Задача не поймать любой обход, а
закрыть удобный путь и поставить человека там, где цена ошибки высока.

## Делегирование внешним моделям

`bin/delegate.mjs` уводит объёмную генерацию в чужие квоты через CLI
opencode: DeepSeek (`v4-flash` для быстрых ответов, `v4-pro` для рассуждения)
и GLM (`5.3-flash`, `5.3`). Режим `jury` спрашивает обеих и возвращает ответы
рядом — выбирает вызывающий, потому что только он знает задачу.

Три решения в устройстве. Промпт проверяется на секреты до отправки
(`findSecretValue` из `security-core`) — у стороннего провайдера нет причин
видеть токен бота или DSN. Запуск идёт с `--pure` и нейтральным рабочим
каталогом, иначе opencode подтянул бы AGENTS.md и плагины проекта: лишние
токены у провайдера и лишний контекст наружу. Здоровье провайдеров кэшируется
на 6 часов в `state/cli-health.json`, а при живой ошибке метка сбрасывается
сразу — так слетевшая авторизация видна на первом же вызове, а не через
таймауты.

`gemini` и `codex` не подключены сознательно: на момент настройки первый не
проходит авторизацию, второй отвечает 400 (`gpt-5-codex` недоступен на
ChatGPT-аккаунте). Появится доступ — добавляются в `PROVIDERS` одной записью.

## Автоматизация проекта и учёт

`claude/project-bootstrap.mjs` на `SessionStart` (`startup|clear`) смотрит
корень репозитория и сообщает в контекст, чего нет: CLAUDE.md проекта,
`.env.example` при наличии `.env`, husky, CI и dependabot для GitHub-remote,
`.gitlab-ci.yml` для GitLab. Что делать — правило «Автоматизация проекта» в
CLAUDE.md: `/init` запускается сам, остальное предлагается одной строкой.
Про husky/CI хук напоминает раз в неделю на проект (метки в
`~/.claude/state/bootstrap/`), про CLAUDE.md — пока файла нет.

`claude/usage-log.mjs` на `Stop` читает транскрипт сессии и транскрипты
субагентов рядом с ним, считает токены по моделям (одно сообщение — один
`message.id`, хотя строк в транскрипте несколько), вызовы инструментов и
оценку стоимости по прайсу API (`PRICES` внутри), и пишет одну запись на
сессию в `logs/usage.jsonl` (upsert). `bin/usage-report.mjs` — отчёт за
период по моделям, проектам и инструментам; в Claude Code — `/usage`.
Цены — оценка, не счёт подписки: нужны пропорции, а не бухгалтерия.

Частично это дублирует встроенный `tokensave cost` (он же ходит по сессиям
локальных агентов и знает долю попаданий в кэш), поэтому `/usage` показывает
оба: `tokensave cost` — за деньги и кэш по всем агентам, свой отчёт — за
разбивку по проектам, вызовам инструментов и субагентам, которой у tokensave
нет. Цифры расходятся: прайс-таблицы разные, своя лежит в `PRICES`.

## Соответствие хуков

| Что                          | Claude Code                         | OpenCode                        |
| ---------------------------- | ----------------------------------- | ------------------------------- |
| Блокировка вызова инструмента| `PreToolUse` → `permissionDecision: "deny"` | `tool.execute.before` → `throw` |
| Правка/чтение                | `Read`, `Grep`, `Edit`, `Write`     | `read`, `grep`, `edit`, `write` |
| Shell / исполнение кода      | `Bash`, `mcp__ide__executeCode`     | `bash`                          |
| Новое сообщение пользователя | `UserPromptSubmit`                  | `chat.message`                  |
| Ответ завершён               | `Stop`                              | `event` → `session.idle`        |

Имена инструментов и MCP-префиксы различаются (Claude: `Read`, `tokensave_context`;
OpenCode: `read`, `tokensave_tokensave_context`) — они вынесены в `CLAUDE_LABELS` /
`OPENCODE_LABELS` и подставляются в текст запрета.

## Подключение

**Claude Code** — `~/.claude/settings.json`, секция `hooks`:
`node ~/.ai-hooks/claude/read-search-router.mjs` (matcher `Read|Grep`),
`node ~/.ai-hooks/claude/edit-router.mjs` (matcher `Edit|Write`),
`node ~/.ai-hooks/claude/bash-router.mjs` (matcher `Bash|mcp__ide__executeCode`),
плюс `bin/tokensave-branch.sh` на `UserPromptSubmit` и `bin/tokensave-sync.sh` на `Stop`.
Ragsave: `bin/ragsave-sync.sh` на `UserPromptSubmit` и `Stop`,
`node ~/.ai-hooks/claude/ragsave-reminder.mjs` на `UserPromptSubmit`.
Субагенты: `node ~/.ai-hooks/claude/subagent-context.mjs` на `SubagentStart`
(без matcher — все типы агентов).

**OpenCode** — `~/.config/opencode/plugin/tokensave-guard.js` реэкспортирует
`opencode/tokensave-guard.mjs`. Плагины OpenCode грузятся автоматически из
`~/.config/opencode/plugin/` (глобально) и `.opencode/plugin/` (в проекте).

У самого бинаря tokensave есть встроенный хук (`tokensave hook-pre-tool-use`).
Он оставлен только на `Agent`, но снят с `Grep` и `Bash`: на deny он предлагал
обойти запрет через `TOKENSAVE_DISABLE_GREP_HOOK=1`, то есть сам подсказывал
агенту путь в shell — в транскриптах web_groza нашлись команды, где агент этой
подсказкой воспользовался. Вдобавок он решал по виду паттерна («похоже на имя
символа»), а не по индексу, и дублировал собственные гарды. `Grep` целиком за
`read-search-router.mjs`, `Bash` — за `bash-router.mjs`.

Matcher переживает `tokensave reinstall`: install дописывает хук, только если
его ещё нет, и чужой matcher не переписывает.

Изменения хуков подхватываются при перезапуске агента.

## Тесты

```bash
node ~/.ai-hooks/test/test-guards.mjs
node ~/.ai-hooks/test/test-ragsave-reminder.mjs
node ~/.ai-hooks/test/test-ask-mode.mjs
node ~/.ai-hooks/test/test-subagent-context.mjs
```

Каждый сценарий проверяется в обоих агентах — вердикты должны совпадать.
Тест ходит в реальный tokensave-проект (`/home/enkeym/main/web_groza`) и в
не-проект (`/tmp`); если проект переехал, поправь константы в начале файла.
Пути в сценариях — настоящие файлы этого проекта: вердикт зависит от того, что
лежит в индексе, поэтому выдуманный путь всегда даст `allow`.

Состав индекса зависит от ветки (на `main` в графе только ts/js/tsx/md, на
рабочих ветках — ещё json, sql, yml), поэтому ожидания для таких файлов тест
берёт из той же БД, по которой судит гард (`isIndexed`, `indexedExtensions`),
а не зашивает константой. Тест ask mode пишет состояние во временный каталог и
глобальное умолчание не меняет.
