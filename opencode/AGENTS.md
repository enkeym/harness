# OpenCode harness

Read `~/.config/harness/repo/rules/core.md` before the first task and follow it throughout the session.
Select applicable skills before each task and when its scope changes. Read missing or changed SKILL.md instructions from the installed skills directory before beginning their workflow.
Load tokensave-routing before project exploration. Discover MCP schemas through OpenCode's tool catalog search (`search` in execute), then call the discovered tools through execute. Catalog search discovers tools; it does not search project files. list_mcp_resources lists resources, not tool schemas; do not use it for tool discovery or guess a callable before discovery.
Before the first project read/search, discover the relevant MCP tools and call tokensave_status. Use tokensave_search for symbols or exact text, tokensave_read for source ranges, and rag_search for concepts, documentation and configuration. Scope queries to relevant paths. Use tokensave_files for coverage only if the catalog exposes it; otherwise try tokensave_read on the known path or use a scoped search. A missing optional tool does not make the other MCP tools unavailable.
Documentation, agent instructions and SKILL.md files may also be indexed. A known path, file extension, handoff, continuation, simple task, tool-list omission or previous use of shell does not exempt project exploration from MCP. Built-in read/grep/glob and shell cat/sed/rg/grep/find, including scripts that perform the same reads, must not replace available indexed retrieval.
Before a fallback, state the specific failing MCP call or coverage evidence and the affected path/scope. No result, an argument error or catalog search alone is not proof that a file is outside the index. Correct bad arguments; try tokensave_read for a known file. Use local reads only for logs, Git output, external configuration or a demonstrated index/tool limitation, bounded to that scope. Reuse an established limitation while it remains valid; do not repeatedly probe a broken service. If an unintended bypass occurs, acknowledge it and resume MCP retrieval immediately instead of continuing the bypass.
Start source reads with 30–80 relevant lines and RAG with 3–5 scoped fragments. Expand only for a specific missing fact. Use full-file reads only when the entire small contract is needed; do not reconstruct full files through successive slices. Verify cited line numbers against an exact source range.
Preserve project conventions and unrelated user changes. Use the installed tools.
For noisy non-interactive tests, builds and diagnostics, run `bash ~/.ai-hooks/bin/brief-output.sh <command> [args...]` from the first invocation. Inspect the saved full_log only around a specific error; reuse successful checks while inputs remain unchanged. Never wrap interactive commands or bulk-read the full saved log.
