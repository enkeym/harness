# OpenCode harness

Call the `skill` tool with the exact, case-sensitive `id` from the current available-skills catalog. The display `name` is not an ID: the built-in OpenCode skill has `id: "opencode"` and `name: "OpenCode"`, so load it with `{"id":"opencode"}`. Do not infer IDs by lowercasing display names. If loading fails, check the current catalog and skill permissions before retrying; correct a mismatched ID and never repeat an unchanged invalid ID. If the exact registered ID still fails, report the loading error and continue only with work that does not require that skill.
Resolve skill-relative links against the `Base directory for this skill` returned by `skill`, including after compaction. Read that exact reference path; never run `find /` or scan the home directory to locate a reference whose base is already supplied. Shells must run a concrete needed command, never serve as placeholders or substitute for unrequested subagents.
Load tokensave-routing only when the project has an index (`.tokensave/` or `.ragsave/rag.db`) and the task needs code navigation; without an index, skip that skill and use built-in tools. In an indexed project, discover MCP schemas through OpenCode's tool catalog search (`search` in execute), then call the discovered tools through execute. Catalog search discovers tools; it does not search project files. Pass exactly one input object per execute call, all fields inside one `{...}`; a second positional argument fails with `expects at most one input object` before the server sees it. list_mcp_resources lists resources, not tool schemas; do not use it for tool discovery or guess a callable before discovery.
For public internet research, discover the available web search/fetch tools first and retrieve source content. Opening a Playwright extension connection tab is not a search. When browser interaction is required, discover browser_tabs, browser_navigate and browser_snapshot directly, follow core.md's tab rules and continue through target navigation and content inspection. If no search tool is available, use supported public page retrieval or report the limitation; never end at Welcome/about:blank as if research succeeded.
Before the first project read/search in an indexed project, discover the relevant MCP tools and call tokensave_status. Use tokensave_search for symbols or exact text, tokensave_read for source ranges, and rag_search for concepts, documentation and configuration. Scope queries to relevant paths. Use tokensave_files for coverage only if the catalog exposes it; otherwise try tokensave_read on the known path or use a scoped search. A missing optional tool does not make the other MCP tools unavailable. Without an index, do not call tokensave_status or load tokensave-routing; use the built-in tools and the local-tool exceptions below.
Documentation, agent instructions and SKILL.md files may also be indexed. A known path, file extension, handoff, continuation, simple task, tool-list omission or previous use of shell does not exempt project exploration from MCP. Built-in read/grep/glob and shell cat/sed/rg/grep/find, including scripts that perform the same reads, must not replace available indexed retrieval.
Before a fallback, state the specific failing MCP call or coverage evidence and the affected path/scope. No result, an argument error or catalog search alone is not proof that a file is outside the index. Correct bad arguments; try tokensave_read for a known file. Use local reads only for logs, Git output, external configuration or a demonstrated index/tool limitation, bounded to that scope. Reuse an established limitation while it remains valid; do not repeatedly probe a broken service. If an unintended bypass occurs, acknowledge it and resume MCP retrieval immediately instead of continuing the bypass.
Start source reads with 30–80 relevant lines and RAG with 3–5 scoped fragments. Expand only for a specific missing fact. Use full-file reads only when the entire small contract is needed; do not reconstruct full files through successive slices. Verify cited line numbers against an exact source range.
Use `task_context` to retain a compact current-step checkpoint and selected observed TokenSave ranges before transfer. On restore, omit `sources` to recover the checkpoint first; request only needed cached ranges within the tool's line limit. Do not rebuild an adequate plan or reread all implementation files. Call `action=complete` after the whole task and checks finish, before the final response; intermediate answers do not complete a task.
