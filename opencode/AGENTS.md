# OpenCode harness

Call the `skill` tool with the exact, case-sensitive `id` from the current available-skills catalog. The display `name` is not an ID: the built-in OpenCode skill has `id: "opencode"` and `name: "OpenCode"`, so load it with `{"id":"opencode"}`. Do not infer IDs by lowercasing display names. If loading fails, check the current catalog and skill permissions before retrying; correct a mismatched ID and never repeat an unchanged invalid ID. If the exact registered ID still fails, report the error and continue only with work that does not need that skill.
Resolve skill-relative links against the `Base directory for this skill` returned by `skill`, including after compaction. Read that exact path; never run `find /` or scan the home directory for a reference whose base is already supplied. A shell must run a concrete needed command, never act as a placeholder or a substitute for an unrequested subagent.
In an indexed project discover tool schemas through OpenCode's catalog search (`search` in execute), then call the discovered tools through execute: exactly one input object per call, all fields inside one `{...}`; a second positional argument fails with `expects at most one input object` before the server sees it. Catalog search discovers tools, it does not search project files, and `list_mcp_resources` lists resources, not tool schemas — never guess a callable before discovery.
`tokensave_search` takes symbols or exact text, `tokensave_read` takes source ranges and `rag_search` takes concepts, documentation and configuration; `skills/tokensave-routing` owns the full tool map, argument formats and read sizing, so load it instead of guessing from these lines. Scope every query to relevant paths and use `tokensave_files` for coverage only if the catalog exposes it. A missing optional tool does not make the other MCP tools unavailable. Verify cited line numbers against an exact source range. Without an index use the built-in tools.
Documentation, agent instructions and SKILL.md files may also be indexed. A known path, file extension, handoff, continuation, simple task, tool-list omission or previous use of shell does not exempt project exploration from MCP. Built-in read/grep/glob and shell cat/sed/rg/grep/find, including scripts that perform the same reads, must not replace available indexed retrieval.
Before a fallback, state the specific failing MCP call or coverage evidence and the affected path/scope. No result, an argument error or catalog search alone is not proof that a file is outside the index. Correct bad arguments; try `tokensave_read` for a known file. Use local reads only for logs, Git output, external configuration or a demonstrated index/tool limitation, bounded to that scope. Reuse an established limitation while it remains valid; do not repeatedly probe a broken service. If an unintended bypass occurs, acknowledge it and resume MCP retrieval immediately instead of continuing the bypass.
Browser work follows core.md's Playwright rules; discover `browser_tabs`, `browser_navigate` and `browser_snapshot` directly and never treat the extension Welcome tab or about:blank as the result. For public research without a search tool use supported page retrieval or report the limitation.
Use `context_cache` to retain only the observed TokenSave ranges the next step needs; the managed task plan holds the checkpoint, so the cache never copies it. On restore, omit `sources` to keep the selection and request only needed cached ranges within the tool's line limit. Call `action=complete` after the whole task and checks finish, before the final response; intermediate answers do not complete a task.
