# DeepSeek: принятое решение, 2 ноября 2026

Основная сессия OpenCode работает на Flash. Для новой задачи вызывается один отдельный Pro-агент: harness-plan для плана либо harness-brief для уточнения. Ему передаются задача, ограничения и пути, без истории основной сессии. Принятый план сохраняется в существующем файле задачи либо PLAN.md; выполнение и отметки готовности делает Flash. Повторное планирование Pro нужно только при изменении требований или опровержении плана данными репозитория.

Review остаётся отдельным Pro-агентом harness-review с чистым контекстом. Handoff и compaction выполняются на Flash. Перенос открывает новую сессию с кратким состоянием и продолжает оставшийся план. Один запуск агента может включать несколько оплачиваемых API-запросов.

Маршрутизация реализована в opencode/model-routing.mjs, подключена установщиком и плагином. Семантический выбор агента задаётся инструкцией модели; явные команды /harness-plan, /harness-brief, /harness-review закрепляют Pro через нативный конфиг. Провайдеры, отличные от DeepSeek, сохраняются; apimira/Qwen остаётся для ручного выбора модели.

Проверки настоящего OpenCode с локальным HTTP-провайдером подтверждают отсутствие истории родителя у Pro-команд и Flash для Handoff. Проверены повторная установка, сохранение настроек, запреты правок и делегирования у специалистов, восстановление модели при ошибке переноса. Инструкционный запрет записи через shell не является песочницей.

Кеш DeepSeek автоматический, управляемого TTL нет. Короткие отдельные задачи Pro уменьшают повторную передачу контекста; бесплатность запросов или cache hit не гарантируются. Подробности и источники: docs/opencode.md.

Пользователь разрешил коммит и push всех текущих изменений ветки codex. Изменения vscode/ сохраняются без редактирования. Секреты остаются вне Git.
